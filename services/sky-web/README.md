# Sky dedicated service deployment

The dedicated Site hosts the same Sky UI and authenticated APIs. Its fresh DB is initialized from the canonical migration union using prepared statements, including all 26 guards. API requests remain unavailable until the complete schema is initialized. This adapter is dedicated to the new Sky Site and must not initialize or replace an existing OS database. The schema snapshot needs regeneration and explicit upgrade handling when the canonical schema changes; it is not a general migration engine.

## `avoado.si` same-origin routing (2026-10-13)

Sky Site v45 owns `avoado.si`. RockstarOS Home is `/os`; `/os/sky` and its child pages map to the existing Sky Worker routes, while old `/sky` URLs redirect to the canonical path. Sky APIs/assets and first-party app paths run in its original Worker and retain that Site's sign-in identity and DB. OS and Sky manifests open at `/os` and `/os/sky/marketplace`. The wrapper in `domain-router.mjs` forwards the public product pages and Mini preorder API to the existing Mini Site. The wrapper removes Sky cookies and identity headers on Mini requests, rejects cross-origin writes, rewrites Mini redirect locations to the browser host, and avoids installing a Sky service worker at the Mini root. It does not grant Mini preorder access to Sky accounts. The existing Mini Site remains independently available at `avocadomini.si` and `avocadopro.si`; the root product homepage already links to those respective domains.

For a new Sky Site build, run `npm run build`, then `node scripts/stage-sky-domain-router.mjs` before packaging `dist/server` for Sites. Rebuild `dist/server` before restaging; the script requires the generated `index.js` entrypoint. Deploy only after checking `/`, `/os`, `/os/sky`, `/os/sky/outputs`, both manifests, `/preorder/`, and `/api/preorders/offer` on the custom domain. The production custom-domain DNS uses Sites' apex A targets plus `_openai-site-verification` and `_cf-custom-hostname` TXT records. A separate custom-domain assignment is required; build output alone does not activate the domain.
