# A2A Cloud Agent価格見積拡張（契約準備）

2026-10-01。A2AのCore operationはagentへのmessage/task送信・状態取得・取消などを規定するが、taskの価格見積や請求単価は共通operationとして定義していない。価格をAgent Cardの自己申告だけで信頼せず、別途versioned extensionとProvider署名quoteを使う。[公式A2A仕様](https://github.com/a2aproject/A2A/blob/main/docs/specification.md) [A2A extension guide](https://github.com/a2aproject/A2A/blob/main/docs/topics/extensions.md)。

## 必須の二段階フロー

1. 端末でProvider、Agent名・版、公開rate card、価格通貨、単位、最低料金を確認する。rate cardはProviderが署名し、運営が`A2A_TRUSTED_USAGE_KEYS`で信頼したProvider鍵とAgent origin・版に束縛する。Agent Cardの能力・価格宣言は自己申告候補にとどまり、署名検証と契約受入までは価格条件として表示しない。
2. Providerへ依頼本文を渡して見積する場合、ユーザーに「本文と必要な入力がProviderへ送信され、仕事を実行せず見積だけ行う」ことを明示して別途同意を得る。見積要求には一回限りの`quoteRequestId`、idempotency key、request hash、Agent版、通貨、明示上限、期限を束縛する。quote-only operationは外部taskを作成せず、usage chargeを確定しない契約にする。
3. Providerの署名付きquoteは次を含む: quote ID、Provider/鍵、Agent origin/name/version、依頼本文hash、rate card version/hash、meter/unit/quantity/unit price、estimate、保証上限、currency、expiry、quote nonce、single-use/idempotency binding。rateの算術合計と保証上限をRockstar側で再計算・検証し、署名済み上限内だけOwner承認対象にする。
4. Zemaの確認画面は見積額、明細・単価、最大請求額、通貨、期限、税/外部費用の扱い、親job共通残枠を表示する。Owner承認hashにquote hash・max amount・rate version・request hash・offline続行・期限を含める。quote期限切れ・入力やAgent版変更・親予算超過・署名不正なら再見積を要求し、dispatchしない。
5. Wallet reservationはquoteの保証上限で一度だけ取得し、全並列子taskで親job予算を原子的に共有する。Workflowの各外部送信前にquote expiry/revocation、Broker proof、scope entitlement、Wallet reservation、cancel/deadlineを再確認する。曖昧なremote sendは再送せずreservationを保留し同一taskを照合する。
6. 完了後はProvider署名usage receiptをquote ID/rate card version/request/task/Agent identityへ結び、使用meter数量×単価、割引・税・費用項目のtotalと合計、quote上限以下を再照合する。利用確定、請求確定、支払完了、作者払出しは別stateとする。RT usageが提供されないProviderでは保留中予約と確定usageを分け、リアルタイム支出と誤表示しない。

## 追加すべきwire contract

- A2A coreは既存JSON-RPC `SendMessage`/`GetTask`/`CancelTask`を維持する。
- Price quoteはA2A Extensionとして宣言する追加RPC/REST methodとrequest/response schemaを別に定義する。実Providerが対応するまではClientはこのextensionを必須として要求せず、quoteが無いAgentの有料dispatchを拒否する。
- Extension URI、JSON-RPC method、HTTP binding、A2A version、quote canonicalization、signature domain、error/retry/idempotency、provider cancellation/refund/reversal、key rotation、quote chargeability、税・為替をProvider契約で確定する。URIは所有domainと登録手続きが整うまで公開・Agent Card掲載しない。
- Quote機能無しのAgent CardはSky検索と無料/非実行確認には使えても、有料dispatchには不適格と表示する。推測rate、入力文字数だけの金額換算、単なるユーザーbudget capを「見積額」と呼ばない。

### Rockstar quote-only extension proposal (unpublished)

The repository now has a client-side proposal for acquiring a quote without creating or dispatching an A2A task. This is a Rockstar protocol proposal, not an A2A standard operation and not a provider-supported endpoint. A2A's extension mechanism permits independently defined capabilities and methods; implementations still need to agree on the extension URI, method, schema, and behavior. The URI must remain operator-configured and unpublished until Rockstar controls a stable versioned URI and a provider has implemented and accepted the contract. See the [A2A extension guide](https://github.com/a2aproject/A2A/blob/main/docs/topics/extensions.md) and [extension governance](https://a2a-protocol.org/latest/topics/extension-and-binding-governance/).

The current proposal is deliberately narrow:

- The Agent Card must advertise the exact operator-configured HTTPS extension URI. The request negotiates it with the `A2A-Extensions` header and uses JSON-RPC method `GetPriceQuote`.
- Request schema `rock-a2a-price-quote-request/1` includes a stable `quoteRequestId`, exact Agent origin/name/version, request SHA-256 and prompt, currency, maximum budget, expiry, and `executionRequested: false`. The caller must obtain separate, explicit consent to disclose the prompt to that Provider before making the network request. A boolean at the library boundary is only a guard; the product UI must source it from a recorded user action.
- Response schema `rock-a2a-price-quote-response/1` echoes the same request ID and contains a Provider-signed `priceQuote`. The response is untrusted until `verifyA2APriceQuote` checks signature, trusted Provider key, request hash, Agent identity/version, arithmetic, budget and expiry. Only then may it be persisted and shown as an estimate; the quote's maximum remains distinct from the estimate.
- `GetPriceQuote` must not create a task, start work, or create a usage charge. An ambiguous response is surfaced with its original request ID for reconciliation; the client never retries it or silently dispatches `SendMessage`.
- `POST /api/sky/a2a-price-quotes` now connects the signed quote verifier to the owner-authenticated application: it accepts only an owner-connected Agent, applies per-owner request limits and the operator egress allowlist, requires the prompt-sharing consent flag, and refuses prompt disclosure unless an active Provider usage key is configured for the exact Agent origin. It returns only a quote whose Provider key, request hash, Agent identity/version, arithmetic, currency, maximum and expiry verify. The Workbench has a separate consent checkbox, invalidates a quote when its terms change, and shows verified estimate, cap, meter lines and expiry before it creates a draft. Creating the draft persists the quote and digest through the existing single-use delegation store. The consent is not yet durably recorded as a separate audit event.
- Local signed fixtures verify this path; no real Provider quote response or Provider support is established. Configure `A2A_PRICE_QUOTE_EXTENSION_URI` only after the versioned URI is operator controlled and a Provider accepts it. Empty/unconfigured extension URI, egress origin or trusted Provider key keeps quote acquisition unavailable. `A2A_TRUSTED_USAGE_KEYS` remains the active signature trust root.
- The verified quote is an input to a confirmation draft, not an execution authorization. Cloud paid dispatch remains gated until the native owner-visible approval and exact Wallet hold/Broker proof path is complete. No production usage charge or invoice is established.

## 現在の実装境界

- RockstarのA2A durable Workflow、owner-bound Broker approval、共有budget reservation、Provider署名最終usage receipt、offline continuation/recoveryは再利用する。
- `lib/a2a-price-quote.ts`は`rock-a2a-provider-price-quote/1`署名検証器を実装する。信頼resolverでProvider/鍵/Agent originを照合し、HTTPS origin、価格・request/rate hash、単価×数量=内訳、内訳合計=estimate、保証上限、owner指定budget上限、最大24時間のquote期限を検査する。`a2aPriceQuoteDigest`は署名対象をhashし、後続のowner approvalへ固定する値を生成する。`tests/a2a-price-quote.test.mjs`は正常署名、改ざん、別request/Agent版、誤算、予算超過、期限切れ、信頼鍵不一致を検査する。
- `lib/a2a-client.ts`の`requestPriceQuote`は上記quote-only提案を実装する。明示的なprompt共有同意、運営設定済みHTTPS URI、Agent Card上の同一URI宣言を必須にし、extension negotiation headerと`executionRequested: false`を送る。応答は既存の署名quote verifierへ渡す前提で未検証のまま返す。曖昧な応答では安定した`quoteRequestId`を返し、再送しない。`lib/a2a-price-quote-acquisition.ts`と`app/api/sky/a2a-price-quotes/route.ts`は接続済みAgent snapshot、egress allowlist、Owner認証・回数制限、Provider署名とquote bindingを追加検査する。migration `0049_a2a_price_quote_consent_events.sql`と`lib/a2a-price-quote-consent-store.ts`はProvider送信前にversion付きconsent eventを追記する。記録するのはowner、Agent connection/origin/name/version/card hash、prompt SHA-256、通貨、上限、有効期限、consent version、時刻であり、依頼本文は保存しない。同じowner/request ID/条件の再送もProviderへは再送せず409とし、条件変更を同じIDで試す場合もconflictにする。曖昧なProvider応答のあと、外部status照合ができるまでは同じ依頼の再送禁止を維持する。Workbenchの同意は料金見積のための依頼文共有だけを認め、有料実行を許可しない。SQLite testsは合成fixtureで記録のhash/所有者/不変性/再送拒否を検証し、実Provider相互接続の証拠にはしない。
- `POST /api/sky/a2a-delegations`は任意の署名quoteを受け、request hash・Agent名/版/origin・通貨・最大額を照合する。`A2A_PRICE_QUOTES_REQUIRED=true`ではquoteなしdraftを拒否する。Verified quote JSONとdigestをmigration `0041`でdelegationと同じD1 rowへ保存し、partial unique digest indexで同一signed quoteの別委任への再利用を拒む。Owner approval intentとnative Broker proofの`authorizationSha256`へquote digestを含める。approval時に署名/期限を再検証し、予算予約額をquote最大額と一致させる。
- Package-specific quote adds a Provider-signed runtime binding pinned to the current reviewed Package key, manifest hash, I/O Schema hashes, Agent Card snapshot, Provider-declared runtime extension URI, pricing version, and required usage meters. The binding id/digest is stored on the delegation by migration `0056_a2a_package_runtime_binding_refs.sql`; its digest is included in owner approval and Broker proof. Cloud dispatch rechecks the active binding and sends a `SendMessage` invocation extension (`A2A-Extensions`, `message.extensions`, and `org.rockstar.sky-package-runtime.v2` metadata) containing the exact bound operation and request digest. This is a Rockstar protocol proposal that still requires real Provider implementation and interoperability acceptance; it is not proof that an external Provider executed the operation. A controlled local Worker/D1/Workflow fixture now exercises the binding through task completion and validates a synthetic Provider-signed usage receipt. Real Provider execution, output-schema validation, and external execution-receipt acceptance remain open.
- Workflowは外部Agent Card取得より前に保存済みquoteの署名・request/Agent条件・digest・期限を再検証する。ローカルWorker/D1 API suite 540 assertionsではquote required flag、改ざん拒否、persisted quote/digest、同一quote再利用拒否、Broker承認、paid direct LLMの価格gateを確認。Cloudflare Worker/D1/Workflow suite is now 12/12, including quote mutation/missing-binding rejection and a positive controlled Provider fixture that executes the bound operation, stores the encrypted result, verifies its signed usage receipt, and settles the local logical budget. Synthetic keys and a service binding are local fixtures only; no real Provider was called.
- WorkbenchはISO currency minor-unit換算で上限額を表示し、上限は見積ではないことを示す。実行中はowner-authenticated task listを10秒ごとに更新し、Provider署名付きcumulative snapshotを暫定amountとして表示する。署名最終receiptは別に表示し、予約額・暫定meterを請求確定額へ読み替えない。live callbackが来なければ「meter未報告」とする。
- Migration `0044_a2a_live_usage_snapshots.sql`と`POST /api/sky/a2a-delegations/{id}/usage-snapshots`は`rock-a2a-provider-live-usage/1`を受ける。payloadはprovider/key/event ID、strict sequence、owner/root job/delegation/task、agent identity/version、currency、cumulative amount、pricing version、issue time、meter linesをEd25519署名する。key trustは既存の`A2A_TRUSTED_USAGE_KEYS`を共有し、独立domain prefixでfinal receiptと混同させない。
- D1は署名検証後の各snapshotをimmutableに記録し、重複event ID、sequence飛び/再利用、金額または時刻の後退、active taskの取り違え、通貨・quote price version不一致、held reservation cap超過を拒否する。再送は既存eventと同じ署名payloadの場合だけ冪等。最終receiptは同じprovider/task/pricing versionで、最後のsnapshot以上、かつ予約cap以下でなければD1 budget settlementへ進めない。失敗時はholdと照合待ちを残す。
- First-party remote LLM endpoints `/api/llm/text`, `/api/legal-guidance`, `/api/patent-research`, `/api/jev-evaluation` are fail-closed until the same class of provider price preflight, user cap authorization and usage reconciliation is integrated. `/api/llm/text` also treats configured non-loopback Ollama/local-model/OpenAI-compatible endpoints as remote, rather than relying only on a provider label. Sky service status and Tool cards no longer describe configured API keys as executable cloud AI. Local browser/OS processing remains separate. API tests confirm even enabled cloud flags and valid remote consent do not call the provider without pricing acceptance.
- Direct remote LLM route gate evidence and its limits: [remote AI price gate](evidence/remote-ai-price-gate-20261001.json).
- `lib/remote-ai-rate-card.ts` adds a versioned provider-signed model rate-card verifier and ceiling estimator for text input upper bounds plus an explicit output-token limit. It binds estimates to provider/model/currency, verifies an operator-trusted Ed25519 key, rejects stale/unsigned/malformed cards, and rounds up to currency minor units before comparing the user's maximum budget. The default text bound is UTF-8 byte length plus framing allowance; each real adapter still needs Provider acceptance of tokenizer/framing, special-token, tool-call, cache, and other billable-meter semantics. The rate-card module does not fetch a live rate, capture consent, reserve Wallet funds, authorize execution, or establish a charge. Synthetic-key tests only validate local arithmetic and signature handling; paid direct LLM routes remain fail-closed.
- `POST /api/llm/estimate` authenticates the owner, applies the existing remote-AI request limit and RockstarOS service entitlement, and selects only the latest active signed card per currency from D1 table `remote_ai_rate_cards`. It rechecks the persisted digest, Provider signature, and current active key from `REMOTE_AI_TRUSTED_RATE_KEYS`. A request containing prompt/system text is sent to the RockstarOS server for local upper-bound calculation only; the endpoint returns `providerSubmission: not_performed` and `executionAuthorized: false`. Multiple trusted currencies require an explicit currency selection. An optional `maximumBudgetMinor` is checked without hiding the estimate when the cap is too low. The Zema composer shows the maximum amount, input/output limits, pricing version, source and expiry, plus a currency-aware per-request cap field. It is estimate-only; the separate `/api/llm/text` route and all other direct paid routes remain closed.

### 実行中cumulative usage extension（local implementation）

Real Provider sandboxがなくてもUI・永続性・課金境界を契約前に検査できるよう、provider-independent receipt extensionを実装した。snapshot endpointはProvider signing keyがactiveで、対象taskが開始済み・未終端、deadline内、approval済み価格版/通貨に一致し、ownerのheld reservationが存在するときだけ受ける。イベントは同じdelegationについてsequenceを1ずつ増やし、累積金額・meter行・issuedAtを後退させない。UIは表示更新が遅れても最後の署名snapshotを保持し、network failureを0円に戻さない。

最終署名receiptは、既にD1へ保存された最後のsnapshotに対しprovider/task/currency/pricing versionを一致させ、累積値以上であることを再検証してから予約額をfinal settlementする。これはProvider側の強制停止、実費、invoice、資金決済を保証しない。sandboxで、時刻許容、通知配信順序、遅延・再試行・価格訂正・税/為替・cancel terminal meter・上限超過直前の停止、最終receipt correction/reversalを確認しなければならない。Providerから署名snapshotが届かない間、画面は暫定金額を作らず「未報告」とする。ローカルcallbackとUIは実装済みだが、実Providerの配信・停止保証は未受入。

### Provider-signed rate-card operations

After a Provider supplies signed cards and a key-rotation process, provision its public signing key in `REMOTE_AI_TRUSTED_RATE_KEYS`, a JSON array of exact provider/key identities with lowercase-hex Ed25519 public keys and explicit active/revoked status. Keep this trust-root list below Cloudflare's current 5 KB per-variable limit; signed rate-card bodies themselves are stored durably in D1 by migration `0042_remote_ai_rate_cards`. [Cloudflare Workers limits](https://developers.cloudflare.com/workers/platform/limits/)

Set `REMOTE_AI_RATE_CARD_INGEST_TOKEN` as a Worker secret and `REMOTE_AI_RATE_CARD_OPERATOR_ID` as a bounded audit identity. `POST /api/internal/remote-ai/rate-cards` accepts only a Provider-signed, unexpired card from an active trusted key; card ID is immutable and same-card retries are idempotent. `PATCH` with `{ "action": "revoke", "providerId": "…", "cardId": "…" }` irreversibly revokes it. Every estimate rechecks the current trusted key and row digest, so key revocation immediately makes its cards unusable. No private signing key or account credential belongs in the app. Only Provider-supplied prices are accepted.

```json
[{"providerId":"provider-id","keyId":"provider-key-id","publicKeyHex":"<replace-with-exactly-64-hex-characters>","status":"active"}]
```

The operator ID example below is a shape only; the example public key is deliberately invalid until replaced with a real Provider key. Cards bind provider, model, currency, input/output rates, pricing version, effective/expiry times, and source URL. There are no default rates; missing, invalid, revoked-key, mismatched, or expired rows produce `REMOTE_AI_RATE_CARD_UNAVAILABLE`. Deployment acceptance must test Provider-issued signatures, current rates, exact billable meter semantics, and revocation propagation before any execution path is enabled.
- Signed quoteを受け取ったdraftはD1へsingle-use保存され、owner approval/Broker authorization digestへ固定され、quote上限とWallet reservation capが一致しない限り承認されず、Workflowは外部Agent Card取得前に再検証する。quote digestが一度保存された後は、取消・期限切れを含め再利用不可のため、新しいquoteと新しいidempotency keyを必要とする。signed rate cardの認証済みD1登録・失効API、estimate-only表示、A2A見積取得API/UI、依頼文共有同意のappend-only audit eventはsource実装済み。Provider quote-only extensionは未公開のproject proposalであり、provider responseはsynthetic fixtureでのみ検証済み。Provider対応・Android native approval/hold integration、paid A2A/direct LLM execution、実行中meterのProvider配信、invoice reconciliation and production billing remain unaccepted or unimplemented. ローカルの署名snapshot callbackと暫定表示は実装済み。 Existing user-provided budget cap alone never enables paid execution.

## 受入試験
