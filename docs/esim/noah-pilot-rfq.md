## 接続の準備と残件

CanalはSORACOM側のVPCと自社AWS VPCを接続する方式。[公式接続方式](https://soracom.jp/services/canal/)。現行Noahの公開先はCloudflareであり、AWS閉域入口から既存の専用実行環境へ渡す経路・相互認証を別途実装・検証する必要がある。eSIM購入だけで専用クラウドが完成したとは扱わない。

最新main 97898c519には専用Workerの `services/noah-test-runtime/src/cloud-entry.mjs` と `wrangler.cloud-work.jsonc` がある。LINEによる要求単位の回線照合、所有者別の保存、バックグラウンド完了の土台を再利用する。実回線の照合器・公開環境のbindingは未設定。`tests/noah-cloud-work.test.mjs` 2件を再実行して成功したが、合成LINEを使うローカルworkerdの結果である。

Pixelの読み取り確認ではeUICC / MEP対応featureと有効なGoogle eUICC packageが存在する。EID・ICCID・既存SIM情報は取得しない。これは特定事業者の互換性や回線追加成功の証明ではない。現在の主回線・OSは変更していない。

ブラウザの特定サイトだけを第2eSIMへ自動的に流すことは実証されていない。手動でデータ回線を選ぶ試験は実回線疎通の受入に限定し、「普段の回線はそのまま、Noahだけ自動切替」の合格にはしない。正本は最新mainの `docs/structure/03-esim.md`。
