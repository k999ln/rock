版 F2 / 2026-11-02。24章の独立警報と共通OSを維持する。**新規の建物配線・AC100V直結工事・天井内工事を必要としない設置を製品要件に追加する。** 本人の「家庭やビルにある火災報知器の基準をクリアした上で取り付け」を採用。完成miiの検定・適合・実機受入は未完了。

## 1. 「工事なし」を成立させる商品条件

施工を簡単にするため、工場で内部ハーネスを配線し、現場では取付・登録・作動確認までにする。粘着剤だけの天井固定、吸煙孔／音孔を覆うカバー、既存感知器の上に重いP3を吊るす方式は採用しない。現物の保持荷重・落下防止・下地・点検空間を合格条件にする。穴開け不要と工具不要も別条件であり、現段階で万能取付具は未設計。

**商品は消防機能を備えたmii一品を目指す。** 現段階で買える機器を並べる連携試作は、その完成形ではない。認定済み感知器のケースを改造せず、独立した指定位置に置いて接続を検証する。最終形状では、固定する消防ユニットと着脱する演算・通信ユニットを一つの商品にまとめ、感知器を外さずCoreだけ取り出せるようにする。共通OSは変更しない。

消防機器側は専用電池または既設の適合受信機で維持し、P3の電池から給電しない。P3は別途充電が必要。消防電池の約6年／10年という目安をmii演算部の持続時間としない。天井位置で衛星通信できる保証はなく、LTE・Wi-Fi・衛星は24章の補助通知のまま。

## 3. F-H 住宅用連携試作の実配線

現存設備を外さない机上試作。無給電で端子刻印を照合して配線する。H4の付属ケーブルをそのまま使い、コネクタ製造元・端子番号・線色は推測しない。**A/Bは付属ケーブルの2本に貼るこちらの線名であり、メーカー端子番号ではない。** 無極性なのでA/Bの入替は電気的に同等。図面の丸数字6はコネクタの部品呼出し番号で、pin 6ではない。

```text
固定側：CR17450E-N-CN10 → FSKJ226-M  ≈≈ 指定無線 ≈≈ FSKJ226-C ← 専用電池
                                     ≈≈ 指定無線 ≈≈ FSOJ001B-S ← 専用電池
                                                           │火災移報用コネクタ
                                        純正ケーブル A ───┼── I1 Digital Inputs 0
                                        純正ケーブル B ───┴── I1 Digital Inputs G
                                                                  │ Mini-B
                                                     C2 3017_1    │
                                                          I2 USB-A (device)
                                             [3060_0 電源/GND/data絶縁]
                                                          I2 Mini-B (host)
                                                     C1 3017_1    │
可搬側：P3専用電池/給電 → Pi4 USB-C                 Pi4 青USB3-A下段
                                             共通OS / 読取専用 / 補助通知
```

| 線ID | 接続元 → 接続先 | 接続条件 |
| --- | --- | --- |
| F01 | H1/H2の専用電池 → 各本体「電池用コネクタ」 | 純正assembly、分岐なし。H4の電池と型番を取り違えない |
| F02 | H4専用電池 → H4「電池用コネクタ」 | CR17450E-N-2-CN1。USB5Vを入れない |
| F03 | H4「火災移報用コネクタ」→ 純正ケーブル | メーカー指定向きに挿す。接点出力と電池コネクタを別物として確認 |
| F04 | 純正ケーブルA → I1 **Digital Inputs 0** | 出力端子0と間違えない。外部電圧を追加しない |
| F05 | 純正ケーブルB → I1 **Digital Inputs G/GND** | 絶縁されたdevice側のGND。Pi GPIO GNDとはつながない |
| F06 | I2 **USB-A device** → C2 → I1 **Mini-B** | I2の切替をFull Speedにする |
| F07 | Pi4 **青USB3-A下段（基板側）** → C1 → I2 **Mini-B host** | P3の黒USB2のmodem/GNSS配線と重ねない。初回はmodem/GNSS未接続 |

I1は入力0をGNDへ落とすとtrueになる。15kΩ pull-upからの接点電流は5.3Vを上限にした概算で約0.354mA以下、電圧は接点の50V上限内。ただし接点の微小負荷保証・OFF漏れ・ON抵抗・故障時保護をこれだけで証明したことにはならない。**現物測定とメーカー接続条件の確認をF-E01に残す。** 接点閉で入力≤1.0V、開で≥1.8Vを確認。適合しなければ抵抗を思いつきで追加せず入力方式を再設計する。[H2,I1]

I1の内部でUSBと信号GNDは共通なので、I2を省かない。絶縁を跨ぐGND線、金属スペーサ、別USB・別電源・シールド接続を追加しない。I1の出力、電圧入力、5V端子は絶縁カバーで未使用とする。接点を制御する線、警報停止線は設けない。

この接点が伝えるのは連動群の火災接点状態だけで、発報室、各感知器ID、電池切れ、電波異常、断線は識別できない。**OPENを「設備正常」や「火災解除」と表示しない。** 短絡でもCLOSEになる。OSは `contact_closed` と `health=unknown` を保存し、試験時はtestラベルを付ける。最後の警報は接点開放後も履歴として残す。H4のボタン操作でも接点が開くため、警報解除の真実性を接点から推定しない。端子ごとにdevice/zoneが取れる将来のOEM adapterまで24章のrich状態は未提供。[H3]

## 4. 施設・ビルの配線境界

**F-S：S1 ⇄ S2/S3は指定無線だけ。** 各感知器の専用電池・内蔵警報・付属取付baseで完結する。H用移報adapterを挿さない。S4は純正ケーブルを未接続で絶縁保持し、miiへの接続はメーカー許可後。火災通報装置の端子へ並列割込みもしない。このためS用のmii状態連携配線はまだ組立releaseしていない。

**F-B：既設P型L/C回線 → 既設FZBJ014-R-2 → 適合FDK246 head**が確認用の固定消防経路。既設LはbaseのL・S+側、既設CはC・S−側という対応を原本図で確認する。既存の送り配線・終端・受信機・地区音響・予備電源は施設の図面で維持する。miiの電源、USB、GPIO、検知抵抗をこの回線へ追加しない。head差込刃はメーカー完成assemblyのままとし、寸法から自作刃を起こさない。

これは指定モデルの交換方式を確認する図で、未知のビルへ使う汎用接続図ではない。headを外した際の回線挙動・終端監視・復旧・火災受信は設備担当が確認する。B2説明書の新設時の適用線はφ0.9～1.2mm銅単線、剥き長10～12.5mmだが、**今回の無新規配線版では既設端子を抜かない**。その作業が必要な物件は対象外として再設計する。[B2]

量産B用はOEM承認済みmii head＋適合既設baseの組合せを完成形で検定へ出す。B1に汎用CPU・電池・無線板を貼って認定を引き継ぐことはできない。**B用のmii head型番・OEM状態無線・最終機構・受信機対応表は未確定**。B3の接点名・終端抵抗を未確認のまま推測した施工図は作らない。無工事という要件を満たさない受信機新設は、本人の最新要件に反するため初号選択肢から外した。

## 5. 電源と充電の見直し

I2の公称device供給上限350mA、I1のカタログ最大500mAは同じ条件ではない。初号はI1にセンサーや負荷をつながずDI0のみ、**I1実測50mA以下**、I2込みhost実測100mA以下を設計受入枠とする。メーカー値のI2最低29mA・効率73%を使う参考計算は29＋50/0.73≒97.5mA。これは最大値保証ではなく、列挙・再接続・接点変化時を含め測る必要がある。[I1,I2]

P3へ100mA追加すると元の2.78A→**2.88A**、USB合計1.10A→**1.20A**で、USB定格1.2Aに余裕がない。**LTE・衛星・GNSSと消防入力の全部同時接続は電源受入HOLD**。初回のF-H机上試作はMurata EVKとBU-353N5を未接続にする。これは完成品の通信要件を削除する変更ではなく、未知の負荷を切り分ける評価構成。完成品はR04のEVK最大電流回答と実測を受け、適合する別給電USB構成または低消費電力入力へ改版する。Yケーブルによる給電注入は禁止。

P3の3Sセルの監視充電条件は継承する。**現P3電池を天井内で無人充電する製品仕様にはしない。** 消防ユニットを残してCoreを外し、指定位置で充電する。外部通知はCoreが離れる／電池切れで停止し得るが、固定側警報は継続する。常時Core稼働を必要とする製品版には独立した連続給電・温度・保守の設計が必要。

## 7. 組立前・机上試験と次工程

F-E01（接点／入力）、F-E02（電源）、F-E03（取付）、F-E04（施設接続許可）、F-E05（完成品OEM）はすべてOPEN。24章F-A01～07もNOT_RUN。

1. **受領照合**：型号、刻印、電池、純正ケーブル、合格表示、説明書revision、製造日を記録。接点コネクタと電池コネクタを別々に確認。受領品と本図が違えば停止。
2. **独立警報**：机上のH1/H2を説明書どおり登録し各器単独テストと連動テスト。実火・実煙を持ち込まずメーカー指定のテスト操作を使う。これで感知性能検定に代えない。
3. **入力側だけ**：H4未接続でI2/I1を用意。DI0―Gを仮接点で短絡/開放してtrue/falseを確認。USBや火災側へ外部電源を注入しない。Phidget22の診断だけで共通OS adapter完成とはしない。
4. **F-H結線**：全電源OFFでF03～07。独立した机上H4の移報テストで閉／開入力と遅延を測る。使用説明書は連動に4～20秒程度を案内するため、補助通知の即時到達を保証しない。F-E01の入力電圧・微小負荷を確認。[H3]
5. **切離し**：CoreのUSB切断／停止／電池なしでH1/H2の警報が継続することを確認。ケーブル断線を入力正常へ変換しない。通知・保存・再開の実装試験は別途F-G06。
6. **製品化**：完成一体形状、取付荷重、流入煙、放熱、RF、接点の故障影響、専用電源の寿命、定期試験、施設ごとの機器互換性を受入。最終筐体の図面とOEM合意なしには代替使用へ進めない。

物件未指定のため、次担当は既設「head・base・受信機」の型番、用途/面積/階/警戒区域、取付穴・下地をそろえてJP-H/S/Bを判定する。問い合わせ文を用意する場合はH4微小負荷、S4外部接続、B用OEM headの検定境界を個別に書く。今回は新たな問い合わせ・購入・契約・施工を行っていない。
