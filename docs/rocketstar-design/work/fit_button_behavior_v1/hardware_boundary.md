# 洋ナシ形電源ボタン：電源管理とOSの境界

2026-09-24 / 設計案。実基板、追加回路、ファームウェアの検証は未実施。

**PANEL1へ常開スイッチを直接つなぐだけでは、OS停止時を含む独自の1回・2回・3秒/10秒長押しを保証できない。** 本版は、常時給電controllerで操作を判定し、ONだけをPWRBTN#短パルス、正常OFFをOS要求、10秒保持を独立主電源遮断ラッチへの要求として分離する。10秒は強制OFF要求の発行閾値であり、電源断完了の実測値ではない。

## 確認できた基板側の仕様

ASRock 4X4-AI350/AI340 manual v1.0の本文11頁（PDFの17頁）は、PANEL1のpin 5をGND、pin 6をPWRBTN#、pin 7をRESET#、pin 8をGNDと定義する。PWRBTNは電源スイッチ、RESETは再起動用で、同じ意味ではない。PLEDは動作時点灯、S3で点滅、S4/S5で消灯と説明される。本文3頁は12〜24V DC入力とAT/ATX動作、本文21頁は停電復帰時Power Off/Power On設定を示す。[HB-S1]

このmanualには、独自のダブルクリック判定、3秒/10秒の閾値、PWRBTN#の保証パルス幅・電気定格、製品用に取り出せるstandby/主基板power-good信号の定義がない。USB_PWRの存在からS5中の常時給電を仮定しない。PLED消灯だけではS4とS5を区別できず、主基板が完全に無給電とも判定できない。

ACPI 6.6 §4.8.2.2.1は、約4秒を超える押下に対するpower-button overrideとsoft-offへの移行を説明する。これは4X4-AI350個体の時間を実測した証拠ではないが、物理押下をPWRBTN#へ直結したまま「必ず10秒まで切れない」とする根拠にはならない。[HB-S2]

## 採用する分離案

```
洋ナシ形の押し部 → 常開接点 → 電源管理controller（追加設計）
                                  ├→ 有限の操作イベント → OSのPower Service
                                  ├→ ON時だけ接点模擬パルス → PANEL1 PWRBTN# / GND
                                  └→ 10秒時の遮断要求 → 主系DC遮断ラッチ・保護付きスイッチ

外部DC入力 → 保護 → 常時給電用変換器 → controller
                 └→ 主系電源スイッチ → Hub主基板・対象周辺機器
```

controllerは主系電源スイッチより上流から給電し、OSの起動・停止と独立して接点のチャタリング除去、押下/解放、時間計測、一度だけのイベント発行を行う。外部電源自体がなければボタンは動作できない。復電だけでは主系を自動ONせず、controllerの初期化後に新しい押下を要求する。復電時から押しっぱなしの場合も、いったん解放するまでONの新操作としない。RTC電池でcontrollerやHubを動かす前提は置かない。

物理接点をPWRBTN#へ並列直結しない。通常の1回・2回・長押しはcontroller側で確定させ、OSへ別の有限イベントとして渡す。主板へ渡すPWRBTN#は電源ON時の短パルスだけとする。正常OFF、強制OFF、ホーム、待機への操作では出力せず、長assertとRESET#も強制OFFに使わない。押下をそのまま透過すると、1回目で基板が反応してダブル判定前に停止したり、独自長押しより先に基板overrideが動いたりする。

PWRBTN#出力は主板内部のプルアップ電圧と定格を確認した上で、接点を模擬する絶縁接点または適合したオープンドレイン等を選ぶ。外部電圧をPWRBTN#へ押し込まない。通常パルスの長さは基板の最小/最大有効時間を確認して定め、100ms等の便宜値をメーカー保証としない。controllerのreset中・給電立上り・入力断では出力を解放側に保ち、誤パルスとバックパワーを防ぐ。OS経由のイベント処理とACPI電源キーの既定処理を重複させない。

## 電源状態の確認

| 観測するもの | 確認できること | その信号だけでは分からないこと |
|---|---|---|
| 外部入力電圧/電源管理側power-good | controllerの給電と主系入力が使用可能か | OSが稼働しているか、主板がS5か |
| 主系電源スイッチの出力/故障状態 | 指定したDC枝が供給されているか、過電流等の故障 | 主板内部のCPU電源状態、正常終了完了 |
| 基板の正式な電源状態信号 | メーカーが定義したS状態/主レール状態 | 取り出し点と論理が未確認なら利用不可 |
| PLEDの高インピーダンス観測 | 表示動作を補助的に判定する候補 | S4/S5の確定、残留電力の消失、OSの健全性 |
| OS heartbeat / shutdown receipt | OSサービスの現在世代と応答、正常終了への進捗 | 無応答だけで電源OFF・保存完了とはいえない |

controllerは`INPUT_ABSENT / STANDBY_AVAILABLE / BOARD_ON / TRANSITION / POWER_STATE_UNKNOWN / FAULT`等のハード側状態を持ち、OS状態と別に管理する。これは基板のACPI S状態を新たに実測済みとする名称ではない。主基板power-goodやstandbyはPANEL1の空きピンへ想像で割り当てず、メーカーの資料・確認または専用監視回路を経て定義する。

同じ押下を起動と強制停止の両方へ使わない。OFFから開始した押下はON要求1回だけとして消費し、起動開始後もいったん解放を確認するまで長押しへ再解釈しない。前回の強制OFFで主系DCが遮断されている場合は、ON要求でラッチを解除し、入力とstandbyの成立を確認してからONパルスを1回発行する。既に起動したことを検出した場合は重ねて発行しない。OFF判定が曖昧なときにPWRBTN#を繰り返し打つと電源ON/OFFを行き来するため、自動反復しない。

## 3秒・10秒と実際の作用を分ける

| 操作の意味 | 電源側とOSの分担 | 完了判定 |
|---|---|---|
| 1回・2回 | 1回は製品内待機/復帰、2回はホームをOSへ通知 | OSの状態応答。基板電源キーへ変換しない |
| 正常終了要求 | 3秒以上10秒未満で離した場合、controllerがOSへ通知し保存・停止を進める | OS手順と観測された基板電源状態を確認後に主系を遮断できる。PLED単独では判断しない |
| 強制OFF要求 | 10秒連続保持の時点でOSを経由せず主系DC遮断ラッチへ要求 | 主系電源が所定状態になったことを別計測 |
| OFFからのON | 新しい押下で給電を用意し、PWRBTN#短パルスは最大1回 | 新boot世代と起動進捗。押し続けを長押しへ再解釈しない |

PWRBTN#を10秒経過してから長くassertする方式は採用しない。その方式では基板overrideの待ち時間まで追加され、10秒完了とも言えない。本版は独立DC遮断ラッチへの要求時刻を10秒とし、controllerの時計誤差、出力遅延、スイッチ遮断、電源の残留・放電を別の時間予算として測る。10秒保持の成立後は通常OFFやクリックを追加発行せず、解放を待って次の操作を受け付ける。

独立DC遮断の対象にはHub主板とTower給電を含め、定格・ピーク電流・突入・逆流・放電・USB等からの逆給電を設計する。外部ディスプレーや別電源機器まで全て無給電にする意味ではなく、遮断対象の枝を図面と受入で固定する。これはOSの正常終了ではなく、未保存データが残り得る最終手段。強制OFFを勝手に再起動へ変えず、ボタン解放後の次の新しい操作までOFFを保持する。RESET#は再起動の別機能であり、強制OFFや工場初期化の代用品にはしない。

1回で復帰する待機は`USER_STANDBY`とする。OS・Scheduler・通信は稼働を続け、画面と入力を休止する製品内状態であり、主板のS3/S4/S0ixへ移す実スリープではない。復帰してもカメラ・マイクを再許可なしに有効化しない。将来実スリープを含める場合はUSB等のwake経路、常時給電、復帰時間とPWRBTN#不使用の両立を別途受入する。OSが固着した場合の1回/2回は効果を保証せず、10秒の独立強制OFF要求を残す。

主板のATX設定と停電復帰Power Offを製品の基準候補とし、Wake-on-LAN/RTC/USB等の復帰源は製品方針に合わせて固定・検証する。これはBIOS設定を今変更する指示ではない。ATモードや自動復帰が有効なままだと、強制OFF後の再給電で自動起動し、意図したOFF保持と衝突し得る。

## 実基板で閉じる確認事項

1. 採用PCB/BIOS版、PANEL1の向き、PWRBTN#の電圧・電流・有効パルス・長押し動作。
2. AT/ATX、停電復帰、Deep S5、各Wake源を含む全状態遷移。PLEDと実電源状態の対応。
3. controllerの上流給電、電圧低下/reset、OS停止中の時間計測、押しっぱなし起動時の再受付防止。
4. OS稼働・終了中・固着・未起動・USB通信断での、1回/2回/長押しと実出力の一意対応。
5. 強制OFF要求時刻と電源OFF完了時刻を別計測し、追加遮断経路の定格・逆給電・再投入を確認。
6. controller自身の故障時処置と手動復旧。OS非依存でもcontrollerの故障耐性まで無条件保証しない。

一次資料はヘッダー機能と標準の電源動作の根拠であり、追加controller・DC遮断回路・独自押下認識の実装証拠ではない。部品定格、主板/Towerの遮断完了時間、逆給電防止、電源状態検知は実基板と追加回路での検証待ちである。
