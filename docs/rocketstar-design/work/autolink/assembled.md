# A-LINK / AVOKADO AUTO CONNECT

衛星・携帯回線・Wi-Fi 自動切替 統合基本設計

v0.3 / 2026-09-21 / 採用方針を反映した設計版

## 01 今回採用した構成

avokadoは、登録済みの通信設定を使い、電源投入後に利用可能な回線を自動で探して接続する。衛星直通、携帯回線、利用許可済みWi-Fiの自動切替を採用する。普段は条件を満たすWi-Fi、次に携帯回線、地上回線が使えないときに衛星小データ通信を選ぶ。

衛星からavokadoへの直接受信経路は残す。衛星は地球側に広い平面通信アンテナを持つB系を配置検討の基準とし、太陽電池、放熱面、折畳み機構を別々に設計する。アンテナ方式・寸法・実送信電力は通信収支と搭載制約を通して確定する。

| 項目 | 本版での決定・扱い |
| --- | --- |
| 自動切替 | 設計として採用。利用者は通常時に回線を選び直さない |
| 衛星の役割 | 地上回線圏外での通知・テキスト・小データの双方向通信を初期目標にする |
| 動画・大型更新 | 必要な容量を持つ地上回線で扱う。衛星の高速化は追加設計 |
| 衛星外形 | B系平面アンテナ配置を作業基準。製造寸法は未承認 |
| 全経路が届かない場所 | 受信待ちへ移り、接続回復後に同期する |
| 現在の状態 | 文書・計算による基本設計。実機・通信網・飛行の実装完了ではない |

「電源がつけばどこでも受信」は製品目標として保持する。電波が遮断される場所、契約地域外、通信網障害まで無条件に受信を保証するものではない。利用者へ実際の回線と最終受信時刻を示し、圏外を接続成功として表示しない。

本版は、A-LINK検討書v0.2の「地上回線併用は未採用」という状態を更新する。RETURN-1統合設計v0.1の通信関連章と併読し、通信方式の採用状態・切替仕様・衛星配備検討については本版を優先する。ロケット両段再使用という要件は継続する。

## 02 三つの経路と責任分担

{{NETWORK_DIAGRAM}}

| 層 | 役割 |
| --- | --- |
| 配信サービス | 端末ごとの未受領データ、期限、認証、配信位置を保持 |
| 衛星網 | 地上ゲートウェイと端末間を中継。端末との方式・帯域をそろえる |
| 携帯・Wi-Fi網 | 契約・許可された地上回線でサービスへ接続 |
| 端末接続管理 | 回線の許可、能力、到達性、料金条件を確認して選択 |
| アプリ | 再接続、認証、差分同期、重複排除、受信状態表示 |

自前衛星網の基準は、対応するNTN無線方式を使い地上ゲートウェイ側でネットワークへつなぐ中継方式とする。市販の「衛星対応モデム」を載せるだけでは自前衛星へつながらない。衛星、端末、地上局、認証網の相互接続を一式で検証する。[S1]

初期の配信待ちは地上サービスと端末へ保持する。通常の中継型NTNが、地上局の見えない間も衛星内へアプリデータを蓄積する機能を持つとは仮定しない。衛星上の蓄積中継を追加する場合は別方式・別試験として扱う。

## 03 回線選択と使える機能

優先順位の適用前に、利用許可と契約、地域・時間、方式互換、認証、通信予算、用途に必要な能力を確認する。Wi-Fiへ接続できただけでは、インターネットや目的サービスへ到達したことにはならない。[S2]

| 用途 | 標準経路 | 衛星だけが使えるとき |
| --- | --- | --- |
| 通知・テキスト・小更新 | Wi-Fi→携帯→衛星 | 小データとして送受信 |
| 受領確認・差分同期 | 適合する全経路 | 双方向通信が成立した範囲で継続 |
| 通話・動画・対戦ゲーム | 能力を満たす地上回線 | 接続待ち。ローカルゲームは継続 |
| 写真・アプリ・モデル更新 | Wi-Fiを優先、携帯は設定次第 | 地上回線待ちへ保存 |

衛星の初期比較速度は上下10kbpsとする。これは必要機能を検討するための目標であり、製品速度ではない。4KiBの本文だけでも10kbpsでは約3.28秒を要し、ヘッダー、誤り訂正、再送、認証、待ち時間は別に加わる。

用途ごとに経路を選べるよう、データ要求へ用途区分、期限、許可された料金条件を付ける。最初の実装では標準IP経路と衛星小データ用の配送部を分け、全アプリが衛星へそのまま移行できるとはしない。

許可Wi-Fiが遅い、ログイン待ち、外部へ出られない場合は、使える携帯回線へ進む。衛星上で大容量速度テストを自動実行せず、小さい認証済み応答と実通信の履歴で能力を確認する。

| 03 接続先を探索 | 有効な主回線なし | 許可済み候補を探索。候補発見で04、探索周期終了で09 | 接続先を探しています |
| 04 接続を確認 | 無線接続候補あり | 契約・認証・提供能力・サービス到達を確認。成功した候補を05〜07へ | 通信を確認しています |

| 07 衛星で接続 | 衛星の認証済み通信成立 | 小データのみ。地上復帰・通信窓終了・障害で08または09 | 衛星で接続中・小データ対応 |

候補回線ごとの探索は独立させる。Wi-Fiがログイン待ちでも、有効な携帯回線まで止めない。表は利用者に見せる主状態であり、候補回線の失敗は必要な場合に小さな副表示で知らせる。

「衛星で接続中」は、衛星信号の捕捉だけでは表示しない。契約・方式・認証・目的サービスへの通信が確認できた状態に限定する。

## 05 切替の安定性とアプリ再開

次の数値は試作設定であり、実ネットワークの保証時間ではない。衛星回線の通過待ちや網側の再接続制約へ、地上回線用の短いタイマーを流用しない。

| 条件 | 初期設定案 |
| --- | --- |
| 地上回線の無応答 | 5秒間隔の確認が3回連続失敗で候補を再評価 |
| 明確な切断通知 | 上記の待ちを省略して切替を評価 |
| 優先回線への復帰 | 候補が30秒安定、現在の正常経路へ60秒滞在後に切替 |
| 主回線が故障 | 30秒・60秒の待ち条件を免除 |
| 地上経路の再試行 | 5、10、20、40、60秒。最大60秒、乱数揺らぎ±20% |
| 全経路不通が継続 | 地上探索を60秒から最大5分へ延長。状態変化時に再評価 |
| 衛星の探索・再試行 | 可視予測、取得時間、網の待機・再送制約に従う |

候補回線は目的サービスと補助的な確認先で評価し、サーバーだけの故障を回線障害と取り違えない。認証証明書の不良や契約失効は再試行の繰返しで解決させず、原因を表示する。

電力と発熱が許す場合、現在の経路を維持して次の経路を準備する。ただし切替でIPアドレスや接続が変わり、セッションは切れる場合がある。アプリは再認証、差分取得、途中再開を行う。対応プロトコルの経路移行を使う場合も、全アプリの無停止を保証しない。[S3]

## 06 保存・再送・初回設定

サーバー側は端末ごとの未受領データと配信位置、端末側は最後に確定した位置を永続保存する。復帰後は差分を取得し、電源断があっても未受領分を見失わない。

| 項目 | 初期設定案 |
| --- | --- |
| 小データ本文 | 1件4KiB以内。回線・モデムの1パケット上限とは別 |
| 未送信キュー | 1000件またはメタデータ込み10MiBの小さい方 |
| 通常保持期限 | 7日。データ固有の短い期限を優先 |
| 重複記録の保持 | 最大再送期間を超える30日を初期案にする |
| 満杯・期限切れ | 受け付け済みの重要データを黙って捨てず、結果を表示 |
| 再送ID | 一意IDと処理結果を永続記録し、同じ要求を二重実行しない |

一意IDの記録と対象処理は同じトランザクション等で一体として確定し、処理後・記録前の電源断による二重実行を防ぐ。外部サービスへの操作は相手側の一意ID受付または結果照会を必要とし、未対応の操作を自動再実行しない。「端末へ保存」「送信」「相手の受領」「処理完了」を分けて表示する。

4KiB×1000件の本文量は約3.91MiB。暗号化・索引・メタデータを含む10MiB枠は保存実装で検証する。全件を10kbpsで送るだけでも本文で約54.61分となり、衛星1回の通過ですべて送れる前提は置かない。

初回の端末登録、許可Wi-Fi、携帯・衛星契約、認証鍵、料金上限は用意する必要がある。契約・設定済みの範囲では、通常の切替のたびに確認を求めない。公衆Wi-Fiのログインや追加購入を自動承認しない。[S4]

端末ごとの認証鍵を保護し、失効と更新に対応する。IP経路は認証済み暗号化通信、非IP衛星経路を採用する場合は検証済み方式によるメッセージ保護を用いる。証明書や鍵の検証を無効にして接続を通さない。

料金は設定上限80%で通知、100%で追加課金が生じる通信を停止する試作方針とする。端末の使用量表示だけで請求額を保証せず、事業者側の上限機能・契約条件も用いる。

## 07 avokadoに追加する機能と配置

Mini200 E1の公称198×178×198mm、本体内ゲーム処理、3眼カメラ、4マイクを参照する。本体の20cm目標を保ちながら、衛星・携帯・Wi-Fiの無線枝を配置する。主基板やアンテナの実部品は未選定であり、追加後の収納成立は未確認である。[L1]

| 追加要素 | 機能とインターフェース要求 |
| --- | --- |
| 衛星無線枝 | 採用網に適合するモデム、RF回路、内蔵アンテナ。外付け試験口を検討 |
| 携帯無線枝 | 契約網対応モデム、認証情報、地域・ローミング状態の取得 |
| Wi-Fi枝 | 許可プロファイル、接続・到達状態、既存搭載分の再利用可否を確認 |
| アンテナ群 | 実周波数、偏波、筐体・人体損失、カメラ・マイクへの干渉を評価 |
| 鍵・時刻管理 | 端末鍵保護、失効・更新、衛星網に必要な位置・時刻情報 |
| 接続管理ソフト | 機器状態、認証、経路選択、キュー、回復、料金状態を統合 |

衛星アンテナは上面マイクや金属放熱器と場所を取り合う。通信面のための非金属領域、グラウンド、配線、シールドを検討し、単に未使用の空間へアンテナを挿入しない。カメラ、USB、GPU、電源変換の雑音と同時送信時の受信抑圧を測る。

機能上は三つの回線を扱うが、独立モデム3台の採用を意味しない。採用網と部品に応じて共用可能な機能を検討する。データ接続をUSB・PCIe・Ethernet等の候補から選び、主基板の実ポート、給電、ドライバー、更新・復旧を一緒に固定する。

## 08 端末の電源・熱・同時動作

既存の80Wは本体内DC負荷の設計配分であり、実測最大入力ではない。衛星・携帯・Wi-Fiの追加電力はこの80Wに含まれると扱わない。[L1]

| 設計比較点 | 本体内DC負荷 | 変換効率90%の入力側比較値 |
| --- | --- | --- |
| 既存案 | 80W | 88.89W |
| 通信追加8Wの平均比較点 | 88W | 97.78W |
| 通信追加18Wの高負荷比較点 | 98W | 108.89W |

8Wと18Wは評価用の仮枠で、モデム仕様値ではない。旧80Wが本体の実ピークではないため、108.89Wを製品最大消費電力として使わない。起動、基地局登録、衛星送信、GPU負荷、USB給電、温度低減を測るまで電源型番を確定しない。

同時送信と探索は、電力・温度・無線干渉の許容範囲でスケジュールする。必要なら旧回線と新回線を交互に使い、その際の中断を表示する。短い切替のためにファンを止めたり、熱保護を無効にしたりしない。

受入は閉じた筐体で行い、ゲーム描画、身体入力、音声、衛星探索、携帯送信、保存を組み合わせる。温度、騒音、入力遅延、受信誤りを個別に測定する。筐体外形だけが20cm以内でも、冷却やアンテナが成立している証拠にはならない。

## 09 衛星の形 B-H1 と収納・展開

{{SATELLITE_DIAGRAM}}

B-H1は、地球側の通信面、本体の機器区画、側方の太陽電池、宇宙側の放熱面を分ける配置案である。平面アンテナは分割・折畳みを検討し、ロケット内では収納、軌道上では展開・固定して使用する。

| 配置する面・機能 | 決定方針 |
| --- | --- |
| 地球側 | 利用者向け平面アンテナ。指向範囲・追尾・ビーム端の性能を評価 |
| 側方 | 太陽電池。通信方向と太陽方向が異なる条件を評価 |
| 宇宙側 | 放熱面・機器の熱輸送経路。太陽入射と展開物の遮蔽を評価 |
| 本体内部 | 通信処理、電源、姿勢制御、計算機、推進剤、配線 |
| 衛星管制・地上局向け | 利用者通信と機能を分け、通信異常時にも管制を保持 |

図は非縮尺の機能配置であり、アンテナ寸法・パネル分割数・ヒンジ型式を確定する図面ではない。開口面積、質量、電力を見積り、収納包絡と展開後の干渉を確認してから三面図と製造寸法を発行する。

利得の高いアンテナは電波を狭い範囲へ集中させる。地球へ向けることと、全可視範囲の端末へ同時に通信できることは異なる。電子走査、反射鏡、ビーム数と同時利用者数を比較し、B-H1に収まらなければ通信面や本体を改訂する。[S5][S6]

## 11 衛星と端末の通信収支

既存比較を継承し、周波数2GHz、下り衛星EIRP20dBW、端末受信利得0dBi・雑音温度500K、上り端末EIRP23dBm、衛星G/T=-5dB/K、追加損失3dBを仮定する。2GHzは計算用であり、採用帯域や送信の許可を意味しない。[S7]

最低仰角25度・高度550kmでは斜距離約1,123kmとなる。この端条件で自由空間損失は約159.48dB。1,000kmの比較より約1.01dB厳しい。復調に必要なEb/N0を仮に3dB、さらに設計余裕3dBを確保した後の残りを示す。

| 端条件の比較 | 下り余裕 | 上り余裕 |
| --- | --- | --- |
| 屋外・10kbps | +13.1dB | +8.1dB |
| 屋外・100kbps | +3.1dB | -1.9dB |
| 建物損失15dB追加・10kbps | -1.9dB | -6.9dB |
| 建物損失15dB追加・100kbps | -11.9dB | -16.9dB |

表は仮のEIRP・G/Tがその方向でも保たれる場合の利用者リンク単独の計算である。透明中継におけるフィーダーリンクの雑音、中継器雑音・歪みを合成したサービス両端の通信余裕ではない。電子走査・ビーム端・姿勢・温度の損失を別途加える。15dBは建物の固定値ではなく、感度を見るための仮値である。[S8]

屋内の不足を回線切替で補う設計にしたが、衛星RFの性能そのものが改善したわけではない。受信機、偏波、筐体、RF雑音、ドップラー、干渉、再送を実測で置き換える。高利得化だけで地下の無線経路を作れるとはしない。

## 12 衛星数・軌道配置の再検討

### まず1機で見える範囲を計算する

地球半径6,371km、高度550km、最低仰角25度の球対称モデルでは、衛星直下から可視境界までの地心角は約8.459度、地表距離は約941km、境界での斜距離は約1,123kmとなる。1機の幾何学的な可視面積は全球の約0.5439%。2機でも重なりなしの上限は約1.0877%である。

地心角はψ=acos[R cos(e)/(R+h)]−e、地表の可視半径はRψ、面積比はf=(1−cosψ)/2で求めた。1/fを切り上げると184機になるが、これは面積だけの必要下限であり、184機なら全球を埋められるという意味ではない。軌道、重なり、時間変化、アンテナの指向範囲を考慮する前の下限である。

既存の傾斜角53度では、幾何学的可視域の緯度上限は約±61.46度となり、極域は覆えない。全球を目標にする配置比較では傾斜角87度を仮定した。

### 3案を同じ条件で比較した結果

高度550km、傾斜角87度、1面24機を共通にし、12面・18面・24面を比較した。地表2,048点と24時間中300秒間隔の288時点、計589,824組を評価した。表の「可視」は、1機以上が最低仰角を超えるという幾何条件だけを指す。

| 試した配置 | 地点×時刻の平均可視率 | 衛星が見えない標本数 |
| --- | --- | --- |
| 288機 / 12面 | 96.04594% | 23,322 / 589,824 |
| 432機 / 18面 | 99.97542% | 145 / 589,824 |
| 576機 / 24面 | 99.99915% | 5 / 589,824 |

いずれの試行配置にも見えない地点・時刻があり、全標本での可視という条件を満たさなかった。576機案でも空白が5標本残り、平均値を100%へ丸めて常時接続と扱わない。432機案と576機案は軌道面・位相の再検討候補とするが、採用機数は確定しない。今回の結果は、この配置と位相についての結果であり、同じ機数の最適配置が不可能という証明ではない。

### 計算の再現条件と限界

地表点はFibonacci球面配置：k=0〜2047、z=1−2(k+0.5)/2048、経度=π(3−√5)k。真の極点は含まない。面番号j=0〜P−1の昇交点赤経はπj/P、面内番号s=0〜23の位相はu=nt+2π[s/24+j/(24P)]とした。標準Walker配置の最適解と主張するものではない。

時刻tは0〜86,100秒、刻み300秒。重力定数μ=398,600.4418km³/s²、n=√[μ/(R+h)³]、軌道周期約95.50分、地球自転角速度7.2921159×10⁻⁵rad/s。地球固定座標に変換し、地上点と衛星の単位位置ベクトルの内積がcosψ以上なら可視とした。

この離散計算は標本間の空白を見落とし得る。全標本が合格した場合でも連続全球可視の証明にはならず、平均可視率は通信サービスの稼働率ではない。次の評価は細かい時間・地点、極点、軌道誤差、故障、ビーム、干渉、地形・建物、容量、ゲートウェイ同時可視を含める。必要な地域と待ち時間を満たすことを確認してから、衛星数と補充計画を決める。

## 13 配備・地上設備・ロケットとの整合

初期の2機は、衛星・端末・地上局の相互接続と衛星切替を実証する。1回の打上げでは同じ投入軌道面から開始し、位相を離す方法・時間・推進剤を設計する。2機で常時衛星受信できるとはしない。

全球配置の候補として近極軌道を検討する場合、既存の高度550km・傾斜角53度向けのロケット性能見積りは再評価する。発射場、方位、地球自転による利得、回収域、上段帰還条件が変わる。

2機／便が実際に成立すると仮定した場合、288機で最低144便、432機で216便、576機で288便となる。これは予備・補充・試験を含まない単純割算であり、飛行計画や費用見積りではない。通信衛星群の規模に対し、1トン輸送を繰り返す方式の配備速度と運用負担を評価し、必要ならまとめて運ぶ機体構成を別設計する。

500kgは各衛星の搭載推進剤・衛星側接口を含む。機体側の保持・分離アダプターは既存上段の乾燥質量へ計上済みで、衛星質量へ二重計上しない。実質量が増えた場合や近極軌道で1トン投入が成立しない場合は、1便2機という条件を見直す。

地上設備には衛星ゲートウェイ、管制局、配信・認証、運用監視、鍵管理、周波数調整、障害対応を含める。利用者端末が見えるだけでなく、衛星とゲートウェイの同時可視、地上ネットワーク、容量、冗長性を試験する。
