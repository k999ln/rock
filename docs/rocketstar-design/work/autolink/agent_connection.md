# avokado 自動接続管理 仕様案

2026-09-21 / 概念設計・未実装・未実証

ユーザーは衛星・携帯回線・利用許可済みWi-Fiの自動選択を採用する方針に同意した。通常利用は「電源投入→自動探索→使える回線で受信」を目指す。Mini200 E1（198×178×198mm、既存DC入力80W、GPU・3カメラ・4マイク）への通信機能追加は、アンテナ・無線機・電源・放熱・干渉試験を終えていない。以下の値は製品性能ではなく、試作評価の初期設定である。

## 1. 自動接続の成立条件

- 初回に所有者登録、端末認証鍵、許可Wi-Fi、携帯・衛星の利用契約と対応地域、通信料金・ローミング上限を設定済みとする。Wi-Fiは未登録なら使わず、契約済み携帯または衛星から初期登録できる構成を検討する。
- 自動切替への同意は、未知のWi-Fi利用、追加契約、ローミング購入、上限超過料金への同意を意味しない。契約と予算の範囲内で繰り返し確認を求めず動作する。
- 自前衛星の無線方式、周波数、モデム、地上局、中継プロトコルを一式で合わせる。市販NTN対応モデムと自前衛星が自動で接続するとは仮定しない。
- 原則は双方向の小データ通信とする。受信専用方式を別途採用する場合、衛星経由の返信・受領確認・オンライン認証はできず、事前配布鍵・署名付き配信・地上回線での後日確認が必要となる。

## 2. 回線の能力判定と優先順位

「電波が見える」「無線登録できた」「目的のサービスから認証済みデータを取得できた」を別に判定する。Wi-Fi接続や衛星信号捕捉だけで受信完了表示にしない。

候補回線は、①利用許可と契約、②地域・時間帯の提供範囲、③端末との方式互換、④認証と接続成立、⑤通信予算、⑥対象サービスの容量・遅延条件の順に絞り込む。条件を満たす回線の基本順位は **許可Wi-Fi → 携帯 → 衛星**。利用者が明示設定した優先回線は許容範囲で尊重する。

| データ | 通常の経路 | 衛星だけのとき |
|---|---|---|
| 通知、テキスト、小さな状態更新 | 全経路 | 小データ機能として継続候補 |
| 通信確認、受領確認 | 全経路 | 双方向サービスの場合のみ送受信 |
| 音声、動画、ゲームのリアルタイム通信 | 能力を満たす地上回線 | 接続待ち・一時停止を表示 |
| 写真、アプリ更新、大容量同期 | 原則Wi-Fi、許可設定がある場合は携帯 | 送信・取得待ちに保持 |

順位は回線単位の固定ルートではなく、データ種別ごとに適用する。遅いWi-Fiを捕捉したまま全機能を停止させず、対象サービスに使える携帯回線を選べるようにする。能力測定には小さな認証済み応答と既存通信の実績を使い、衛星で自動速度テストや大容量測定を行わない。

## 3. 接続状態（主状態10種）

候補回線ごとの探索・認証は独立して進める。表は利用者に見せる主状態であり、Wi-Fiの承認待ちが発生しても別の有効回線を止めない。

| 状態 | 進入条件 | 動作・終了条件 | 表示例 |
|---|---|---|---|
| 01 起動 | 電源投入 | 設定・端末鍵・通信機器の自己診断後、登録確認へ | 起動しています |
| 02 初期設定が必要 | 未登録、認証情報未配布 | 初回登録を案内。設定済みの有効経路があれば設定用接続に限定して利用 | 最初の設定が必要です |
| 03 接続先を探索 | 有効な主回線なし | 許可済み候補を探索。候補発見で04、探索周期終了で09 | 接続先を探しています |
| 04 接続を確認 | 無線接続候補あり | 契約・認証・提供能力・サービス到達を確認。成功した候補を05〜07へ | 通信を確認しています |
| 05 Wi-Fiで接続 | Wi-Fiが主経路 | 対応データ送受信。障害・別経路優先条件で08 | Wi-Fiで接続中 |
| 06 携帯回線で接続 | 携帯が主経路 | 許可容量内で送受信。Wi-Fi復帰・障害で08 | 携帯回線で接続中 |
| 07 衛星で接続 | 衛星の認証済み通信成立 | 小データのみ。地上復帰・通信窓終了・障害で08または09 | 衛星で接続中・小データ対応 |
| 08 切替中 | 主経路不良、より優先する候補が安定 | 新経路を認証・確認。成功で05〜07、全候補なしで09 | 接続を切り替えています |
| 09 受信待ち | 全経路が圏外または一時利用不能 | ローカル機能・保存済みデータを継続。再探索して03へ | 接続待ち・最終受信○時○分 |
| 10 操作が必要 | 自動で使える経路がなく、登録・契約・承認等の問題あり | 対応内容を一度案内。設定変更または別回線発見で02〜04へ | Wi-Fiへのログインが必要です 等 |

衛星信号を捕捉していてもサービスの認証済みメッセージが確認できなければ07にしない。既に利用可能な主回線があるときの候補エラーは小さな副表示とし、10へ全面遷移しない。通信断では08や09を表示し、通信成功のような演出をしない。

## 4. 認証・公衆Wi-Fi

端末の秘密鍵は外部に取り出せない保管方式を候補とし、端末ごとの認証と鍵の失効・更新手段を用意する。IP経路は認証済み暗号化通信、専用の非IP衛星経路は既存の検証済み暗号方式によるメッセージ保護を使う。証明書エラー時に暗号化や検証を無効化して接続を通さない。

Wi-Fiのログイン画面や利用条件同意が必要な場合は、そのWi-Fiを通常通信用の候補から除外し、利用者が完了するまで他の経路を使う。CAPPORT情報が提供される環境はそれを利用し、未対応の場合も目的サービスへの認証済み接続で通信可否を確認する。ログイン画面への自動同意・自動購入はしない。Captive Portalでは、Wi-Fiへの接続と広域ネットワークの利用許可が別段階である。[IETF RFC 8952](https://www.rfc-editor.org/rfc/rfc8952)

## 5. 切替と揺れ抑止の初期値

| 項目 | 試作時の仮設定 | 適用上の条件 |
|---|---|---|
| 地上回線の正常性確認 | 通信中は既存の成功応答を利用。無応答時は5秒間隔、3回連続失敗で候補再評価 | 別の確認先も用い、サービス側障害と回線障害を区別する。値は障害判定の設定で復旧時間保証ではない |
| 明確な切断 | モデムの圏外・切断通知で即時に切替評価 | 連続失敗待ちを省略 |
| 優先回線への復帰 | 候補が30秒以上安定し、主回線滞在が60秒以上で切替 | 主回線が故障した場合は待機時間を免除 |
| 失敗回線の再試行 | 5→10→20→40→60秒、最大60秒、乱数揺らぎ±20% | 地上回線用。設定変更や新たな有効接続イベントでは早期再試行可能 |
| 衛星の再試行 | サービスが定める接続待ち時間・可視予測・再送制約に従う | 上記の地上回線用5秒/3回判定を衛星に流用しない。通過待ちを障害や契約切れと誤判定しない |
| 全経路不通の探索 | 地上は初期60秒ごと、長期不通では5分まで延長 | 無線状態変化・操作で即時再開。衛星は可視窓と受信機の取得時間に合わせて別管理 |
| 候補経路の同時通電 | 電力・発熱予算内で旧経路を維持しながら新経路を準備 | Mini200の80W入力に追加分が収まるとは仮定しない。収まらなければ交互探索して中断を表示 |

IPアドレスや接続先が変わるため、回線を切り替えると既存セッションが切れる場合がある。アプリは再認証、再接続、配信位置からの再開を実装する。対応する通信方式では経路変更を使えるが、QUICにも経路検証や移行条件があり、全アプリの無停止移行を保証するものではない。[IETF RFC 9000 §9](https://www.rfc-editor.org/rfc/rfc9000#section-9)

## 6. オフライン保存・再開・重複防止

サーバーは端末ごとの未受領データと配信カーソルを保持し、端末は確定済みカーソルを永続保存する。回復後はそこから差分取得する。送信待ちがある場合は暗号化した永続キューに保存し、電源断後にも復元する。

小データの仮上限は本文4KiB/件、未送信1,000件またはメタデータ込み10MiBの小さい方、通常メッセージの保持7日とする。個別の有効期限が短いデータはそれを優先する。上限超過時は明示し、既に受け付けた重要メッセージを無表示で捨てない。画像・音声・動画は小データキューに押し込まず別の地上回線待ち領域へ置く。保存サイズ・期間は製品用途と記憶容量を確認して調整する。

各メッセージに一意ID、送信元、作成時刻、期限、処理種別を付ける。受信側でIDと処理結果を永続保存し、同じIDの再送には既存結果を返す。重複記録は最大再送期間より長く、仮に30日保持する。ACK紛失や切替中の再送は起こり得るので、伝送は再送ありとし、アプリの二重実行を抑止する。購入等の取り消しにくい操作は結果照会と一意IDなしに自動再実行しない。期限切れ操作を遅れて実行しない。

「端末に保存」「送信済み」「相手が受領」「処理完了」は区別する。衛星が受信専用なら上りのACKがないため、相手側の受領確認状態は地上回線で確認できるまで確定しない。

## 7. 課金ポリシー

利用可能な回線の契約、通信量、ローミング可否、月間予算を初回設定で保存する。金額・容量が未設定の有料経路を勝手に開通しない。設定上限の80%で通知、100%で追加課金が生じる通信を停止する仮ルールとする。無制限契約であることが確認できた経路はその契約条件に従う。

回線側の計量と端末の計量には差があり得るため、端末表示だけで請求額を確定しない。契約側の上限機能を優先し、端末側は送受信・再送・接続確認の通信も含めて保守的に管理する。衛星の小データ上限はサービスのペイロード上限と料金体系が決まってから確定する。

## 8. 受入試験（10項目）

1. **登録済み起動：** 許可済み正常Wi-Fiがある場合、電源投入から60秒以内に最初の認証済み通知を表示する試作目標。30回試行し中央値・95パーセンタイル・失敗数を記録する。衛星の通過待ちにはこの時間を適用しない。
2. **経路選択：** 正常Wi-Fi・契約済み携帯・衛星模擬経路が揃った試験で、普通の通知はWi-Fiを選択する。Wi-Fiが対象サービスに到達できなければ携帯へ進む。
3. **Captive Portal：** Wi-Fiに接続できてもログイン未完了なら通常接続成功と表示しない。携帯が有効なら継続し、ログインや購入を勝手に承認しない。
4. **実障害と揺れ：** Wi-Fiの明確な切断で直ちに候補再評価する。短い復帰を繰り返しても30秒安定条件を満たすまでWi-Fiに戻らず、正常な主回線を維持する。
5. **衛星小データ：** 衛星だけの環境で4KiB以下のメッセージ送受信を確認する。受信専用構成は受信のみを合格範囲と明記する。動画・ゲームは通信成功扱いにせず待機表示する。
6. **全遮蔽：** 全経路遮断で受信待ち・最終受信時刻を表示し、保存済み内容とローカル機能を利用できる。圏外中に受信成功や新着データを捏造しない。
7. **切替中の継続：** 切替でセッションを切断し、アプリが再認証・カーソルから再開することを確認する。中断時間を計測し、無停止を合格条件や宣伝値にしない。
8. **電源断と重複：** 未ACK送信直後に電源断・復帰させ、キューを復元する。同じIDを100回再送しても表示または副作用が1回になり、期限切れ操作は実行されない。
9. **契約・料金制限：** 未契約、未承認ローミング、上限超過を注入し、その経路で有料ユーザーデータが流れないことを確認する。既存の許可済み別経路は継続する。
10. **認証異常・機器負荷：** 不正証明書・失効鍵で接続を拒否し、全無線の探索/切替を最大GPU負荷時に実行して入力電力・内部温度・電波干渉を測る。通信追加分を含む電源と熱の予算に収まるまでMini200対応を確定しない。

資料中の状態・閾値・保存容量・試験目標はこの計画の設計提案である。引用したIETF文書はCaptive PortalとQUICの性質を説明する根拠であり、avokadoの性能や実装済み機能を証明するものではない。
