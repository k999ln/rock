# 機能成立の未解決事項と閉じ方

2026-09-22。対象は RETURN-1 v0.1 と A-LINK v0.3、および最新の avocadoMini Tower20 E3。ここに示す合格値はプロジェクトの試作受入基準案であり、標準規格による製品認証値でも実測結果でもない。

## 最優先の構成差分：端末側はTower20 E3へ合わせる

最新のE3 READMEと本文は、旧E1/E2一体箱を4本のMotion Tower＋別筐体Edge Hubへ置き換えている。各塔は使用時200mmの要求、各塔1カメラの候補、Hubは240×200×70mmの検討案。通信処理はHubへ接続する。旧資料の198×178×198mm一体箱、前面3カメラ、DC80Wを新構成へ転用しない。外形と部品の具体値も製造承認済みではない。

E3の電力比較枠はHub100W＋塔4本×4W＝DC116Wであり、90%変換効率でAC入力128.9W、20%ディレーティングでDC定格145Wが必要という仮計算である。衛星通信の追加分がここに含まれるとは扱わず、実際の通信機器と給電元を決めた後で加算する。独立電源の屋外通信部はHub内発熱へ加えないが、システム全体の入力・設置機器数へ含める。共有USBへ通信部を足す場合は4カメラの帯域・同期・音声との同時動作を再評価する。

E3が報告する物理試験・実音声試験は0件。計算の30/30再現や条件比較177件を通信・ゲームの実機試験合格数へ転用しない。親タスクは実機保有の回答と環境に応じて、設計内容と実在する機器をさらに区別する。

## 今回変えるべき結論

接続管理を実装すれば、回線選択・切断待機・再開の未実装は解消できる。ただし仮の回線状態を入力する試験だけでは、実モデム制御、衛星への接続、屋内受信、ロケット帰還は解消しない。成果物の状態を「設計済み」「模擬試験済み」「実機試験済み」「運用実証済み」に分ける。模擬試験の合格を上位段階へ繰り上げない。

「電源を入れるだけ」の操作性は、事前登録済みの端末が利用可能な通信経路へ自動接続することで実現する。「外界と通信する経路が一切ない場所で、新しい情報を受信する」は実現できない。遮蔽の外で受信し有線で引き込む構成を設計に追加し、外部配線も許さない完全遮蔽場所は受信保証の対象から外す必要がある。電源線があるだけでデータ通信経路まで存在するとは扱わない。

## 衛星2機の実証と広域サービスを分ける

今回、元の球対称条件を独立した短い計算で再確認した。高度550km・最低仰角25度では1機の可視面積は全球の0.543871%、2機の非重複上限は1.087742%。傾斜角53度の可視緯度上限は約±61.459度である。2機から全球常時サービスを導くことはできない。面積だけで必要下限184機となるが、実配備数の答えではない。同梱の再計算ファイルは `analysis/space_budget_check.py`、今回の結果は `evidence/space-budget-checks.json`。

2機の合格は「選定した実証地点と通信窓で、衛星を通した通信が成立した」までにする。衛星が端末に見えても、透明中継では地上局に達するフィーダー経路が必要である。衛星への可視だけをサービス接続へ変換しない。[ETSI TS 36.300 §4.12](https://www.etsi.org/deliver/etsi_ts/136300_136399/136300/19.00.00_60/ts_136300v190000p.pdf)

| 段階 | 合格に必要な証拠 | 認める表現 |
| --- | --- | --- |
| 2機の無線実証 | 各機で、最低10回の独立した予定通信窓を観測。窓と送信負荷を事前登録し、受信成功だけを選び出さない。各窓で32件×1KiBの試験通知と受領確認を対象に、少なくとも99%が事前に定めた窓終了までに完了。全件の結果、取りこぼし、期限切れ、再送を保存。1回の成功を連続可用性としない | 「対象地点・試験窓で衛星通信を実証」 |
| 衛星間の引継ぎ実証 | 実軌道が作る通信窓の重複/空白を区別。重複しない配置なら切断後の次機での再開を確認し、連続ハンドオーバーとは呼ばない。共通の配信位置とIDで欠落・二重処理0 | 「次の衛星で同期を再開」または実証した条件付きの「引継ぎ」 |
| 広域の設計受入 | 対象地域、利用者密度、データ量、最大待ち時間、許容停止率を固定し、軌道/衛星ビーム/同時端末数/地上局/地上接続を結合。季節・軌道誤差・保守・単一衛星/地上局故障を含め、全要求地点の最悪待ち時間が予算内。平均値で局所不達を隠さない | 「対象地域のサービス設計条件を満たす」 |
| 広域の運用受入 | 設計時と同じ定義の端末測定で期間・地域・母数・欠測理由を公開。衛星の幾何可視率と認証済みアプリ配信成功率を別集計 | 測定条件を添えた稼働実績 |

32件×1KiBは1回の窓で過大な負荷を要求しないための初期基準。実効速度・取得時間・プロトコルヘッダーが決まったら、最短の予定窓に収まるか先に確認する。99%はこの有限な試験集合の受入しきい値であり、将来の99%成功確率を統計的に保証するものではない。

v0.3の288/432/576機比較は離散標本であり、576機でも空白5標本がある。次の解析は正確な極点を加え、細分化だけでなく可視の開始/終了を解いて空白時間を評価する。全球常時とする場合には空白が1つでもあればその配置を却下する。ただしビームと地上局経路を入れる前の合格は幾何可視の合格に限る。未確定のサービス水準を勝手に全球常時・無制限容量へ置き換えない。

## 両段帰還の重大な不足と受入条件

上段乾燥18t、帰還用4t、Isp等は実部品の積上げではない。今回の再計算でも基準案の理想上昇Δvは10,323.65m/sで、仮必要量10,080m/sに対する余裕は243.65m/sしかない。上段乾燥が2t増えると余裕は−26.52m/s、帰還分を2t増やして上昇分を2t減らすと−51.51m/sとなる。帰還量だけ増やして解決した扱いにしてはいけない。

旧資料の感度条件「離脱150m/s、着陸600m/s」を独立に計算すると、上段乾燥18tと非使用残量0.6tに対して帰還用推進剤は約4.896t。4tに対して約0.896t不足する。ただし150/600m/s自体が必要量を確定する飛行解析値ではない。結論は「4tで不足が確定」ではなく「4tを成立済み性能として固定できない」である。推進剤を足せばタンク・熱防護・乾燥質量も変わる。算術の式は[NASAの理想ロケット方程式](https://www1.grc.nasa.gov/beginners-guide-to-aeronautics/ideal-rocket-equation/)を用い、空力・重力・操舵の損失や実燃焼を計算したものではない。

| ID | 先に閉じる欠落 | 具体的な合格条件 |
| --- | --- | --- |
| R-1 | 同じ機体構成で上昇と帰還が両立する証拠 | 実部品質量、構造・TPSの積上げ、全消耗品と残留量、発射/回収場所、軌道を一つの台帳へ固定。校正済み飛行解析で投入条件と帰還条件を同時に満たし、全管理項目の余裕が正。仮定のままの項目が主要性能を左右する状態で製造承認を出さない |
| R-2 | 再突入の熱・空力・構造が未確定 | 飛行全区間の荷重/加熱/姿勢から最悪条件を求め、材料・取付・扉継目・損傷条件を含む試験でモデルを校正。表面温度だけでなく裏面温度、接着/取付強度、局所損傷が個別の許容値内。試験前に許容値・計測誤差・モデル誤差を固定 |
| R-3 | 姿勢遷移・液供給・再始動・着陸推力の結合 | 実飛行計算機と実証済み機器応答モデルで、主通信断、測位劣化、遅延、残量誤差等を含む事前登録ケースを実行。到達可能域、機器飽和、液供給、電力、着陸荷重の要求違反0。違反ケースを除外して合格に変更しない |
| R-4 | 回収した同じ機体が再び使える証拠 | 同一ミッションで両段が所定回収条件を満たす。各機番の点検で未許容損傷0、寿命記録と交換内容を記録。回収した同一機番の両段が再整備後に再飛行・再回収されて初めて両段再使用を実証とする。片方を新品に交換した飛行は両段再使用実証へ数えない |

R-2の合格限界は材料によって異なるので、一律の耐熱温度を新たに発明しない。再使用可能温度と一回限り耐える温度を区別するのは[NASAの再使用熱防護資料](https://www.nasa.gov/general/thermal-protection-materials-branch-reusable-materials/)とも整合する。帰還の誘導制御、姿勢が変化する間の推進薬管理、再整備を結合して扱う根拠は[JAXA CALLISTO](https://www.kenkai.jaxa.jp/project/callisto/callisto.html)の研究課題にも示されている。

今回の接続ソフト試験はR-1〜R-4の証拠にはならない。端末開発をロケット完成まで止める必要はなく、実衛星サービスとの通信試験や衛星ペイロードの地上試験は別経路で進められる。自前ロケットの両段再使用要件はそのまま保持する。

## 親タスクへの反映指示

成果物の先頭では、今回実際に通したソフト試験の件数と範囲を示す。屋外通信部・有線引込を遮蔽条件に対する設計変更として具体化するが、設置なしのどこでも受信を達成したとは言わない。実機、衛星網、ロケットは未試験のまま完了扱いにしない。要求IDごとに証拠を対応させる形式は[NASAの要求検証マトリクス](https://www.nasa.gov/reference/appendix-d-requirements-verification-matrix/)を参照できるが、本書の数値しきい値は独自の試作基準である。
