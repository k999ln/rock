# RETURN-1 / AVOKADO LINK

両段再使用ロケット・小型通信衛星・avocadoMini 統合設計書

版 0.1 | 2026年9月21日 | 基本設計・成立性評価

目的は、小型通信衛星を軌道へ届け、ロケットの1段目と2段目をそれぞれ回収・再飛行させ、その衛星からavocadoMiniへデータを届けることである。

本文は方式、機能、質量、帰還、熱、通信、保守、試験の設計を定義する。計算値は記載した仮定に基づく机上値であり、製造承認図、飛行手順書、実証済みの性能表ではない。

## 01 設計の結論と到達点

### 採用するシステム

無人の2段式ロケットを用いる。両段とも液体酸素と液体メタンを使い、1段目は海上の回収設備へ、2段目は軌道離脱・大気圏再突入の後に指定回収場へ垂直着陸する。衛星を覆う扉と段間部は機体に保持し、通常飛行で投棄しない。衛星は軌道で仕事を続け、ロケットが帰還する。

衛星系は、550km円軌道・軌道傾斜角53度・500kg級通信衛星2機を初期の検討条件とする。高度、傾斜角、衛星数はユーザーの確定仕様ではなく、機体・通信・運用の検討をそろえるための仮定である。発射場が決まれば軌道と輸送性能を再計算する。

avocadoMiniは参照設計Mini200 E1を継承する。公称198×178×198mm、内蔵ゲーム処理、前面3眼カメラ、4マイク、外部TV・外部電源という構成へ衛星通信を追加検討する。既存設計に衛星対応無線機が搭載済みとは扱わない。[L1]

### 「完成」を分けて管理する

| 到達点 | 達成と呼ぶための証拠 |
| --- | --- |
| 設計書の整備 | 要件、予算、未確定項目、試験の対応が追跡できる |
| 両段回収 | 同一ミッションで両段が予定区域へ着陸し、安全化できる |
| 再使用実証 | 回収した同じ機体が再整備後に再飛行し、再び回収される |
| 継続運用 | 部品寿命・交換率・整備工数・費用を複数飛行で測定する |
| avokado通信 | 衛星由来のデータが認証され、対象端末で受信・表示される |

現時点で行ったのは文書化と単純モデルの算術確認である。エンジン燃焼、風洞、構造、実機通信、軌道飛行、回収、再飛行の実証は行っていない。

## 02 要求の優先順位と設計境界

設計優先順位は、第三者と運用者の安全、機体の制御可能性、帰還・再使用、衛星の軌道投入、通信サービス性能の順とする。投入能力を大きく見せるために帰還用推進剤を上昇へ流用した条件を、標準性能に含めない。

| ID | 要求 | 確認方法 |
| --- | --- | --- |
| SYS-01 | 無人で500kg級衛星2機、計1,000kgを参照軌道へ輸送する | 軌道解析・飛行測定 |
| SYS-02 | 1段目と2段目を両方回収する | 同一飛行の追跡・着陸記録 |
| SYS-03 | 同一機体を再使用できる構造・推進・整備体系を持つ | 寿命試験・再飛行 |
| SYS-04 | 通常運用で扉・フェアリング・段間部を投棄しない | 構成照合・分離試験 |
| SYS-05 | 衛星からavocadoMiniへのデータ受信経路を設ける | 無線・端末統合試験 |
| SYS-06 | 通信不能でも端末のローカルゲームと入力を継続する | 通信断・高負荷試験 |
| SYS-07 | 正常系から独立した飛行安全機能を持つ | 独立性解析・故障注入 |
| SYS-08 | 機番・部品・飛行・検査・交換履歴を追跡できる | 記録監査 |

有人搭乗、月・火星輸送、任意地点への着陸、初期からの全球常時通信は今回の性能要求に含めない。将来の追加は、それぞれ独立した要件改訂とする。

第1段の発射場帰還は将来案とする。初期は飛行方向の海上回収で帰還負担を抑える。第2段の回収場も発射場と同じ場所である必要はない。地球の自転、軌道面、着陸場への到達性に応じて回収時刻と場所を決める。

### 回収方式の比較

| 案 | 利点 | 主な負担 | 判断 |
| --- | --- | --- | --- |
| 両段の推進着陸 | 回収後の塩水浸漬を避け、機体姿勢を管理できる | 帰還燃料、再着火、推力調整、脚、上段の熱防護 | 基準案 |

## 04 機体配置・外形・構造

外形の検討枠は、胴体外径5〜6m級、全高55〜70m級とする。これはパッケージング探索範囲であり、確定寸法ではない。衛星が小さくても、上段の熱防護・脚・帰還推進系の質量が大きいため、機体を小型と決めつけない。

機体上部から、保持式ペイロード扉と収納室、上段航法区画、酸化剤・燃料タンク、推進区画、段間接続、第1段タンク、ブースター推進区画を置く。翼面・熱防護・配管・点検口の位置は、全飛行状態の重心と圧力中心を解析して決定する。

| 部位 | 設計方針 | 詳細設計で必要な成果物 |
| --- | --- | --- |
| タンク・一次構造 | 溶接金属を基準に低温靱性・疲労・加工性を比較 | 材料許容値、板厚、溶接仕様、座屈・強度解析 |
| エンジン支持 | 荷重を主要フレームへ伝え、点検と交換を可能にする | 推力・振動・熱変形を含む荷重経路 |
| 段間接続 | 分離機構と配線・配管の切離しを一体設計する | 分離衝撃、再接触、誤分離への検証 |
| ペイロード室 | 蝶番・ラッチ付き保持式扉、汚染と局所加熱を管理 | 開閉信頼性、変形時の閉鎖、再突入時気密・熱評価 |
| 着陸脚 | 交換可能な吸収部と機体転倒余裕を持つ | 接地荷重、傾斜、滑り、海上設備動揺の組合せ |

荷重条件は、地上支持、風、輸送、点火、最大動圧、加速度、段間分離、再突入、着陸、吊り上げを含める。限界荷重・終極荷重・安全係数は採用規格と材料試験に基づいて確定し、未知の材料強度へ一律の係数をかけて製造可能としない。

## 05 質量予算と上昇性能

全質量はトン(t)。以下は部品見積りではなく設計配分である。乾燥質量には構造、推進装置、脚、舵面、電装を含め、上段では熱防護・ペイロード扉・機体側アダプターも含める。

| 項目 | 第1段 | 第2段 |
| --- | --- | --- |
| 成長余裕前の乾燥質量配分 | 32.0 | 14.4 |
| 乾燥質量の成長余裕25% | 8.0 | 3.6 |
| 計算に使う乾燥質量 | 40.0 | 18.0 |
| 上昇用推進剤 | 380.0 | 150.0 |
| 帰還用の使用可能推進剤 | 24.0 | 4.0 |
| 着陸時の未使用量 | 1.0 | 0.6 |
| 段単体の打上げ質量 | 445.0 | 172.6 |

衛星2機で1.0tを加え、打上げ総質量は618.6t。推進剤等の充填総量は559.6tで、乾燥58.0tと衛星1.0tを合わせると一致する。乾燥質量の25%余裕はすでに算入済みで、総質量へさらに25%を加えない。

理想ロケット方程式は Δv = g0 × Isp × ln(m0/mf)、g0 = 9.80665m/s²。第1段の平均比推力330秒、第2段370秒を仮定する。[S1]

| 上昇区間 | 開始→終了質量 | 計算上のΔv |
| --- | --- | --- |
| 第1段 | 618.6→238.6t | 3,083m/s |
| 第2段 | 173.6→23.6t | 7,241m/s |
| 合計 | 帰還用は消費しない | 10,324m/s |

238.6tは第1段帰還機65.0tと第2段・衛星173.6tの合計。23.6tは上段乾燥18.0t、帰還4.0t、未使用0.6t、衛星1.0tの合計である。

必要な理想Δvを9,600m/sと仮置きすると差は724m/s。さらに5%の性能余裕を求めた10,080m/sに対して244m/s残る。ただし9,600m/sは軌道解析前の仮条件である。高度・発射緯度・方位・燃焼時間による重力、抵抗、操舵の損失を求めて置き換える。必要量9,800m/sなら差は524m/sで、その5%条件10,290m/sに対する残りは34m/sしかない。

### 感度と設計変更の判断

| 条件 | 理想Δv合計 | 10,080m/sとの差 |
| --- | --- | --- |
| 基準案 | 10,324m/s | +244m/s |
| 上段乾燥18→20t | 10,053m/s | -27m/s |
| 両段のIspが各10秒低下 | 10,035m/s | -45m/s |
| 上段帰還4→6t、上昇150→148t | 10,028m/s | -52m/s |
| 上段乾燥+2t、両段Isp各-10秒 | 9,772m/s | -308m/s |

上段上昇用112tの比較案では総質量580.6t、合計Δv9,783m/sだった。基準案は上段推進剤を38t増やすが、上段乾燥18tを維持できる根拠は未確定である。タンクと熱防護の大型化、燃焼時間、点火時推力重量比が変わるため、この増量だけで飛行成立と判定しない。

暫定的な乾燥内訳は、第1段32tを構造17・推進9・舵面脚3・電装配線2・その他1へ、上段14.4tを構造5・推進3・熱防護2.5・舵面脚1.5・電装1・扉と機体側分離部1.4へ配分する。詳細積み上げがこの枠を超えたら、感度表の通り全体を再設計する。

## 06 帰還用推進剤の予算

第1段は分離後65.0t、第2段は衛星放出後22.6tを帰還開始質量とする。上昇用推進剤を消費した後にも、以下の帰還分を機体に残す。

| 段・用途 | 使用可能量 | 計算上の能力・扱い |
| --- | --- | --- |
| 第1段の帰還・着陸 | 24.0t | Isp 310秒の仮定で理想Δv 約1,401m/s |
| 第1段の着陸後残量 | 1.0t | 燃焼に使えるとはみなさない |
| 第2段の離脱・軌道調整 | 0.8t | 22.6→21.8t、Isp 360秒で約127m/s |
| 第2段の終末降下・着陸 | 3.2t | 21.8→18.6t、Isp 320秒で約498m/s |
| 第2段の着陸後残量 | 0.6t | 燃焼に使えるとはみなさない |

第2段の帰還用理想Δv合計は約625m/sである。これは軌道速度をエンジンだけで打ち消す能力ではない。大部分の減速を大気で行う前提で、そのために熱防護と姿勢制御が必要になる。

約127m/sの離脱能力は、550km軌道から所定の再突入回廊へ入れることをまだ証明していない。離脱点、近地点、飛行方向、着陸場、推進誤差、待機時間を同時に解析する。仮に離脱150m/s・着陸600m/sを必要とすれば、帰還用は約4.90tとなり、4.0t案は約0.90t不足する。

本表の1.0t・0.6tは着陸後まで残る非使用質量として計算した。途中消費する姿勢制御剤、冷却・再着火消費、ベント損失等は未配分であり、乾燥質量・使用可能推進剤・残留量の台帳へ別途反映して再計算する。加圧ガスも別項目へ展開し、二重計上しない。

## 07 推進・タンク・流体系

両段の推進剤を液体酸素・液体メタンにそろえる。エンジンサイクル、燃焼圧、混合比、ノズル形状、噴射器、ターボポンプ型式は未選定であり、比推力の仮値から製造仕様を逆算して確定しない。

| 系統 | 要求する機能 | 主要な確認事項 |
| --- | --- | --- |
| 第1段主推進 | 離昇、上昇推力調整、帰還再着火、着陸 | 始動過渡、最低安定推力、故障時推力偏り |
| 第2段主推進 | 軌道投入と離脱に必要な再始動 | 真空始動、長時間待機、推進剤沈降 |
| 上段着陸推進 | 空力減速後の姿勢遷移・接地速度低減 | 主推進とは別の低推力域、応答・供給安定 |
| 主タンク | 低温保持、液量推定、供給、圧力維持 | 熱侵入、スロッシング、圧力変動、残液測定 |
| 着陸用供給 | 姿勢が大きく変わっても液を供給 | 小型保持タンク等の比較、気泡吸込み・漏洩 |
| 弁・加圧・ベント | 遮断、圧力管理、安全化 | 固着、誤状態表示、配管熱変形、共通故障 |

エンジン数は推力、径、冗長性、製造性の比較から決める。たとえば離昇推力重量比1.3を仮定した場合の必要推力は質量×g×1.3で得られるが、その値だけではエンジン数も単基故障時の継続可否も決まらない。

着陸時に必要なのは最大推力だけではない。第1段の約41t、第2段の約18.6tという接地側質量に対して、推力下限と推力応答を確認する。上昇用の大推力エンジンをそのまま絞れば着陸できる、と仮定しない。再始動回数・待機時間・着陸条件は実証前の要求として管理する。

JAXA CALLISTOも、帰還中の推進薬管理、誘導制御、エンジン再整備を重要課題としている。本機でも流体系、姿勢、整備を個別に最適化せず、結合して検証する。[S4]

## 08 打ち上げから帰還までの状態遷移

時刻固定の操作列ではなく、センサーと機体状態による遷移を定義する。実飛行の閾値と時間は飛行解析・試験後に別文書で確定する。

| 状態 | 主な仕事 | 次へ進む条件 |
| --- | --- | --- |
| 地上待機 | 構成・気象・回収場・推進剤・通信を照合 | 飛行と回収の両方が実施可能 |
| 上昇 | 荷重制限内で加速、残量と機体健全性を推定 | 分離条件を満たす |
| 段分離 | 推力状態と間隔を管理し分離 | 分離確認・再接触回避が成立 |
| 第1段帰還 | 回収回廊へ進み、大気減速と推進を組み合わせる | 着陸能力・区域内到達性を維持 |
| 第2段軌道投入 | 衛星に必要な軌道を形成 | 軌道・姿勢・衛星健全性が適合 |
| 衛星放出 | 扉を開き2機を時間差で分離 | 衝突回避、放出確認、扉閉鎖を確認 |
| 軌道離脱 | 回収場と再突入条件へ合わせる | 熱・姿勢・電力・推進予算が成立 |
| 再突入・着陸 | 熱防護面を保ち、減速後に接地姿勢へ移る | 所定の回廊内で接地可能 |
| 安全化・輸送 | 残留エネルギーを管理し機体を固定 | 回収員が接近できる状態を確認 |

衛星放出前に異常があった場合、衛星を搭載したまま帰還できると無条件には扱わない。残留ペイロードによる質量・重心・着陸推力・熱履歴を別解析する。帰還可能範囲外なら、その状態に対する飛行安全方針をあらかじめ定義する。

## 09 第1段の海上帰還

基準は飛行方向の海上回収とする。分離後は、推力停止・分離確認、姿勢の再確立、回収可能域の再評価、再突入・大気減速、終末航法、脚展開確認、着陸、安全化の順で機能を分ける。

帰還誘導は、海上設備の位置だけでなく、残推進剤、風、機体姿勢、エンジン健全性、航法誤差、甲板動揺を入力とする。設備の位置更新が失われた場合にも、古い位置へ盲目的に進み続けない。

| 課題 | 設計上の扱い |
| --- | --- |
| 横風・上空風 | 風の分布と誤差を含む多数条件解析、舵面飽和の確認 |
| 機体の再着火 | 液の供給状態、温度、圧力、再始動待機時間を認定 |
| 甲板の移動・傾斜 | 船位・動揺の計測と通信遅延を含む着陸許容域を定義 |
| 接地後の転倒 | 脚間隔、重心、残液移動、固定機構、風の組合せ評価 |
| 航法・通信異常 | 安全機能が必要な場合に帰還最適化より優先される |

着陸目標は、初期評価用として接地水平速度1m/s以下、鉛直速度2m/s以下、傾き5度以下を置く。ただし脚の強度や海上動揺との整合が必要であり、現段階の受入保証値ではない。最終値は着陸荷重試験と結合させて確定する。

着陸の成功と再使用可否は別判定とする。着陸時に機体が立っていても、脚・推力支持部・タンク・配管に未許容損傷があれば、隔離して再飛行を認めない。

## 10 第2段の軌道帰還と熱防護

第2段は、衛星の運搬機であると同時に軌道速度から帰還する再突入機である。550km円軌道の速度は球対称重力の近似で約7.59km/sとなる。熱は速度だけで決まらず、大気密度、機首半径、姿勢、局所形状、飛行時間に依存する。

基準案は、熱防護を設けた面を風上へ向ける高迎角降下、空力制御面による姿勢・降下位置の調整、十分に減速した後の姿勢遷移、専用着陸推進による垂直着陸とする。機体形状とこの飛行方式の安定性は未検証である。

| 熱防護区域 | 設計方針 | 調べる量 |
| --- | --- | --- |
| 風上の広い面 | 交換・検査可能な再使用断熱材 | 熱流束、総受熱量、裏面温度、剥離 |
| 前縁・突出部 | 高温対応材料と荷重支持の一体検討 | 局所加熱、酸化、熱疲労、接合部 |
| 扉・継ぎ目・舵面 | ギャップと変形を含む熱侵入対策 | 段差、漏れ、ラッチ温度、開閉の再現性 |
| 推進区画 | エンジン・配管・脚根元を保護 | 再突入加熱と噴流再循環の組合せ |

NASA資料は、再使用できる温度限界と一回なら耐える限界を区別している。本設計でも最大耐熱温度だけで材料を採用せず、再使用回数、継ぎ目、欠損時、修理後を確認する。[S5]

着陸へ向けて機首方向を変える際は、空力安定性、液体の移動、着陸用推進剤供給、エンジン始動を同時に扱う。熱防護材の剥離・扉閉鎖未確認・航法品質不足の場合の挙動を事前に定義し、地上通信が途切れても機上で状態管理を続ける。

上昇・衛星放出後に生じた熱防護の損傷を、再突入前に評価する方法と検出限界は未確定である。地上検査結果だけで飛行中の無損傷を保証せず、機上計測や撮像を含む方式を比較する。

## 11 航法・制御・電源・ソフトウェア

慣性計測と衛星測位を基幹にし、終末降下では地表または甲板との相対距離・速度を測るセンサーを比較する。機上時刻、座標系、測定遅延、センサー校正を共通仕様で管理する。単にセンサーを複数置くだけでは冗長性にならない。

| 機能 | 構成案 | 故障時に確認すること |
| --- | --- | --- |
| 飛行計算 | 複数計算系、電源・通信経路の分離 | 共通ソフト不具合、同時再起動、時計ずれ |
| 航法 | 慣性・GNSS・終末センサーの統合 | 古い測定、飛び値、欠落、互いの矛盾 |
| 制御 | 推力方向・舵面・姿勢制御の役割分担 | 飽和、遅延、固着、機体柔軟性 |
| 電力 | 帰還・安全化まで独立供給 | 再突入加熱、低温、ピーク負荷、劣化 |
| 通信 | 地上監視、飛行ログ、追跡ビーコン | 通信断でも必須機能が継続できること |
| ソフト更新 | 地上で構成固定、署名検証、復旧版 | 機番違い、誤設定、更新途中の電源断 |

電池容量は区間ごとの平均電力×時間の総和に、ピーク、低温・経年劣化、変換損失、待機延長の予算を加えて決める。上段の軌道待機を長くする案は、帰還用推進剤の蒸発と電池容量の両方を再計算する。

飛行制御の判断周期・ゲイン・軌道データは、機体モデルが確定してから設定する。LLMや端末のゲームOSを飛行制御の決定経路に置かない。avocadoMiniへ見せる飛行情報は閲覧用に分離し、受信機能からロケットへの操縦権限を作らない。

## 12 故障時の方針と独立安全機能

以下は故障の検出と設計上の反応を定義するもので、射場の実運用命令ではない。異常を検知しただけで一律にエンジンを停止する設計にも、一律に着陸を続ける設計にもしない。飛行状態と周囲への影響で適切な対応が異なる。

| 故障例 | 検出の根拠 | 基本方針・試験 |
| --- | --- | --- |
| 推進系1系統の機能喪失 | 推力・圧力・姿勢応答の整合 | 残る制御能力を評価。全区間の飛行継続は保証しない |
| GNSS異常 | 慣性系・他計測との差 | 誤測定を隔離、航法不確かさを拡大して判定 |
| 主通信断 | 更新欠落・経路監視 | 機上自律機能を継続、独立安全機能を保持 |
| 熱防護の損傷兆候 | 熱履歴・温度・地上検査情報 | 帰還可能域と残余機能を評価、次回飛行を保留 |
| 扉・脚の不一致 | 冗長状態検知、駆動応答 | 再指令の回数と期限を限定、未確認を成功にしない |
| 着陸用残量不足 | 液量・消費積算・推力履歴 | 投入能力の帳尻合わせにせず飛行可能域を再判定 |
| 回収場が使えない | 気象・船舶・設備の状態 | 発射前に止める条件と飛行中の代替方針を定義 |

飛行安全系は、帰還誘導や衛星サービス系から電源・判断・指令経路の独立性を持たせる。具体的な区域、閾値、最終措置は、射場と安全解析の承認済み要求から決める。

解析では単一故障だけでなく、共通電源、共通時計、同一ソフト、熱による複数センサー故障を調べる。信頼性数値を試験本数だけから保証せず、故障率の根拠、独立性、モデル仮定を残す。

## 13 回収後の整備と再飛行判定

帰還機は、安全化、機体固定、輸送、洗浄・外観記録、非破壊検査、機能確認、修理・交換、構成確認、再飛行審査の順に管理する。海上回収では塩害と湿気を追加し、上段では再突入の熱履歴を重視する。

| 対象 | 毎飛行で残す記録 | 再使用を止める条件 |
| --- | --- | --- |
| 主構造・タンク | 加圧回数、ひずみ、温度、衝撃、漏れ | き裂、許容外変形、検査範囲外の損傷 |
| エンジン | 燃焼時間、始動回数、過渡、部品交換 | 寿命限界、異常摩耗、必要性能未達 |
| 熱防護 | 区画ごとの損傷、交換、接着・取付状態 | 剥離・欠損、裏面損傷、修理未検証 |
| 脚・舵面・駆動部 | 接地荷重、作動回数、遊び、潤滑 | 変形、駆動不一致、限界超過 |
| 電池・航法・配線 | 容量、校正、絶縁、コネクタ履歴 | 校正期限外、容量不足、接触不良 |

NASAの非破壊検査事例では赤外線等を用いて内部損傷を調べている。外観がきれいであることを、熱防護や構造が再使用可能な証拠にはしない。[S6]

開発目標は、まず同一機体の2回目飛行、次に5回、10回へ段階的に広げる。初期認定後の計画目標として第1段20回・第2段10回を置けるが、試験で裏付ける前は保証寿命にしない。部品は機体と別々に寿命管理し、定期交換が必要でも、機体全体の使い捨てとは区別する。

整備日数は、運用目標案として第1段30日以内・第2段60日以内を置き、初期回収機の実績で見直す。短縮より先に、点検の検出能力と再現性を確立する。

## 14 地上設備とインターフェース

発射設備だけでは反復運用できない。海上回収設備、上段着陸場、残留エネルギーの管理設備、輸送架台、非破壊検査、熱防護修理、推進系点検、衛星地上局、端末試験設備までを開発対象に含める。

| ICD | 接続 | 固定する内容 |
| --- | --- | --- |
| IF-01 | 第1段／第2段 | 荷重、位置、公差、電気、時刻、分離状態、機体保持物 |
| IF-02 | 上段／衛星 | 質量・重心、包絡、振動、音響、熱、清浄度、分離速度 |
| IF-03 | 機体／地上設備 | 支持点、給排液、接地、遮断、状態確認、構成識別 |
| IF-04 | 帰還機／回収場 | 位置座標、時刻、着陸許容範囲、接地荷重、固定方法 |
| IF-05 | 衛星／地上局 | 無線方式、認証、追跡、データ形式、再送、時刻 |
| IF-06 | 衛星通信部／Mini200 | 電源、データ端子、帯域、熱、権限、更新、障害表示 |

値の単位はSIを基準とし、座標系、軸方向、時刻系、符号を明示する。仕様の単位が合っていても、機体中心とセンサー原点の違いで事故につながるため、変換定義をインターフェース契約に含める。

衛星分離試験では、ダミー質量、重心、ケーブル、扉開閉を実機条件へ近づける。分離した2機が互い・上段・扉へ接触しないことと、放出後の上段が帰還構成へ移れることをセットで検証する。

## 15 試験計画と開発ゲート

要件ごとに解析、試験、検査、実演の証拠を対応させる。NASAの要求検証マトリクスはこの整理の参考とし、本機の要求と合格条件は固有に定義する。[S8]

| 段階 | 主な活動 | 次へ進むための条件 |
| --- | --- | --- |
| G0 要求・基本設計 | 軌道・回収・質量・通信の条件統一 | 主要な予算と未解決課題に担当と期限がある |
| G1 要素実証 | 材料・低温構造・エンジン・熱防護・無線 | 要素ごとの性能と故障モデルを取得 |
| G2 統合地上試験 | 段間、配線、実計算機、流体系、衛星分離 | 故障注入を含む統合機能が要求へ適合 |
| G3 低高度回収試験 | 着陸推進、航法、脚、回収整備 | 同じ試験機で反復し、点検後再飛行を実証 |
| G4 高エネルギー帰還試験 | 上段の熱・姿勢・遷移を段階評価 | 軌道帰還を外挿できる検証モデルを整備 |
| G5 軌道実証 | 衛星投入、両段回収、衛星受信 | 要求ごとの証拠がそろう。1回で寿命認定しない |
| G6 再飛行実証 | 同一機番を再整備して再飛行 | 構造・推進・熱防護の劣化モデルを更新 |

上昇・帰還解析は最初に3自由度で質量と軌道を調べ、次に6自由度、柔軟性、液体振動、舵面・推力応答、風、航法誤差を結合する。多数条件のシミュレーションは試験で校正し、回数の多さだけで信頼性を示さない。

ソフトウェアは、モデル上の試験、実計算機と模擬センサーをつなぐ試験、実アクチュエーターを含む試験へ進める。リセット、計測順序逆転、通信遅延、古いコマンド、電圧低下、センサー固着を正常条件と同じ程度に扱う。

## 16 主要リスクと設計を変更する条件

| リスク | 性能への影響 | 設計変更の判断 |
| --- | --- | --- |
| 上段の乾燥質量増加 | 軌道投入と帰還の両方の余裕が減る | 熱防護・脚・タンクを積み上げ直し全体再計算 |
| 帰還推進剤不足 | 接地まで制御能力を維持できない | 搭載量を増やす、回収方式・ミッションを変更 |

| 姿勢遷移と液供給の不整合 | 終末再着火の失敗 | 姿勢計画、保持タンク、着陸推進を結合再設計 |

| 衛星の通信能力不足 | avokadoへ電波が届いても復号できない | アンテナ、電力、帯域、方式、端末側を変更 |

開発期間や費用を、機体質量だけから確定しない。必要なチームは、機体・構造、推進、空力・熱、航法制御、電気・ソフト、飛行安全、地上運用、品質、衛星・RF、端末統合である。工程は年月の断定より、上表の技術ゲートに従って管理する。

反復1回の費用は、機体償却、寿命部品、推進剤、整備工数、地上設備、海上回収、衛星統合、運用を合算する。機体償却は製造費÷認定使用回数を出発点にするが、故障損失と中途退役を別計上する。部品費と工数の見積り前に「使い捨てより必ず安い」と結論しない。


## 17 衛星からavokadoへ届く全体経路

通信の目的は、衛星からavocadoMiniへ認証されたデータを届けることである。希望する通信速度は未確定のため、初期は短いメッセージと小容量データの受信を検証し、双方向通信と広帯域通信を追加の性能段階として設計する。

### データが流れる順序

配信サービス → 地上ゲートウェイ → 衛星の中継・保存機能 → 利用者向け電波 → avokadoの衛星アンテナ・無線機 → RockstarOSの検証・保存・表示。

返信やインターネットでは、この逆方向も必要になる。受信だけの放送サービスなら端末の送信機を省く案を比較できるが、Web要求、ログイン、アップロード、通話、受領確認まで使う場合には上り回線も設計する。

| サービス段階 | 初期の比較条件 | 必要になるもの |
| --- | --- | --- |
| A 受信中心 | 通知、配信文書、小データ | 下りリンク、受信機、署名検証、未受信データの再配信 |
| B 低速双方向 | 上下10kbpsを計算比較点にする | 上り送信、接続認証、送信制御、両方向の通信余裕 |
| C より高速な双方向 | 100kbps以上を拡張比較点にする | 衛星と端末の利得・電力・帯域の増強 |
| D 通常・高速ネット | Web、通話、大容量、動画 | 地上網接続、連続カバレッジ、同時利用容量、広帯域端末 |

この速度は規格や市販製品の保証値ではない。3GPPのNR-NTNとIoT-NTNは異なる方式群であり、対応モデムを選んだだけでは自前衛星や地上局との接続が成立しない。衛星・地上網・端末の対応規格、周波数、タイミング、認証をそろえる。[S9]

ロケットの飛行通信、衛星管制の通信、利用者のデータ通信を別系統として設計する。avokadoで衛星データを受け取れることが、衛星やロケットを操作する権限にはならない。

## 18 500kg級通信衛星の構成予算

2機は通信・運用実証の初期構成とする。各機の500kgは、放出時点の構造、展開物、搭載推進剤、成長余裕を含む総質量である。上段に残る分離アダプターは上段の乾燥質量へ含め、衛星500kgへ二重計上しない。

| サブシステム | 1機あたりの仮配分 | 主な機能 |
| --- | --- | --- |
| 通信ペイロード | 100kg | 無線処理、増幅器、利用者・フィーダーアンテナ |
| 一次構造・展開機構 | 65kg | 打上げ荷重、アンテナ・太陽電池の保持と展開 |
| 電源 | 85kg | 太陽電池、電池、配電・保護 |
| 姿勢制御 | 35kg | 姿勢測定、指向、外乱抑制 |
| 軌道制御 | 55kg | 推進系・搭載推進剤、軌道保持・衝突回避・廃棄 |
| 熱制御 | 25kg | 放熱面、断熱、温度監視 |
| 計算機・管制通信 | 25kg | 記録、指令検証、健全性、更新・復旧 |
| ハーネス・保持接口 | 10kg | 電源・通信配線、衛星側の分離部 |
| 小計／成長余裕 | 400kg／100kg | 小計に25%を付加 |
| 総質量 | 500kg | 質量配分であり部品見積りではない |

定常電力の初期比較点を1kWとする。例として通信400W、姿勢・計算・管制200W、熱・電源損失200W、余裕200Wへ配分する。無線EIRPと電源消費は別の量であり、100kgや400Wの枠だけで通信容量を保証しない。

発電・電池は日照と食、太陽電池の姿勢、経年劣化、送信ピーク、電源変換、再充電を含めて設計する。定常1kWで35分間の食を仮定すると、負荷側の必要エネルギーだけで約0.583kWhとなる。実電池容量は放電深度、効率、劣化を含むため、これより大きい。

衛星間リンクは初期必須としない。搭載保存による遅延配信と、衛星・地上局が同時に見える間の中継を比較する。後者を常時ネットと呼ぶには、可視時間とネットワーク構成の追加検証が必要である。

## 19 軌道・カバレッジ・サービス時間

参照軌道は高度550km、傾斜角53度の円軌道とする。地球半径6,371km、重力定数398,600.4418km³/s²という球対称モデルでは、周期は約95.50分、軌道速度は約7.59km/sとなる。

最低仰角25度を初期比較条件とすると、衛星までの最大斜距離は約1,123km、地表の可視範囲半径は約941kmとなる。1000kmで計算した通信例は、全可視範囲の最悪条件ではない。

このモデルで地上点の真上を通る場合の、仰角25度以上の通過時間は約4.49分となる。ただし地球自転・軌道方向・観測地点を無視した幾何学的な比較値であり、実際のパス長や再訪間隔ではない。

| 設計で必要な条件 | 決めること |
| --- | --- |
| 利用地域 | 日本の特定地域、複数国、海上等の優先順位 |
| 利用場所 | 屋外、窓際、建物中央、移動中を別条件にする |
| 可用性 | 受信機会、最大待ち時間、継続接続率を定義 |
| 衛星配置 | 軌道面、位相、寿命、故障・補充機の配置 |
| 地上局 | 衛星との同時可視、雨・設備故障・回線冗長性 |
| 利用密度 | ビームごとの端末数、データ量、同時通信数 |

衛星2機で常時接続できるとはしない。利用地点と衛星配置を決め、24時間から季節変動までの可視・干渉・容量解析を行ってから、必要な衛星数を求める。53度の軌道は全世界の均一なサービスを意味しない。

初回の2機は同一投入軌道面を基準とし、位相分離の手段と所要時間を別途設計する。異なる軌道面への配置は現行の輸送・推進剤予算に含まない。

衛星が見えない間は、期限付きの受信待ち・送信待ちキューへ保存する。端末表示は「衛星接続中」「次の通信機会を待機」「受信済み」「期限切れ」を区別する。次の通信時刻の計算根拠がなければ、推定時刻を確定表示しない。

## 20 無線リンク収支・屋内受信の限界

以下は方式比較用の単一リンク概算である。2GHzは計算周波数であり、使用帯域の選定・免許・割当を意味しない。自由空間損失の式はITU-R P.525を参考とする。[S10]

Lfs[dB] = 92.45 + 20 log10(f[GHz]) + 20 log10(d[km])

f = 2GHz、斜距離d = 1000kmではLfs ≈ 158.47dB。追加伝搬・偏波等の損失を3dBと仮定する。

| パラメーター | 下り | 上り |
| --- | --- | --- |
| 送信側EIRP | 衛星20dBW | 端末23dBm = -7dBW |
| 受信側G/T | 端末 約-27dB/K | 衛星 -5dB/K |
| 端末G/Tの仮定 | 利得0dBi、雑音温度500K | 同左は上りへ使わない |
| 損失 | 自由空間158.47dB + その他3dB | 同条件 |

C/N0[dBHz] = EIRP - Lfs - Lother + G/T + 228.6

Eb/N0[dB] = C/N0 - 10 log10(Rb[bit/s])

復調に必要なEb/N0を仮に3dB、設計余裕をさらに3dBと置く。次表はこの合計6dBを差し引いた残りであり、実際の符号化方式の必要量はモデム選定後に置き換える。

| 条件 | 下り余裕 | 上り余裕 | この仮定での判定 |
| --- | --- | --- | --- |
| 屋外・10kbps | +14.1dB | +9.1dB | 両方向の成立候補 |
| 屋外・100kbps | +4.1dB | -0.9dB | 双方向100kbpsは未成立 |
| 建物損失15dB追加・10kbps | -0.9dB | -5.9dB | 両方向とも不足 |
| 建物損失15dB追加・100kbps | -10.9dB | -15.9dB | 両方向とも不足 |

15dBは感度分析の仮値である。建物侵入損失は、構造・材料・周波数・入射方向・位置で変わる。屋根、金属膜入り窓、筐体、TV、家具、人体の影響を別途測る。ITU-R P.2109も建物損失を統計的に扱っている。[S11]

この表は利用者全体の容量、干渉、ドップラー、再送、接続手順、端末回転、ビーム端を含まない。EIRPには送信アンテナ利得が含まれるため、20dBWを消費電力100Wと読み替えない。

## 21 Mini200へのアンテナ・無線機追加

Mini200 E1は使用時20cm以内の本体を目標とし、現時点でも基板・冷却・実機収納が未確定である。衛星機能を追加しても、公称外形だけで収納成立としない。[L1]

| 案 | 構成 | 主な利点と制約 |
| --- | --- | --- |
| 内蔵低速案 | 本体内モデム、RF回路、筐体内アンテナ | 外付けを減らせるが、室内受信と電磁干渉が厳しい |
| 外部受信アンテナ案 | 屋外アンテナから本体内受信機へ | 見通し改善。配線損失、保護、設置が必要 |
| 屋外通信端末案 | 屋外で無線処理しEthernet等で接続 | 広帯域の候補。外部機器・電源・設置が増える |

外付け設備は比較候補であり、ユーザーが採用を指定したものではない。内蔵案の実測結果と用途を基に決める。高速インターネットを使いたい場合、受信だけの内蔵案へ名前を付け替えて満足したことにしない。

内蔵アンテナは、上面4マイク、カメラ、主計算機、放熱器、金属シールドと干渉し得る。無線部品を空いた場所へ足す前に、アンテナの空間、筐体材質、受信雑音、送信時のカメラ・音声品質を確認する。

本体内DC負荷は参照設計80Wである。仮に衛星通信の平均追加分を5Wと置けば85W、変換効率90%で入力側は約94.44Wとなる。追加分が15Wなら95W、入力側は約105.56Wとなる。5W・15Wは部品仕様ではなく設計比較値であり、送信ピークと待機を別に扱う。

既存の120W級電源候補に収まるように見えても、温度低減、突入、外部USB、瞬間負荷を含めた採用判断にはならない。本体を20cm以内に保つため、通信追加後の閉箱・ゲーム・カメラ・音声同時試験を必須にする。

## 22 通信データ・RockstarOS統合仕様

ネットワーク層はデータを届け、アプリ層はそれを検証・表示する。受信したデータに命令文が含まれていても、ローカル権限を飛び越えて実行しない。衛星回線経由でも、既存のカメラ・音声の外部送信条件は変わらない。

| 受信データの項目 | 目的 |
| --- | --- |
| message_id / sequence | 重複の排除、欠落と順序の検出 |
| source / audience | 送信主体と受信対象の限定 |
| issued_at / expires_at | 古い通知や再送攻撃の拒否 |
| content_type / length / hash | 内容型、サイズ上限、完全性確認 |
| key_id / signature | 認証された送信元の確認と鍵更新 |
| receipt_status | 電波受信・復号・認証・保存・表示を別記録 |

この表はデータ項目の設計であり、完成プロトコルではない。署名アルゴリズム、鍵管理、符号化、パケット最大長、送信窓、再送、暗号化は採用網と合わせて固定する。受信専用案では衛星へ受領確認を返せないため、地上側に届いたと断言しない。

端末の処理優先順位は、身体入力とゲーム描画、ローカル音声処理、利用者の保存、通信同期の順とする。大容量更新は中断・再開を可能にし、ゲーム中の帯域とCPUを占有しない。通信待ちが入力の1フレームを止める実装にしない。

表示例は「衛星から通知を受信しました」「衛星が見えるまで待っています」「受信できましたが送信元を確認できません」「更新はダウンロード済み、適用待ち」とする。生の信号強度だけで利用可能なネット接続を表示しない。

## 23 通信・端末・衛星の受入試験

最初は、地上の無線試験環境と衛星回線の模擬で端末を評価する。その後に衛星実証へ進める。自前ロケットの完成を端末ソフトの試験開始条件にせず、ロケット、衛星、端末の開発を並行できる構成にする。

| ID | 試験 | 合格のための証拠 |
| --- | --- | --- |
| COM-01 | 地上模擬の下り受信 | 送信IDと受信・認証・保存・表示ログが一致 |
| COM-02 | 上り・下りの独立評価 | 両方向の誤り率・実効速度・再送・遅延を測定 |
| COM-03 | 距離・仰角・ドップラー変化 | 想定範囲と変化率で捕捉・追従・復帰する |
| COM-04 | 屋内受信 | 建物・位置・時刻・遮蔽物を固定して測る |
| COM-05 | ゲーム同時負荷 | 描画・身体入力・音声・通信の劣化を別々に記録 |
| COM-06 | 電力・熱・EMC | 送信ピークと連続動作で既存機能と限界を満たす |
| COM-07 | 通信断・再接続 | 重複実行なし、途中保存の破損なし、期限切れ拒否 |
| COM-08 | 不正・古いメッセージ | 認証・完全性・期限・対象端末の検査で拒否 |
| COM-09 | 実衛星からの受信 | 衛星・地上局・端末の時刻付き記録が照合できる |
| COM-10 | カバレッジ運用 | 利用地域で待ち時間と接続可能時間を実測 |

通信品質の受入値は、サービス段階と同時利用者数を決めてから固定する。初期の地上模擬では、例えば1kB通知1000件の完全性、重複排除、期限処理を確かめる。ただし地上試験で1000件成功しても、屋内で衛星通信できる確率の証明にはならない。

端末の既存設計にある1080p・60fpsや身体入力P95 100msは設計目標であり、衛星通信を加えた状態で達成済みとはしない。既存試験の結果を通信追加後へ無条件に引き継がない。[L1]

## 24 運用・周波数・寿命終了

衛星の利用者向け電波、地上局のフィーダーリンク、衛星管制、ロケット追跡は、それぞれ異なる用途と干渉条件を持つ。2GHzの試算から実際の送信周波数を確定せず、運用地域と採用方式に対応する割当・調整・国内手続を確認する。ITUの宇宙無線業務は国際的な周波数調整の参照先となる。[S12]

| 対象 | 運用開始までに決めること |
| --- | --- |
| 発射・再突入 | 運用国、射場、経路、追跡、安全、第三者保護 |
| 海上回収 | 回収区域、海況、作業船、立入管理、輸送 |
| 衛星通信 | 事業主体、帯域、地上局、端末送信条件、干渉管理 |
| 顧客サービス | 利用地域、待ち時間、容量、料金、障害時表示 |
| 機体再使用 | 認定寿命、交換部品、履歴、退役・再利用処理 |
| 衛星寿命終了 | 軌道離脱、衝突回避、エネルギーの安全化、監視継続 |

衛星はロケットのように回収する設計ではない。軌道で寿命まで運用し、終了時に管理された処分へ移る。推進剤の軌道保持分・衝突回避分・寿命末期分を分け、自然落下するからよいと一括判断しない。

国や運用主体が未定なので、本書は特定法域の申請適合を判定しない。規制事項は運用地が決まった段階で公式資料と責任者により更新する。これらを理由に端末ソフトや机上解析の作業を止める必要はなく、依存する運用行為のゲートとして管理する。
