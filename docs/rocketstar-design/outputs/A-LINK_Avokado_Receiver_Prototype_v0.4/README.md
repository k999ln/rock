# A-LINK / avokado 受信実証パッケージ v0.4

2026-09-22。通知の受信・回線切替・保存・再開を実行できるPython試作です。Tower20 E3の別筐体Edge Hubに通信処理を追加するための独立した検証用プログラムです。RockstarOS本線へ組込み済みのOSイメージではありません。

## 今回動かしたもの

暗号化した通知をこのPC内のHTTPサーバーから受信し、Wi-Fi・携帯・衛星を表す3つの模擬経路を切り替えました。途中で全経路を止め、復旧後に未受信分を取得し、受信器を再起動して同じ通知を再配信しても表示件数が増えないことを確認しています。

この試験は実ソケットとSQLiteを使いますが、無線の伝搬・衛星の可視・モデム・実回線の切替を再現したものではありません。試験中の切替時計は意図的に進めています。実行にかかった時間を衛星通信の遅延として使わないでください。試験件数と環境は `evidence/verification.json`、段階別の結果は `evidence/demo-results.json` にあります。

| 機能 | 今回の到達点 |
| --- | --- |
| 回線選択 | 許可された経路だけを評価。優先回線への復帰は30秒安定・60秒滞在。主経路故障時は待ちを免除 |
| 受信と復旧 | 本文・ID・ACK待ちを同じDB処理で確定。受領応答が失われても再送できる |
| 二重表示の防止 | 同じID・同じ内容を1件にまとめる。違う内容の同じIDは拒否 |
| 電源断に備えた保存 | プロセス強制終了後の再読込を検証。SSDの実電源遮断試験は別 |
| 期限と容量 | 本文4KiB、通知1000件、論理保存量10MiB、通知期限最大7日、重複記録30日。満杯は新規受信を保留 |
| 認証・通信中の保護 | AES-256-GCM。宛先・方向を結合し、HTTPでは要求ごとの乱数に応答を結合。TLSは検証を維持 |
| 使用量の歯止め | 送信試行回数の上限をDBへ保存。再起動でリセットしない。通信料金そのものの上限保証ではない |
| 衛星機器との接続 | RockBLOCK 9704公式SDK向け非同期受信コードを作成。模擬SDKで試験、実電波では未試験 |

通知は表示・保存するデータです。受信した文章から家電・決済・任意のプログラムを実行しません。ここでの一度だけの処理は「通知を重複保存しない」範囲であり、外部操作全般の一回実行保証ではありません。

## 動かす

Python 3.11以降を使用します。今回の実行環境はPython 3.12です。展開したフォルダーで実行します。

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m alink demo
.venv/bin/python -m unittest discover -s tests -v
```

demoは外部サービスへ接続せず、127.0.0.1上の3つの一時サーバーを使います。無線機・SIM・APIキーを必要としません。鍵は試験ごとにメモリー内で生成し、試験用DBは一時領域へ作成して終了時に削除します。

## 実機へ進む構成

端末側は最新のTower20 E3へ合わせ、4本の20cmタワーと別Hubを使います。旧Mini200一体箱の80Wや3眼構成を転用しません。E3の仮電力枠はHub100W＋塔4本×4W＝DC116Wで、通信追加分は別に積み上げます。

初期衛星試験は **Hub → USB → 別筐体RockBLOCK 9704 → Iridium IMT → Cloudloop** を基準にします。自前衛星やロケットが完成する前に、端末の受信を試験できる構成です。これは自前A-LINK衛星への互換性を証明しません。

メーカーは9704と他の送信機の同一筐体への共置を避ける設置条件を示しています。衛星部は空が見える場所に置き、室内のHubへデータを有線で戻します。短いUSB接続を最初のベンチ試験とし、建物への長い引込みは屋外側の受信コンピューターとEthernet等を別設計します。未検証の長いUSB線や同軸線を指定しません。[9704設置条件](https://docs.groundcontrol.com/iot/rockblock-9704/installation)

必要な機器・契約・地域・アンテナ条件は `hardware-path.md`、実機で合否を記録する条件は `acceptance-gaps.md` にまとめています。

## 地上経路の実機接続

`config.ip.example.json` を複製し、実際のLinuxインターフェース名、接続先、使用を許可した経路、送信試行上限を記入します。Wi-Fi・SIM・APN・通信契約は先に設定します。このプログラムはNetworkManagerの設定変更やSIM開通を行いません。

```sh
.venv/bin/python -m alink new-lab-key lab-key.bin
.venv/bin/python -m alink receive-ip --config config.ip.json --ticks 12
```

鍵は32バイトの試験用共通鍵で、ファイル権限0600を必要とします。配信側と同じ端末ID・鍵を使います。長期運用の鍵配布、更新、失効、TPM・OS秘密保管庫への統合は未実装です。

接続先は本パッケージの暗号化プロトコルを実装した試験サービスである必要があります。一般のWebサイトやCloudloopのAPI URLを直接入れても動きません。`alink/fixture.py` はAPIの実行例ですが、単一端末向けローカル試験用で、公開サービスではありません。配信側の本番DB・ユーザー隔離・API認証・監視・再送運用は追加実装が必要です。

実機モードはHTTPSに限定し、Linuxの指定インターフェースへソケットを固定します。必要なOS権限やインターフェースがなければ送信を失敗させ、別の既定経路へ黙って流しません。今回のMac上で、このLinux経路固定を実回線試験したとは扱いません。DNS解決、回線の起動、SIM登録はOS側の設定に依存します。

## 衛星機器の試験用接続

機器・契約・試験地が揃った後、別環境へ任意のSDKを入れます。通常のdemoと試験には不要です。

```sh
.venv/bin/python -m pip install -r requirements-radio.txt
.venv/bin/python -m alink radio --config config.radio.json
```

`config.radio.example.json` の `radio_approved` は初期falseです。実機のシリアルポート、契約で与えられたTopic、端末ID・鍵、送信試行上限を設定します。Topicの値を別契約から流用しません。

SDKは専用プロセスの単一スレッドで所有し、10ms間隔を目標にpollします。受信保存は別の処理スレッドで行い、DBへの保存後にだけSDKの受信キューを解放します。ACKを無線機へ渡しただけではDBのACK待ちを消しません。配信側から認証済みの確認が戻ったときに確定します。メーカーが示すpoll間隔を守れなかった場合は診断状態へ記録します。[公式SDK](https://github.com/rock7/RockBLOCK-9704)

radioと地上受信器を同じ端末ID・鍵・state_dirで動かすと、通知の重複判定とACK待ちを共有します。ただし現版のradioは受信を取りこぼさないよう独立して常時処理します。配信サーバーが地上回線の状態を見て衛星への配信を抑制する運用は未実装です。ソフトの3経路模擬試験を、この実機構成全体の自動切替受入済みという意味にしません。

### 衛星用パケットの往復試験

配信する1件を次の4項目で `record.json` に保存します。idは再送時に変更せず、時刻はUTCのUnix秒、expires_atはcreated_atより後で最大7日です。本文はUTF-8で4KiB以内です。

```json
{"id":"bench-notice-001","created_at":1790110000,"expires_at":1790196400,"payload":"avokadoへの試験通知"}
```

時刻は試験当日の値へ置き換えます。古い例をそのまま使うと、正しく期限切れ扱いになります。

```sh
.venv/bin/python -m alink make-delivery --record record.json --device avokado-lab-01 --key lab-key.bin --output downlink.packet
```

生成した暗号化パケットをCloudloopの契約済みThing/Topicへ送るのは、事業者の管理画面またはAPIを使う実機試験担当者です。このコマンド自体は外部送信しません。CloudloopのBase64 payloadには `downlink.packet` の全バイトを符号化して渡します。機器の輸送完了とHubアプリへの保存完了は別です。

Hubから返ったアプリACKを事業者側で取得してBase64から元バイトへ戻し、`receipt.packet` として保存します。元の通知との一致を確認して、確認パケットを生成できます。

```sh
.venv/bin/python -m alink confirm-receipt --receipt receipt.packet --record record.json --device avokado-lab-01 --key lab-key.bin --output confirm.packet
```

確認パケットも同じ端末へ送ります。手動往復をまず成立させてから、配信サーバーの永続キュー・Cloudloop認証・再配信・確認処理を自動化します。実契約のAPI呼出しと課金は今回実行していません。

## 保存・運用上の境界

SQLiteは保存時暗号化を実装していません。Hubのストレージ暗号化と秘密保管の統合が必要です。10MiBは通知・メタデータ・ACKの論理量で、SQLiteページやWALを含むディスク使用量の上限ではありません。暗号化パケットは最大8192バイト、1回の本文は最大1件です。

衛星アプリACKは最低30秒間隔、送信中は1件までに制限します。起動をまたぐ試行上限も持ちますが、モデム内部再送や実際の請求額を制限するものではありません。事業者の契約上限も必要です。`budget_epoch` は試験単位の識別子で、変えると別枠になるため、自動的な上限解除には使いません。

資格エラーは接続成功として扱わず理由を診断へ出します。現版は再評価を続けるため、資格情報の失効通知・更新時だけ解除する管理画面は追加実装です。ブラウザーのログイン画面を自動承認しません。

地上の通知受信器とradioの状態をRockstarOSの画面へ統合する部分、サービスの配信制御、端末登録、初回起動、自動サービス起動、量産機の鍵・更新は未統合です。本試作を完成OSへ読み替えないでください。

## 宇宙機側の要求

自前衛星2機は通信実証用、ロケットは両段回収・再使用という要件を保持します。今回の試作は、それらの完成を待たずに端末側を検証するための経路です。自前衛星の無線設計、全球常時サービス、ロケットの推進・構造・再突入・着陸・再飛行は未実証です。

完全に遮蔽され、外へつながる有線経路もない場所では、新しい通知は受信できません。その場所には屋外受信部からの有線引込みを追加する必要があります。「どこでも」はこの設置条件を含めて定義し直す必要があります。
