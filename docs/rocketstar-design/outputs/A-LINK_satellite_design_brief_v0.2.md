# A-LINK 衛星・avokado通信の設計方針

2026-09-21 / v0.2 / 通信要件を優先した改訂

## 最上位の製品目標

ユーザーの希望は「avokadoの電源がつけば、どこでも受信可能」。衛星の見た目より、端末で受信できることを優先する。電源投入後に機器が自動で接続を探し、利用者がアンテナの向きや接続操作を意識しない体験を目指す。

この希望は要求として記録するが、達成済みの仕様とはしない。「どこでも」が地球上の任意地点・任意建物・地下・金属遮蔽を含む場合、衛星への無線経路が存在しない場所があるため、衛星単独での無条件保証はできない。電源供給は受信機を動かす条件であって、電波が届くことの保証ではない。

## 確定した意図と提案を分ける

確定したユーザーの意図は、小型通信衛星の打上げ、ロケット両段の回収・再使用、衛星からavokadoへ電波を届けること、電源投入だけで場所を意識せず受信したいという体験である。

設計上の提案は、衛星直通、携帯回線、既に利用許可されたWi-Fiを自動選択する通信機能である。地上回線の併用は追加提案であり、ユーザーが採用を指定した構成ではない。通信量、契約、利用地域、認証方法を確認して確定する。閉じたWi-Fiへの無断接続や、追加契約が不要という前提は置かない。

## 実際の受信経路

空が見える場所では、地上ゲートウェイ→衛星→avokadoの内蔵衛星アンテナ・モデムという直接受信経路を目指す。衛星は配信側のネットワークと接続する必要がある。継続サービスでは地上局の可視と衛星側の中継・保存方式も含めて設計する。

屋内では建物による電波損失が加わる。衛星直通で受信できる場所とできない場所を実測で分け、提案する地上回線の併用案では携帯回線や許可済みWi-Fiへ切り替える。地上回線経由のデータを「衛星から直接受信した」と表示しない。

地下や強い遮蔽などで全経路が届かない場合は、その時点の受信はできない。端末は受信待ちを表示し、ローカル機能を継続し、接続回復後に同期する。待機と受信成功を同じ状態として扱わない。

## 衛星の形を決める順序

1. avokado側の内蔵アンテナの受信性能、取り付け方向、筐体損失を測る。
2. 必要な通信量、利用地域、最大待ち時間、最低仰角を定義する。
3. 周波数、衛星までの距離、建物・人体・家具の損失、干渉を通信収支へ入れる。
4. 衛星の送信電力、アンテナ開口、指向範囲・追尾、放熱と発電を同時に決める。
5. そのアンテナを収納・展開できる本体、太陽電池、推進系の形へ落とし込む。

前版Bの「地球向きの広い通信面」を、配置検討の暫定候補にする。電子的に電波の向きを変えるアンテナを検討できるが、機構・電力・熱・干渉まで含めて成立するかは未判定である。前版Cの展開反射鏡との比較も残す。

大きなアンテナにすれば無条件にどこでも届く、という設計にはしない。利得を高めると通信余裕を改善できる一方、指向範囲・追尾・利用者へのビーム配分が重要になる。外観だけでBとCの優劣は決まらない。[NASAの通信設計資料](https://www.nasa.gov/smallsat-institute/sst-soa/soa-communications/)

## 既存の仮予算を見直す

統合基本設計の衛星1機500kg・定常1kW・高度550km・初回2機は、今回の「どこでも」を満たした設計ではない。2機で常時通信できるとはせず、必要な衛星数と軌道配置を、利用地域・連続性・故障・補充の条件から求め直す。

20cm版Mini200も、既存の主計算機・3カメラ・4マイクに衛星モデム等を追加するため、収納、電源、発熱、受信雑音の再設計が必要である。衛星通信に対応したアンテナとモデムを備えず、OS更新だけで直接受信できるとはしない。

通知などの受信だけか、返信・Web・音声・動画まで必要かは未確定。インターネットには上りも必要なため、下り受信の成功だけで双方向ネットを保証しない。

前版のA/B/C画像は外観比較用のAI生成図であり、無線・収納・展開を検証した図面ではない。本改訂は通信を優先した設計方針を定義するもので、新しい実機試験の成果は含まない。
