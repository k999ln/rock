# Skyの役割エージェント仕様 — 2026-09-12

## 判断

Skyの自動化Hubは、ツール一覧を中心にするだけでなく、役割を持つ担当エージェントと会話して仕事を進める「Agent Hub」へ段階的に移行する。利用者は専門ツール名を覚えなくても、相談内容から適切な担当へつながり、担当が許可されたMCPだけを使う。

今回の「サブスク顧問」が最初の実装例である。ローカル台帳へ接続すると、質問例または自由入力から、全網羅状況、過去の契約、月額、要対応、次の更新、全体状況を会話形式で確認できる。回答はPC内の台帳だけから組み立て、外部LLMへ契約データを送らない。情報源または更新日の不足が残る間は全網羅と回答しない。

## Sky共通の会話契約

各担当は次の項目を持つ。

| 項目 | 意味 |
| --- | --- |
| role | 担当名と利用者に対する責任 |
| objective | 何を完了状態とするか |
| tools | 使用を許可するMCP toolのallowlist |
| dataScope | 読み取れる保存領域と外部送信可否 |
| approval | 支払い、送信、公開、削除など本人確認が必要な操作 |
| memory | 会話中だけ、端末内、アカウント保存のいずれか |
| receipt | 参照データ、実行tool、結果、未完了理由の記録 |

会話は原則として次の順序で進める。

1. 相談を理解し、使う担当とデータ範囲を示す。
2. 読み取り専用toolで状況を確認する。
3. 結果と根拠を会話で返す。
4. 外部変更が必要なら、対象と結果をプレビューして本人確認を求める。
5. 許可された操作だけを1回実行し、receiptを残す。

## 担当の構成案

- サブスク顧問: 契約、定期課金、更新、支払い失敗を確認する。現行は読み取り専用。
- 営業担当: 案件条件と応募可否を確認する。応募送信は本人確認。
- 編集担当: 記事の無料版、出典整理、納品前照合を行う。
- 特許出願担当: 発明を整理し、公式特許情報の候補調査と出願書類ドラフトを作る。特許性を保証せず、AI送信は明示同意、提出は本人確認。
- Wallet担当: 認証済み収益、実行費用、留保を説明する。送金は本人確認。
- Sky受付: 相談を分類し、1担当または複数担当の順序を提案する。無断実行しない。

## 実装境界

今回のWeb試作はローカルSkyからRockstar LedgerのHTTP read APIへ接続する。Rockstar Ledger自体はstdio MCPでも同じ台帳を提供する。次段階ではNative SkyのMCP brokerを共通policy gatewayにし、担当ごとのtool allowlist、確認要求、receipt、再起動後の継続を統一する。

自由会話へ外部モデルを使う場合は、送信データのプレビュー、秘匿項目の除去、利用者の明示許可を必須とする。モデルは権限を持たず、実操作は常にSkyのpolicy gatewayが判定する。
