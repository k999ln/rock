## 2026-10-14 追加決定 — 話せる相棒

利用者は参考のESP32 ballから、ランドセルに**ぶら下げられ、ワンタッチで外して手で持ち、話せる相棒**を明示した。防犯はその機能の一つである。黒い鏡面・二つの目・手のひらサイズの画像は外観参考であり、筐体寸法・防水・電池・音響の実証ではない。名称候補は`avocado Companion`（仮称）。正式名、商標調査、販売名はOWNERが別に確定する。

上部の短い交換可能なストラップと一手で外せる金具で、ランドセルのDリング等へ吊るす。硬い背面マウントを前提にしない。引掛り・脱落・首への巻付き・外した際の紛失はMAT16/MAT17で検証する。**SOS入力とローカル警報は取り外す本体側に置く**。外した後にも警報が使える。下部の引き手と側面の握り操作は候補であり、一動作性と誤作動を試して決める。

### できることと実装段階

| 体験 | V0で作り測る内容 | 後続候補・受入条件 |
| --- | --- | --- |
| 身に着ける／外す | ランドセル等に吊るし、片手で外して持つ。装着位置を変えてもSOS操作を妨げない | 掛け具互換と保持力を代表ランドセル・衣服で測る |
| 話す | 明示操作からマイクを開き、保護者のスマホまたはWi-Fiを経由してRockstarOSの許可済みCloud Agentへ送る。返答をスピーカーで聞く | 常時呼びかけ、直接eSIM通信、家族との通話は電池・学校利用・同意・費用・接続の別受入後 |
| 相棒の反応 | 二つの低消費電力の目で待機、聞き取り、応答、通信不可、電池低下を区別。振動でも知らせる | 子供が文字なしで意味を理解できるかを実測する |
| SOS | 本体の物理操作から、AI、network、accountに依存せず現地で鳴らす。接続時だけ保護者への通知を試みる | 緊急位置の一回共有、単独回線、自動通報は別設計・別同意・別受入 |
| 日常の助け | 会話経由で質問、学習のヒント、予定の確認、家族への連絡依頼を行う | 個人別データ、外部送信、第三者Tool操作は各能力と保護者設定が受入済みの範囲だけ |

V0は**スマホ中継またはWi-Fi接続がある場所での会話実証**を目標とする。子供がスマホを持たない通学中には、この構成だけで会話できない。携行品としての販売版は、単独データ通信を受け入れるか、会話可能な場所を限定して明示する必要がある。圏外では会話と通知の成功を表示しない。常時録音、カメラ、連続位置追跡、子供による購入／外部Toolの包括承認をV0に入れない。AIの返答は権限判断やSOS成功の証拠にならない。

### 能力候補 — 毎日使いたくなる相棒として

以下は2026-10-14の「何ができるかもっと考えて」に対する**製品提案**。利用者が各機能を確定した記録ではない。実装可能性、子供の使いやすさ、保護者の同意を見て採否を決める。

| 場面 | 子供がすること／端末が返すこと | 依存・失敗時の表示 | 優先度 |
| --- | --- | --- | --- |
| 聞く・考える | 本体を持って押しながら質問。短い音声で答え、必要なら「一緒に考えよう」と一問ずつ進める。分からない時は分からないと伝える | Agent接続が必要。圏外では一般知識の回答を作らない | 最初の会話体験 |
| 遊ぶ | なぞなぞ、しりとり、短い物語、気分転換の呼吸などを選ぶ | 事前収録の短い遊びだけならオフライン候補。無限会話を約束しない | 早期候補 |
| 今日を確かめる | 「帰る時間は？」「持ち物は？」に、保護者が設定した予定だけを返す。変更は保護者へ照会する | 端末へ最小限の予定cacheがある場合だけオフライン表示可。予定が古ければ明示 | 早期候補 |
| 家族に伝える | 「迎えに来て」「着いたよ」などを事前登録した相手へ送る。送信内容を子供に読み返してから送信する | 接続と保護者が設定した宛先が必要。送信待ち・到達確認・失敗を区別 | connected版候補 |
| 困った時 | 「道が分からない」「助けて」に対し、立ち止まる、近くの信頼できる大人へ声をかける等の短い案内を出す。SOSは物理操作で即時作動 | 案内は一部を端末内に固定可能。位置・通報・迎えの到着を推測しない | 安全試験候補 |
| 緊急時 | 引く／握る一動作で会話を中断して警報を鳴らす。通信があれば登録先へ別eventを送る | local alarmを先に作動。保護者への通知成功はreceiptがある時だけ表示 | 最優先 |
| 帰宅後 | dockに置くと充電と自己診断を行い、電池・警報・接続の状態を保護者へ示す | 故障や警報reserve不足を隠して「ready」と表示しない | 早期候補 |

会話の記憶は最初はその会話session内だけ。後から好みや予定を覚えるなら、保護者が許可した項目と保持期間を選び、子供にも削除できることを説明する。端末に「内緒にしよう」と促す人格、子供に課金を決めさせる操作、無断で第三者へ連絡する機能は採らない。回答と外部行動は別権限にする。

### 商品にするための決定的な検証

V0の中継会話は音声体験を測る開発段階である。子供がスマホを持たず毎日使う商品として成立させるには、独立通信付き試作機で通学路・建物内の接続、会話遅延、騒音下の聞き取り、警報音量、電池一日分とSOS reserve、月間データ量と家庭の費用上限を**同一筐体**で測る。無線方式は音声品質、回線提供、消費電力、アンテナと筐体の実測で比較して決める。GPS、常時位置、家族通話をこの受入から自動的に追加しない。

### Pixel限定エージェント V0.3（同日）

利用者の「中のエージェントを動かす」指示により、[端末内の限定実行器](../public/companion-preview/agent.js)をPocket Consoleへ接続した。明示起動後だけ入力を受け、しりとりの次音・使用済み語、伝言の未送信下書きをブラウザのメモリに保持し、安全相談を遊びより優先する。学校モードでは通常会話を止め、SOS試験開始・会話停止・画面破棄時に実行器を停止する。入力は文字列と現在モード・圏外再現、出力は分類、有限の処理step、表示・読み上げ用返答である。権限はページ内の状態更新に限り、保存、network、保護者通知、位置取得、任意Tool実行はない。未対応質問は未対応と返し、LLMの回答を装わない。Pixel 10 Vanadiumで起動表示と入力→未対応返答を確認した。4件の状態試験は`node --test tests/companion-agent.test.cjs`で合格。これはルール型の限定Agentで、Qwen等のローカルLLMもCloud Agentも起動していない。

## 1. 確定した要求と、まだ確定していないこと

利用者の明示要求は、**avocadoのRockstarOS系hardwareとして、防犯ベル程度の大きさでランドセルに吊り下げ、外して手で持って話せる相棒を開発する**ことである。これはRQ48の専用端末profileとして扱い、RQ01〜RQ49を維持する。

次はまだ確定していない。

- 一般販売時に防犯ブザー規格の製品として申請するか
- 正式製品名、対象年齢、販売国、学校配布の有無
- 最終寸法、重量、色、価格、販売・通信契約
- GPS、cellular/eSIM、単独通信、常時呼びかけの採否
- 保護者通知、位置共有、家族通話、会話履歴をどこまで提供するか

そのためP0は、外形・会話・安全構造を検証する**吊り下げ型companion profile**とする。防犯ブザーを名乗って販売する場合は、鳴動性能と公的試験を別gateで受け入れる。

## 2. 製品体系での位置

この端末は、使用時200mm以内・空間表示を目指す[avocadoMini R5](avocado-mini-r5/README.md)の縮小版ではない。R5の表示、3D入力、Material Invention受入を引き継がず、R5も本端末の完成待ちにしない。

本端末へLinux／Androidのfull RockstarOSをそのまま載せることをP0要件にしない。小型MCUの署名済みfirmwareをRockstarOS Platform Coreへ接続する限定Device Profileとし、重いAI・Sky・Zemaは保護者の既存端末またはcloudで使う。物理SIM/eSIMの購入、RockstarOS service entitlement、端末の無線契約、保護者通知は別状態で追跡する。

## 3. P0の目的と利用者体験

目的は、子供が毎日持てる会話の相棒を作り、通信不能時にも一動作で周囲へ危険を知らせ、保護者が故障・電池・設定を確認できるhardware基盤を作ることである。

1. 保護者が端末IDとhardware keyを自分のRockstar accountへ結ぶ。子供の実名を筐体へ表示しない。
2. 子供が手の届くランドセルDリング等へ短い連結具で吊るす。長い閉ループ紐や鋭い突起を使わない。外して手に持って話せる。
3. 引き手または大型操作部の一動作で、network、cloud、account、RockstarOS appの状態に関係なくローカル警報を開始する。
4. 接続profileを採用した版だけが、保護者の事前設定に従い、警報eventを送る。送信失敗でもローカル警報を止めない。
5. 停止方法は誤操作を増やさず、子供本人と保護者が練習できる。停止と通知取消を同じ処理にしない。
6. 子供は明示操作で会話を始め、接続とマイク動作が目・振動で分かる。接続不能時は会話ができないと伝え、SOSのローカル動作は維持する。
7. 保護者は月次self-test、電池低下、最後の成功試験、firmware版、失効状態を確認する。

P0は「子供を必ず守る」「常に居場所が分かる」「警察・学校へ自動通報する」と表示しない。警報、通知、位置、通話はそれぞれ別能力として受け入れる。

## 4. 外形・機構の初期engineering envelope

「防犯ベルサイズ」を架空の単一寸法へ固定しない。P0の設計目標を次の通り置き、市販の優良防犯ブザー候補3機種以上を実測してP1 envelopeを決める。

| 項目 | P0設計目標 | 合格方法 |
| --- | --- | --- |
| 本体包絡 | 70 × 45 × 25 mm以内。取付具と引き手を除く | 3軸実測。部品突出を別記 |
| 質量 | 電池・取付具込み80 g以下 | 校正済み秤で3台測定 |
| 角・開口 | 外部に鋭い突起を作らず、指や衣服を挟む開口を避ける | inspection、引掛りfixture、落下後再検査 |
| 操作 | 手袋なしの片手一動作で警報開始。通常動作で簡単に外れない | 年齢・同意を管理したhuman factors試験 |
| 取付 | Dリング等へ短い連結具で吊るし、子供が片手で外せる。長い閉ループ紐を作らない | 代表ランドセルfixtureで歩行・着脱・引掛り・脱落試験 |
| 耐環境 | 通学時の雨、汗、粉じん、落下後も安全側へ遷移 | 等級をP1で確定し、同一筐体で公的／第三者試験 |

70 × 45 × 25 mmと80 gは製造確定値ではなく、最初のmockupを比較するための上限である。実測benchmark、音響容積、電池安全、取付安全が両立しない場合はOWNERが変更理由と比較証拠を記録して更新する。

## 5. hardware block

```text
本体の引き手／握り操作 ── 独立alarm latch ── siren driver ── sounder
          │                    │
          └──── low-power MCU ─┼─ eyes LED / haptic
                               ├─ secure hardware key
                               ├─ battery gauge / self-test
                               ├─ mic / speaker / bounded voice session
                               └─ BLE guardian relay / Wi-Fi候補
                                      └─ cellular/eSIM + GNSS候補（後続・未決）
```

| block | P0責任 | 禁止・保留 |
| --- | --- | --- |
| 独立alarm path | MCU crash、未登録、圏外でも警報を開始・継続する | cloud応答を待って鳴らす構成にしない |
| MCU | 入力debounce、状態、self-test、署名event、電池監視 | 任意shell、生成AI、Wallet、外部Tool実行を入れない |
| secure key | device identityとevent署名。鍵を外へ出さない | 端末鍵を子供本人性や保護者権限そのものにしない |
| radio | 保護者スマホ中継／Wi-Fiで同意済み会話sessionと最小alarm eventを扱う | 未認証無線、常時追跡、常時周辺音声送信を既定にしない |
| voice | 明示操作中だけマイクを開き、送信中を表示する。応答をspeakerで返す | AIの応答を安全判断、保護者承認、Tool成功に昇格しない |
| sensor | tamper、姿勢、取付状態は候補 | cameraと常時microphoneはP0から除外 |
| power | 一次電池と保護回路付き充電池を比較する | button形アルカリ電池を基準案にしない。PSE該当性を推測しない |

電池方式、sounder、radio、secure element、MCUの型番は未選定。P0では二つ以上の電源案について、警報中の電圧降下、待機日数、低温、短絡、誤充電、交換時の誤飲・工具要否をbench比較してから決める。

利用者が示したEbeaconの小型丸画面等は参考とする。最新の明示方向は**二つの目だけを持つ吊り下げ型の会話companion**である。全面displayは必須とせず、低消費電力の目表示と音声を同じ包絡と電池で比較する。

| 比較案 | 構成 | この案で確かめること |
| --- | --- | --- |
| P0-A safety reference | alarm、状態LED、haptic、2操作部、低消費電力MCU | 警報reserve、単純操作、電池下限を測る比較対象 |
| P0-B companion（主案） | P0-Aの独立alarm＋目表示、マイク、スピーカー、BLE／Wi-Fi、着脱金具、service dock候補 | 会話の聞き取り・返答、装着中と手持ちの音響、学校の一日と警報reserveを両立できるか |

P0-Bの目表示は`待機`、`聞き取り中`、`返答中`、`接続不可`、`要点検`、`電池低下`、`保護者通知待ち`、`通知receipt確認済み`を視覚と触覚で区別する。二つの目だけで区別しにくい場合は音・振動・保護者画面を補う。子供の端末操作で購入、位置共有、任意Tool、将来の許可を包括承認させない。Ebeacon投稿の電池3〜4時間という自己報告は本端末の合格値ではない。

据置製品の有線化を推す利用者提示資料は、**家庭側service dockを有線電源・有線診断へ寄せる判断**に使う。通学中の本体を線でつながない。dockから外した端末は警報reserveを自己診断し、不足時は`ready`にしない。PoEは住宅設備候補であり、P0本体や一般家庭の必須条件にしない。

## 6. RockstarOS Device Profile

最小capabilityは次に限定する。

- `device.self_test`
- `alarm.local.trigger`
- `alarm.local.stop`
- `guardian.notification.request`（connected版のみ）
- `companion.voice.session.start`／`stop`（明示操作・保護者設定・接続時のみ）
- `companion.voice.reply.play`（受信済み応答のみ）
- `device.status.read`
- `device.firmware.update`（保護者操作、署名、rollback付き）

`device.location.once`、家族との実通話、学校連携はP0 capabilityへ含めない。必要性、法域、保護者と子供への説明、保存期間、送信先、圏外復旧を決めた後の別版で追加する。端末の物理操作は、Sky Agent実行、料金承認、Wallet送金、位置共有の包括承認にならない。

## 7. 状態、保存、失敗、復旧

主状態は`unprovisioned`、`guardian_bound`、`ready`、`voice_connecting`、`voice_active`、`voice_unavailable`、`alarm_local`、`notification_pending`、`attention_required`、`lost_or_revoked`とする。`alarm_local`は会話・provisioning状態より優先し、会話を停止しても通知失敗時も警報を継続する。

端末へ保存するのはdevice key、firmware版、保護者bindingのopaque ID、最小設定、self-test時刻、電池状態、単調event counterである。子供の氏名、学校名、住所、会話、写真、連続位置履歴をP0端末へ保存しない。base P0は位置情報を取得しない。会話音声は明示session中の処理に限り、端末では永続保存しない。cloud側の一時処理、履歴、保存期間、削除、Providerへの送信は採用Providerの契約と保護者同意で個別に決め、未確定なら保存・学習利用を既定で無効とする。

- 電池低下: 警報に必要なreserveを下回る前に`attention_required`。通常通知よりローカル表示を優先する。
- radio断: event IDを一回だけqueueし、同じeventを新しい事件として再送しない。ローカル警報は継続する。
- voice接続断: sessionを閉じてマイクを止め、目・振動で接続不可を伝える。未送信音声を後から自動再送しない。AI応答なしを回答済みと表示しない。
- 着脱・紛失: 金具を外しても本体のSOSが使える。金具の破断、紛失、第三者所持を試験し、保護者がbindingと音声接続権を失効できるようにする。失効はローカル警報を無効にしない。
- firmware不整合: 直前の検証済みslotへrollback。alarm pathはupdateから独立する。
- 紛失: 保護者がbindingと接続権を失効する。失効をローカル警報の無効化に使わない。
- 保護者端末交換: recovery codeまたは既存Rockstar accountの再認証で再bindし、古い接続sessionを失効する。
- 結果不明: 「通知済み」と表示せず、ローカル鳴動とserver receiptを別表示する。

## 10. 現行資料から確認した外部条件

- 全国防犯協会連合会は、子供が携帯する防犯ブザーについて、確実な作動、受傷のおそれのない外形、適切な重量・形状、公的機関等の試験成績を含む推奨制度を運用している。P0はこの制度の推奨取得済みではない。[優良防犯ブザー](https://www.bohan.or.jp/suishou/)
- 経済産業省は、一定のリチウムイオン蓄電池を電気用品安全法の対象としており、完成品への組込み方や輸入・販売形態で扱いが変わる。最終電源と商流を決めて該当性を確認する。[対象非対象解釈例](https://www.meti.go.jp/policy/consumer/seian/denan/subject01.html)
- 個人情報保護委員会の通則ガイドラインでは、位置情報は蓄積・他情報との結合により個人情報になり得る。P0は位置を取得せず、将来版は目的、送信先、保持、開示・削除を先に設計する。[個人情報保護法ガイドライン（通則編）](https://www.ppc.go.jp/personalinfo/legal/guidelines_tsusoku/)

これは2026-10-14時点の設計確認であり、法的助言や認証結果ではない。販売国と部品が決まった時点で最新版を再確認する。
