# GX01 UI / Platform boundary — implementation contract

Work in progress; this file fixes the interface for parallel UI work, not a PASS claim. Public synthetic Wallet -> Game only. Root owns Platform forwarding and C UI; D owns protocol, Wallet facade, authenticator, profile and host sandbox. Candidate integration target: 08:45 UTC.

## Transport and permissions

Platform UID1002 sends the following operations to the existing Wallet Unix IPC service. The dedicated `development-game-authority` Wallet facade uses one pinned v3 authenticated TLS owner transport for both ordinary Wallet operations and Game, so both screens see the same contract's AVAILABLE. No author signing key/server module is installed on the device. Existing local-development profile remains available. New profile is explicit/fresh, not an automatic conversion of existing local userdata.

The new owner wire validator is `game_exchange.exchange_protocol.request(value)` for `game.exchange.*` (returns the validated object). GX00 existing `game_exchange.protocol.validate_owner_request` covers `game.connection.*`. For UI convenience the device facade also accepts `game.sandbox.catalog` and `game.sandbox.connection.begin` described below; these are public-fixture-only translation operations.

Every success is `{ok:true,result:...}`. A received policy/authentication rejection is `{ok:false,code:'rejected'|'unauthorized',error:<bounded text>}`. Transport loss is unavailable/unknown; preserve the request and retry its exact key/bytes. A typed `DENIED` approval is a durable successful protocol response with `result.decision='DENIED'`, not a communication error.

## Connection before purchase

1. `game.sandbox.catalog`: `{v:1,op:'game.sandbox.catalog'}` returns `{schema:'rock-game-sandbox-catalog/1',games:[{game_id,game_name,player_id,connection_id:null|UUID,current_state:'NOT_CONNECTED'|'AWAITING_OWNER_CONSENT'|'ACTIVE'|'REVOKED',simulation_only:true}],simulation_only:true}`. Exactly Public Game A/B; authenticated/current state, no author secret.
2. `game.sandbox.connection.begin`: `{v:1,op:'game.sandbox.connection.begin',key,game_id}` uses the configured player's authenticated public session to obtain a real Game TLS proof and then sends persisted GX00 begin. Result is existing `rock-game-connection-intent/1`, with `binding`, `challenge_id`, `binding_sha256`, `options`.
3. UI sends directly to authenticator UID1004: `{v:1,op:'auth.game.connect',key:<ceremony-key>,intent:<entire connection intent>,pin:'0000'}`. Fresh user PIN entry remains required. Result `{ok:true,credential,metadata}`.
4. Platform forwards `{v:1,op:'game.connection.approve',key,intent_id:<intent.binding.intent_id>,challenge_id,binding_sha256,credential}`. Existing consent receipt returned. Status is `{v:1,op:'game.connection.status',connection_id}`. Connection-only consent is not an exchange permission.

## Purchase ceremony

1. Quote: `{v:1,op:'game.exchange.quote',key,connection_id,exchange_id,principal_minor:100}`. `exchange_id` is a new bounded opaque identifier for a new user purchase, and must remain the same on retry. Reply is signed `rock-game-exchange-quote/1` with `binding`, `binding_sha256`, private `owner_ref/account_id`, signature fields and `simulation_only:true`.
2. Quote binding contains `quote_id`, `game_id`, `player_id`, `destination_asset` (`COIN_A`/`COIN_B`), `principal_minor:100`, `game_fee_minor:3`, `external_cost_minor:0`, `total_minor:103`, `units:10`, `source_asset:'synthetic:usd'`, scales2/0, `asset_class:'PURCHASED'`, `issued_at`, `expires_at` (at most120sec), fixed policy/terms. Display principal, game fee, total and received units separately with an explicit synthetic label. These are fixture values, not commercial rates; ATM fee0 and monthly888 are unchanged.
3. Begin explicit approval: `{v:1,op:'game.exchange.approval.begin',key,quote_id}`. Reply is `rock-game-exchange-approval-intent/1` with `attempt_id`, entire signed `quote`, `quote_sha256`, authenticated `device_ref/device_credential_revision`, `credential_id`, timestamps and `options.purpose:'wallet.game.exchange'`.
4. UI sends directly to authenticator: `{v:1,op:'auth.game.exchange',key:<ceremony-key>,intent:<entire approval intent>,pin:'0000'}`. Reply `{ok:true,credential,metadata}`. ATM/connect ceremonies reject these options. The PIN/signing key never travels through Platform, Wallet or network.
5. Approve: `{v:1,op:'game.exchange.approve',key,attempt_id,quote_sha256,credential}`. Reply is signed `rock-game-exchange-approval-receipt/1`: `decision:'APPROVED'|'DENIED'`, `reason:null|'INSUFFICIENT_FUNDS'|'QUOTE_EXPIRED'|'QUOTE_SUPERSEDED'|'CONNECTION_INACTIVE'`, `quote_id`, `attempt_id`, `hold_id/outbox_id` (UUID or bothnull), `sign_count`, `committed_at`, digest fields, signature, synthetic marker. APPROVED means held/queued, not granted; poll status. DENIED consumes the verified counter/challenge, reserves0, and exact retry always returns the same denial.

## Current state, history and recovery

- Status: `{v:1,op:'game.exchange.status',connection_id,exchange_id}` → `{schema:'rock-game-exchange-state/1',id:<internal UUID>,connection_id,exchange_id,quote:<full quote>,state,held_minor,committed_minor,released_minor,approval:<approval receipt>,terminal_receipt:null|<signed Game receipt>,simulation_only:true}`.
- List: `{v:1,op:'game.exchange.list',limit:10,after:null|<last internal UUID>}` → `{schema:'rock-game-exchange-list/1',items:[<state>...],next_after:null|UUID,simulation_only:true}`. Up to50. Display bounded recent rows; no automatic re-purchase for a missing row.
- States: `QUEUED` (held before dispatch), `CONFIRMING` (may have reached Game), `REVIEW_REQUIRED` (unverified/unknown receipt), `COMPLETED` (signed APPLIED receipt and Wallet consumption), `REVERSED` (signed REJECTED receipt and hold released), `CANCELLED` (atomically canceled before any possible dispatch).
- Cancel: `{v:1,op:'game.exchange.cancel',key,connection_id,exchange_id}` returns current state. Before claim it can atomically cancel; after possible dispatch it requests conditional reject and remains CONFIRMING until a terminal receipt. APPLIED wins if the Game already granted; it then displays COMPLETED. A click is not a refund.
- Reconcile: `{v:1,op:'game.exchange.reconcile',key,connection_id,exchange_id}` schedules same exchange/status request and returns current state. Never create a replacement exchange ID for unknown outcomes. NOT_FOUND/timeout/expired quote never release an existing hold.

`game.exchange.status/list` are safe read polls (each is a fresh authenticated server projection). The facade persists mutating requests before sending. A disabled/unconfigured game service returns unavailable without preventing Hub/local results or normal shutdown. Profile/backup must preserve both the ordinary backend cache and private Game pending journal.
