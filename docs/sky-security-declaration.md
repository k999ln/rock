# Sky: Stripeセキュリティ申告との対応

2026-10-01。フォームの選択は実施証拠と一致させる。画像のチェック状態は実装の証拠ではない。

## 実装済みのアプリ対策

- CSV更新APIは認証コンテキストを要求し、同一originを確認する。
- CSV履歴・成果物・決済は所有者で分離する。
- CSV見積作成は所有者ごと毎分10回、決済開始・確認は毎分20回。D1の永続カウンターを原子的に更新し、超過は429とRetry-Afterを返す。認証後、本文解析やStripeへの問い合わせ前に適用する。外部ログイン試行の制限ではない。
- 決済金額をサーバーで固定し、Stripeの入金状態・金額・通貨・関連IDを検証する。Webhookは署名を検証する。
- API制限の記録はユーザー識別子、固定の操作名、直近の窓と回数のみ。IPや端末指紋を新規収集しない。利用者ごとの行は残るため保存期間の運用は別途必要。

## 申告項目の確認状況

| 項目 | 状況 |
| --- | --- |
| 不審IP制限 | 未確認。入口のWAFなどで実際のルールと運用を確認する必要がある |
| ログインMFA | 未確認。認証基盤の適用条件を確認する。カードの3DSとは別 |
| 登録時の個人情報確認 | 未確認。認証メールの存在だけで本人確認としない |
| ログイン試行制限 | 未確認。今回のCSV API制限でこの項目を実施済みにしない |
| ログイン・変更通知 | 未確認。通知の実送信を確認する必要がある |
| 行動分析 | 未実装 |
| デバイスフィンガープリント | 未実装 |
| その他 | 上記のAPI制限などを具体的に説明できる。該当可否はStripeに確認する |
| 会員ログインなし | Skyにはログイン機能があるため該当しない |

認証ヘッダーの信頼性はSites入口が保証する前提であり、ローカルの合成ヘッダー試験を本番認証の証明にはしない。Stripeアカウント自体のMFA設定もSky利用者のMFAとは別。

申告済みの内容が実態と異なる場合はStripeの案内に従って修正する。本人確認書類と実施状況の申告は所有者が行う。
