# CSV仕事 v1 — 商品・実装・運用の正本

更新日: 2026-09-15 / 仕様版: `csv-cleanup/1` / 商品ID: `rockstar-csv-cleanup`

## 1. 目的と経路

最初に完成させる売れる仕事はCSV整形である。v1は市場補助型で、販売者本人がココナラ等の許可された公式画面で受注、連絡、入金確認、納品を行い、RockstarOSは私有CSVの受付、決定的変換、独立検査、成果物保存、作業記録を担当する。外部市場のログイン情報を取得せず、出品、応募、メッセージ、購入、返金を自動操作しない。

購入者向け試験価格は税込3,000円。1ファイル、条件と入金確認後24時間目安、範囲内の修正1回を含む。販売主体、連絡先、支払時期、返金窓口、特定商取引法上必要な表示は、実際の販売者と経路が確定した注文画面で別途提示する。

## 2. 入出力契約

- 入力: `.csv` 1ファイル、10 MiB以下、データ50,000行以下、100列以下。
- 入力文字コード: UTF-8、UTF-8 BOM付き、CP932。BOMを優先し、BOMなしで厳密なUTF-8として読めなければCP932を試す。読めないbyte列は拒否する。
- CSV: RFC 4180型のカンマ区切り。引用内の改行と二重引用符を保持する。NUL、閉じない引用、空/重複見出し、列数不一致を拒否する。
- 値: 全セルを文字列として扱う。先頭0、長い数字、改行、引用符を保持し、型推定、計算、日付化、補完をしない。
- 出力: `result.csv`、`report.json`、`report.html`。選択時だけ、原本結果と別に`spreadsheet-safe.csv`を作る。
- 保管: 受付から7日後は本人・buyerの取得と共有URLを無効化し、次回の本人アクセスcleanupでR2の原本・全納品成果物・共有token行を物理削除する。支払/返金イベントがあるjobは監査・会計に必要なjob/payment metadataを保持するため、ファイル本体の削除とmetadata削除を混同しない。支払記録のないsample/unpaid jobはmetadataも削除する。本人の削除操作なら条件を満たすjobを即時削除できる。独立scheduled purgeは未配置である。
- 顧客納品: sellerは納品後、任意で7日有効の共有URLを発行・失効できる。これはbearer capability URLであり、URLを持つ人なら操作できる。受取人の本人確認・identity bindingは実装していない。tokenそのものはURL fragmentで渡し、D1にはtokenのSHA-256だけを保存する。転送を避けるよう顧客へ説明し、本人確認が必要な市場では公式納品画面を使う。市場が公式納品画面を要求する場合はそちらを優先し、共有URLは規約を確認してから使う。

変換順は固定する。

1. decode・構文検査
2. 元見出しを使った列名変更
3. 変更後見出しを使った列順変更
4. 指定列の前後空白（Unicode whitespaceと全角空白）除去
5. 変更後見出しを使った重複判定（既定は報告のみ、先頭/末尾を選択可）
6. 指定列の文字列code point比較による安定sort。同値は元の行順を維持
7. 指定文字コードで出力。CP932へ往復できない文字は拒否
8. 変換器と別の期待値組立てで列、行数、全セル、上限を検査

表計算ソフトが`= + - @`始まりを式として解釈し得る値は、原本結果では変更せず警告する。利用者が選んだ場合だけ、先頭に`'`を付けた安全版を別成果物として作る。

## 3. 主体と状態

- seller: RockstarOSへサインインし、受注条件と外部入金の照合番号を登録し、成果物を取得する販売者。
- buyer: 市場の公式画面でsellerと取引する。sellerが規約上許されると確認した場合だけ、期限・失効付きbearer capability URLから納品物を取得し、1回の修正依頼または検収を記録する。URL保有者の操作であり、買主の本人確認ではない。市場の公式納品・連絡経路が優先される。
- operator: 保存障害、検査不合格、期限超過を監視する運営者。任意の利用者ファイルを通常画面で閲覧しない。
- billing account: 料金判定単位。`user_id`とは別に`billing_account_id`、`contract_id`、`policy_version`を固定する。
- provider: 売上、返金、手数料、税、払出しを外部証拠で照合する事業者。手入力番号は`manual_verified`として区別し、Provider証拠ではない。

運営画面は全体・利用者hash・売主ごとの新規受付停止/再開を記録できる。停止は新規受付だけに効き、受注済み・処理中jobは継続する。本人はアカウントのJSON exportを取得し、内部解約状態を翌JST月から新規受付停止へ切り替えられる。運営操作・監査event・outbox・冪等キーは同じD1 batchで保存する。outboxの外部配送worker、production operator allowlist/secret、実運用受入は未設定である。

仕事の状態は`quoted → accepted → processing → delivered → approved`。buyerまたはsellerの明示操作で検収する。検収前に範囲内修正を1回依頼でき、その後は第2納品版で完了する。検査または処理失敗は`quality_failed`となり最大3回まで再実行できる。同一受付番号に異なる入力または仕様を結びつけず、処理claimはrevision付きleaseで一度だけ取得する。各attempt固有のR2 keyとjobのlease IDを納品時に照合し、期限切れworkerによる上書き・二重納品を拒否する。入力と成果物はD1へ入れず、私有R2 objectへ保存する。

受付はD1へ確定してからCloudflare `waitUntil`で処理を登録し、登録に失敗した場合も未完了jobを残す。lease切れのjobは次の認証済みseller pollで最大3件ずつ再開し、attempt上限は3回。これは再開可能性であり、独立Queueの保証ではない。Sitesに独立Queue bindingがないため、ブラウザを閉じている間も必ず計算が継続するとは表示しない。P0で閉鎖後の無人完了を主張するには、別worker/queueを配置し、実iOS Safari・Android Chromeの端末証拠が必要である。

## 4. 料金

購入者価格とRockstarOS利用料を分ける。購入者価格はJPY 3,000（JPYは小数桁のない通貨なのでquote値も3,000円）。運営者が記録したbuyer paymentはこのJPY 3,000 quoteと通貨を完全一致で照合し、一部入金・別通貨・返金・取消・争議があれば開始と納品を停止する。販売者のRockstarOS利用料の試験判定はJST暦月、billing account・contract・policy version単位で、同じbilling accountに属する複数seller/providerの対象払出しを先に合算し一意な決定を一行だけ保存する。Provider確認済みの純入金が30.00 USD相当以上なら8.88 USD、未達なら0。現在の台帳は、対象仕事に紐付いたProviderの`paid_to_owner`を手数料控除後の本人向け払出しイベントとして計上し、同じ払出しに紐付く返金を差し引く。buyer paymentに紐づく注文返金・取消・争議はpayout調整とは別系列で保持する。これはProviderが通知した払出し状態であり、銀行口座への最終着金を必ず意味しない。`provider_fee`は監査用に保存し、払出し額に既に反映された費用を二重控除しない。手入力イベントは月額資格を増やさないが、手動確認した返金は対象額を減らす方向にだけ適用する。USD以外の入金は換算レートが未構成のため運営確認に回し、推測換算しない。根拠・FX・返金対応が確定できない純入金は0でなく`null`と要確認として保存・表示する。

`csv-seller-fee/1`は境界値を機械検査し、D1ではbilling account+JST月につき判定行を一意にする。Provider webhookのHMAC時刻署名、Provider event IDの冪等記録、同一IDの内容衝突拒否、逆順返金の保留と再計算、Provider payoutに紐付く手動返金の控除を合成API試験で確認する。仕事別の直接費台帳は運営記録用であり、30 USD対象純入金からの控除は未実装。請求IDの作成・同月一意請求の決済接続、本人同意、Setup/SCA、失敗後の再試行、fee refund adapter、月次回収上限を強制する課金台帳、解約済み月の請求抑止・既存請求取消も未実装である。現時点では請求・カード登録・請求test modeのいずれも有効化していない。閾値を後日返金が下回らせた場合に判定行は免除へ再計算されるが、既請求額を実際に返す経路は未実装である。FXはUSD以外のevidenceをnullableの要確認にする。本番前に月額請求と返金のProvider/test adapter、同意、FX、失敗・遅延通知、二重回収防止を別途受入する。将来、本人別の販売・決済・払出しProviderを接続した後だけ、払出し前控除へ移行できる。

## 5. 画面と販売文

`/csv`はスマホの最初の画面で商品、価格、上限、納期、ファイル、変換条件を示す。顧客の自己申告だけで入金済みにする操作はなく、未払jobは処理を開始しない。Providerイベントまたは運営者の`manual_verified`記録で入金状態が確認された後、sellerが処理を開始する。buyer納品、期限付き共有・失効、1回修正、明示検収を記録できる。`/csv`のアカウント領域では内部解約予定と本人データJSON exportを提供する。`/csv/operations`は運営者限定の停止/再開、支払event確認、月次判定、介入・納期・直接費dashboardと運営exportを提供する。直接費は記録できるが月額判定から未控除である。`/csv/terms`で範囲、返金、保管、共有納品の条件、月額課金が未有効であることを提示する。

販売文:

> CSVの「列がばらばら」「前後に空白がある」「重複を確認したい」「文字化けする」を、指定どおりに整えます。1ファイル税込3,000円。結果CSVに加え、何を変えたかと独立検査の報告をお渡しします。値の推測や勝手な補完はしません。10MB・5万行・100列まで、条件と入金確認後24時間目安、範囲内の修正1回込みです。

利用者募集文:

> 自分の仕事としてCSV整形を販売したい方を5人募集します。受付、変換、検査、納品ファイル管理をRockstarOSで試せます。外部市場の出品・連絡・入金確認は本人が行う市場補助型から開始します。JST月のProvider確認済み純入金が30 USD相当未満なら利用料0、到達月だけ8.88 USDです。実案件、返金、介入を含めて検証し、数字を作るための自己購入はしません。

## 6. 完成判定

- P0: 許可済み試験ホストで、合成入力から保存済みの検査付き成果物を得る。ローカルAPI統合試験は再開・納品・入金の合成ケースを検証する。ブラウザ閉鎖後完了を主張するには独立queueと実端末証拠を必須とする。
- P1: 第三者の有料取引1件を納品、検収、Provider入金照合まで通す。
- P2: 別の第三者3人以上を含む5人で、売主、データ、受取の分離を再現する。
- P3: 本人別の販売・決済接続で、対応範囲内1件を初期設定後の人手なしで入金照合まで通す。
- 事業検証: 10件の真正な有料案件について受注0、未入金、返金、実費、介入、再注文も分母へ含める。自己購入、架空顧客、合成入金を実績にしない。

コード、公開、販売開始、実績は別状態で管理する。実顧客、外部アカウント、同意、決済が必要なgateは、コード完成だけで完了へ変えない。
