# Cloud agent runtime and orchestration provider comparison

Research date: 2026-10-02. Prices below are public list prices read from the linked vendor sources on this date, in USD, before tax, region adjustments, negotiated discounts, logs, data transfer, support, storage beyond included amounts, or model inference. Recheck the vendor price pages and contract terms immediately before selecting a provider.

## Decision summary

Keep the current Cloudflare Workers + D1 + Durable Workflows implementation as the first production candidate for Rockstar's **durable control plane**: it is already the repository's workflow runtime and the local fixture proves prepared-work recovery after a Wrangler/Workerd process restart. This is a candidate, not a contract or production acceptance. It has usage and retention limits that must be designed around; a long sleep is not a free archive, because persisted state for sleeping and completed workflows counts toward storage and completed state is retained by default for 30 days on the Paid plan. The paid plan currently includes 50,000 concurrent running workflows, 2 million queued instances and 365-day maximum `step.sleep`; verify account-level rate limits and needed retention before launch. [Cloudflare Workflows limits](https://developers.cloudflare.com/workflows/reference/limits/) · [Cloudflare Workflows pricing](https://developers.cloudflare.com/workflows/reference/pricing/)

### 2026-10-02 official-source recheck

- Cloudflare's published Workflows rates and limits remain the reference used by the estimate above: Paid includes 500,000 steps/month and 1 GB-month state, then $0.80 per 100,000 steps and $0.20 per GB-month; requests and active CPU use standard Workers rates. A completed Paid Workflow's state is retained by default for 30 days. A single step's non-stream return and event payload are each capped at 1 MiB, each instance state at 1 GB, and `step.sleep` at 365 days. Keep durable business records and user artifacts in Rockstar's own D1/R2 contracts rather than relying on Workflow retention as the product archive. V2 sessions are isolated microVMs but terminate after inactivity or at an 8-hour maximum, and the docs say session state is ephemeral rather than long-term durable. Treat V2 as a possible bounded **execution** adapter in those regions, never as Rockstar's controller or offline-continuation ledger. Its pricing page still labels the committed-baseline V2 price as “launching by October 2026”, so whether that discount is actually purchasable for the target account/region must be confirmed in that account. A contained sandbox estimate therefore must include runtime, storage, Worker/DO, logs and the destination region, not just CPU. [Cloudflare Containers pricing](https://developers.cloudflare.com/containers/platform/pricing/)
- Google's public Agent Engine/Code Execution prices remain $0.0864/vCPU-hour and $0.0090/GB-hour, with sessions and memory metered separately from model inference. Use the linked price table as a list-price input only; this comparison does not establish Google contract acceptance or Rockstar's per-task invoice semantics. [Google Cloud price update](https://cloud.google.com/blog/products/ai-machine-learning/new-enhanced-tool-governance-in-vertex-ai-agent-builder/)

Do not put every agent in the workflow runtime. Keep durable job state, budgets, deadlines, approvals, cancellation, provider receipts, and reconciliation in the control plane. Run third-party or generated code in a separately bounded per-job sandbox; keep model inference as a separately measured provider cost. Cloudflare Containers, AWS Bedrock AgentCore Runtime, and Google Vertex AI Agent Engine are execution candidates, not replacements for Rockstar's consent, Wallet, A2A task-state, or owner-scoped artifact contracts.

## Orchestration price example

This deliberately isolates orchestration cost to make the metering difference visible. Assumptions: 100,000 jobs/month; 20 billable workflow steps/transitions per job; no retries; Cloudflare 1 second active CPU per job; Google 18 internal and 2 external steps per job; Cloudflare persisted workflow state averages at or below 1 GB-month. Price inputs use Cloudflare Workers Paid plan, AWS Step Functions Standard in US East (N. Virginia), and Google Cloud Workflows list pricing.

| Provider | Metering assumptions | Monthly orchestration estimate |
|---|---|---:|
| Cloudflare Workflows | 2.0M steps, 100k invocations, 100M CPU-ms; 500k steps and 30M CPU-ms included; 1 GB-month state included | $13.40 usage + $5 Workers Paid base = **$18.40** |
| AWS Step Functions Standard | 2.0M state transitions; 4,000 free; US East price $0.000025/transition | **$49.90** |
| Google Cloud Workflows | 1.8M internal and 0.2M external steps; first 5k internal and 2k external free; rates charged per fully or partially used 1k increment | **$22.90** |

Calculations:

- Cloudflare steps: (2,000,000 − 500,000) / 100,000 × $0.80 = $12.00. CPU: (100,000,000 − 30,000,000) / 1,000,000 × $0.02 = $1.40. Requests are below the 10M included monthly amount; storage is assumed below the 1 GB-month included amount. The $5/month Workers Paid plan charge is added. CPU wait time is not charged, but steps and persisted state are separately metered. [Cloudflare Workflows pricing](https://developers.cloudflare.com/workflows/reference/pricing/)
- AWS: (2,000,000 − 4,000) × $0.000025 = $49.90. Retries count as more transitions. The rate is explicitly the vendor's US East example; other regions can differ. AWS charges Lambda/compute, data transfer, and other called services separately. [AWS Step Functions pricing](https://aws.amazon.com/step-functions/pricing/)
- Google: ceil((1,800,000 − 5,000)/1,000) × $0.01 = $17.95 internal; ceil((200,000 − 2,000)/1,000) × $0.025 = $4.95 external; total $22.90. Failed and retried steps count. Calls to external providers and callback waits are external steps. [Google Workflows pricing](https://cloud.google.com/workflows/pricing)

These are not full per-job costs or a benchmark. A production estimate must add the actual retry distribution, state retained per job, execution environment, object storage, D1/SQL, queues, network, telemetry, provider runtime, and each LLM's exact input/output token rates. The cost of model reasoning, provider-agent usage, or an isolated code sandbox can exceed workflow orchestration by orders of magnitude. Never derive a customer charge from these infrastructure estimates; use verified provider usage receipts and the existing reservation/settlement ledgers.

Vendor claims of “exactly once” or durable steps describe the provider's orchestration semantics. They do not prove that an external agent received a task exactly once, that a timed-out request was not accepted, or that stopping a remote task succeeded. Rockstar must retain one-shot send claims, result-unknown reconciliation, remote task IDs, signed usage receipt verification, Wallet reservation/settlement, and owner-authorized cancellation in its own state machine.

## Recommended boundary

1. **Rockstar control plane:** Cloudflare Worker/Workflow + D1 for the current implementation; stable adapter contracts for job acceptance, status, approval wait, cancellation, cost ceiling, provider usage receipt, and artifact retrieval. Preserve an exportable state schema and an alternate-provider deployment path as scale or contract needs change.
2. **Agent execution plane:** start with an allowlisted tool/agent provider. Add per-job sandbox execution only for work that needs shell, code, a browser, or packages. Use short-lived scoped credentials, deny ambient credentials, deny unnecessary egress, cap CPU/memory/disk/wall time, and destroy or explicitly retain files according to user consent.
3. **Model plane:** accept BYO/API-key and marketplace providers through a separate adapter; pin provider/model/version and price schedule per job. Record provider-verified usage and map it to Rockstar's own bounded billable ledger.
4. **Device plane:** mobile or desktop client can disconnect after durable cloud acceptance. The cloud owns continuation only when `continueWhileDeviceOffline=true` was signed into the consent proof; reconnect fetches the same job state and artifact and never resubmits the work automatically.

## Contract questions before enabling production

- What are the region, availability SLA, support response times, retention/deletion behavior, RPO/RTO, account limits, and incident notice obligations for the precise plan and services?
- Can persisted Workflow/D1 state and artifacts be exported and deleted for a user/account on request? What data remains in backups, logs, support systems, traces, or abuse review?
- What is the maximum job duration and durable-state retention at the contracted tier? What happens at queue, concurrency, step, payload, CPU, memory, or storage exhaustion?
- Are provider task lookup, cancellation, idempotency key retention and accepted-but-unanswered reconciliation supported by the agent provider? Specify behavior with a dropped response and task ID not received.
- Does sandbox egress allow-listing prevent access to cloud metadata, private networks, and other tenants? Who can inspect or retain filesystem snapshots and logs?
- Which region/rate and invoice dimensions apply to the actual account? How are usage details exported at job granularity, and can those receipts support customer dispute resolution?
- How are customer encryption keys, key rotation, breach response, subprocessors, data residency, model training, and customer content deletion handled contractually?
- What are provider model rate limits, model deprecation notice, price change notice, cached-token semantics, tool charges, and minimums? Can exact model/version and the rate snapshot be pinned for the life of a job?

## Acceptance before switching or enabling paid execution

Use the existing 12 cloud-continuity scenarios, plus a costed load profile, against the contracted sandbox and a supported offline device. Require: same-job recovery after controller restart; no repeat send after an ambiguous provider response; owner/project isolation; real remote task lookup/cancel; test usage receipt signature and exact Wallet settlement; false offline consent rejected; hard budget/deadline stops; log and storage secret scans; export/delete evidence; and measured local-document conflict preservation. Keep production deployment, external sends, live model charges and user billing disabled until those pass.
