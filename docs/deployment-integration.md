## 提案する再開手順

1. 「配信側の追加機能を残してrockへ統合する」方針を利用者に確認する。ファンド/利用料/分配試算の事業方向は固定する。
2. Sitesの公開履歴とDB適用履歴を調べ、適用済みSQL・journal・snapshotを特定する。不明なら移行を書き換えない。
3. 両親履歴を保持する統合用branchで、API名・データ契約・画面導線を設計してmergeする。片側優先の一括解決をしない。
4. 仕事と単発実行の関連を追加し、冪等性・ユーザー分離・revision/実行ロック・台帳の重複拒否を再検証する。
5. 新規DBと既存配信スキーマからの移行の両方を検証。PC接続、アプリのservice worker更新、スマホの仕事入口も確認する。
6. README・project.mdを更新し、全検証→両リモートへ通常push→同一SHAの成果物保存→本人限定公開→本番確認の順で完了させる。
