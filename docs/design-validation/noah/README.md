## 実行

リポジトリ直下で実行する。Node.js 22.13 以上と Python 3.9 以上（標準の `sqlite3`）。先に `npm ci` を流す（`noah-screenless.test.mjs` が、今の main の起動スクリプトをそのまま読み、そのスクリプトが npm の package `fflate` を使うため）。`npm ci` をしていない checkout でも、他の 7 ファイル（56 群）と DDL の検証は動く。

```sh
node --experimental-strip-types --test "docs/design-validation/noah/*.test.mjs"
python3 docs/design-validation/noah/validate-noah-v1.py
```

L3 の後（2026-11-20、Node.js 22.23、SQLite 3.53）: 試験 61/61、DDL 11/11。

失敗すると終了コードが 0 以外になる。DDL の検証の結果は `work/design-validation/noah-v1-validation.json`（`NOAH_SQL_RESULT` で変えられる）。型契約は `npm run typecheck` の対象に入っている（`tsconfig.json` が `**/*.ts` を読む）。

2026-11-20 の結果（main `fa57c57` を、別の場所へ取り出して確かめた。Node.js 22.23、SQLite 3.53）: 試験 61/61、DDL 10/10（拒否を確かめた行 63）、`npm run typecheck` エラー 0、`oxlint docs/contracts docs/design-validation/noah` 指摘 0。これはその時点の入力への結果で、変更した後の成功は保証しない。

## 限界

- まだ移していない参照実装（握手・入力欄・道具を持つ担当・面の見分け・Space と ACP の下書き）は、製品のコード（`lib/`）から import されていない。ここの全件成功は、製品の成功を意味しない。実装する task が `lib/` と `tests/` へ移し、同じ試験を通す。移した後の関数は、ここの試験も `lib/` の実装を通る。
- 握手は、参照実装を実在の 500 host に 1 回ずつ（通った 276 host には、1 時間あけてもう 1 回）通した（上の実測）。試験の中にあるのは、実測の写し 1 件と合成のサーバー。**道具の呼び出し（`tools/call`）は、実在の接続先へ 1 回も送っていない**（設計の検証で、他人の道具を呼ばない）。成果の形（文字・JSON・画像の割合、時間）は、測っていない。L6 の完了の定義で、実在の接続先 3 つへ、人が頼んで確かめる。
- 参照実装を動かしたのは Node。Cloudflare Workers の上（CPU 時間、同時の接続、`waitUntil` の 30 秒）では動かしていない。本番の Worker から内部向けのアドレスへ届かない事も、確かめていない（仕様書 86 の 10.3 に、出す前の確かめ方）。
- 入力欄の関数は、実在の道具 3,699 個の定義に通したが、作った引数を相手が受け取るかは、確かめていない（呼んでいないため）。
- 起動の型紙（`noahLaunchPlan`）は、命令の並びを作る所までを確かめている。**実際に配布を導入して動かす確認はしていない**（外の package をこの検証で実行しない）。`npm exec --offline` と `uv pip sync --require-hashes` の動きは、task 89 が隔離環境の中で確かめる。
- 道具を持つ担当の試験は、決めた応答を返すモデルを使う。実際のモデルが仕込まれた指示に乗らない事は示していない。示しているのは、乗った場合でも、一覧に無い道具と確認の要る道具が呼ばれない事。
- DDL は手元の SQLite（3.53.1）で流した。Cloudflare D1 の batch・複製・負荷は確かめていない。接続先の枠（`host_take`）と、つなぐ前・頼む前の上限は、1 本の接続で、文の結果を確かめた。同時に来た要求で数え落とさない事は、D1 の上で確かめる（74 と 87 の試験）。本番への適用は本人の許可の後。
- 実測は 2026-11-20 の 1 日。標本 500 の割合には ±4 ポイント程度の幅がある。道具の定義の変わり方は、1 時間あけた 2 回だけで、日や週の単位は測っていない。台帳は月に 2 万件以上増えているので、数字は古くなる。

## 変える時

この folder と `docs/contracts/noah-*` を、検証コードの正本にする。契約を変えたら 2 つのコマンドを流し直し、型・DDL・試験の差分を一緒に確かめる。合格の件数を固定の条件にしない（件数が増えるのは普通）。失敗した試験を消して通さない。
