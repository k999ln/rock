## 実行

リポジトリ直下で実行する。Node.js 22.13 以上と Python 3.9 以上（標準の `sqlite3`）。このキットだけなら `npm install` は要らない。

```sh
node --experimental-strip-types --test "docs/design-validation/noah/*.test.mjs"
python3 docs/design-validation/noah/validate-noah-v1.py
```

失敗すると終了コードが 0 以外になる。DDL の検証の結果は `work/design-validation/noah-v1-validation.json`（`NOAH_SQL_RESULT` で変えられる）。型契約は `npm run typecheck` の対象に入っている（`tsconfig.json` が `**/*.ts` を読む）。

2026-11-20 の結果（main `c4d7c27` の上）: 試験 41/41、DDL 9/9、`npm run typecheck` エラー 0、`oxlint docs/contracts docs/design-validation/noah` 指摘 0。これはその時点の入力への結果で、変更した後の成功は保証しない。

## 限界

- 参照実装は、製品のコード（`lib/`）から import されていない。ここの全件成功は、製品の成功を意味しない。実装する task が `lib/` と `tests/` へ移し、同じ試験を通す。
- 握手の試験は、実測の写し 1 件と合成のサーバー。実際の接続先の多様さ（遅い応答、途中で切れる接続、独自の拡張）を網羅しない。
- 起動の型紙（`noahLaunchPlan`）は、命令の並びを作る所までを確かめている。**実際に配布を導入して動かす確認はしていない**（外の package をこの検証で実行しない）。`npm exec --offline` と `uv pip sync --require-hashes` の動きは、task 89 が隔離環境の中で確かめる。
- 道具を持つ担当の試験は、決めた応答を返すモデルを使う。実際のモデルが仕込まれた指示に乗らない事は示していない。示しているのは、乗った場合でも、一覧に無い道具と確認の要る道具が呼ばれない事。
- DDL は手元の SQLite（3.53.1）で流した。Cloudflare D1 の batch・複製・負荷は確かめていない。本番への適用は本人の許可の後。
- 実測は 2026-11-20 の 1 回。標本 500 の割合には ±4 ポイント程度の幅がある。台帳は月に 2 万件以上増えているので、数字は古くなる。

## 変える時

この folder と `docs/contracts/noah-*` を、検証コードの正本にする。契約を変えたら 2 つのコマンドを流し直し、型・DDL・試験の差分を一緒に確かめる。合格の件数を固定の条件にしない（件数が増えるのは普通）。失敗した試験を消して通さない。
