# ゲームを入口に生活を豊かにするOS — 自律動作と衛星通信

2026-09-21 / Mini200 E1設計追補 / RQ48の共通OSとRQ49のavocadoMiniへ接続する製品方針。主担当はMaterial Invention / avocadoMiniのROCK。実装、実回線、家電、衛星、実機の受入資料ではありません。

## 1. 利用者の方向と設計案を分ける

利用者の明示した方向は「ゲーム機が主となり、生活全体にも入り、生活全体をより豊かにするOS」。衛星を増やして端末へ通信を届け、人の環境の近くで自律して役立てる構想も記録します。続く「ちゃんと更新してmainにあげて」は、この設計と前回E1資料のGitHub main統合の承認です。通信契約、衛星開発・打上げ、機材購入、他者の環境への接続、Site配備、実資金の承認には拡張しません。

実現方法の提案は、まず端末内でゲーム・認識・保存が成り立つ構成を作り、家庭回線・携帯回線・外付け衛星ゲートウェイを交換可能な通信手段として扱うことです。直接衛星通信と自社衛星群は将来研究で、初期製品の前提や発注仕様ではありません。

最新の商品体験の入口はゲームです。既存の仕事・Tool・Walletや、Pixel 10でのCore実機検証、QEMU検証を廃止・完了扱いにはしません。共通Coreと個別アプリの更新・受入は独立させます。

## 2. 利用者が体験する一周

1. avocadoMiniを起動し、誰が使うか、カメラ・マイクの状態、導入済みゲームを確認する。
2. 「赤い粒子にして」で選択し、身体とボタンで狙い・発射し、画面内で衝突・結合させる。主要計算と描画は本体内。
3. 作品やルールを版付きで保存し、自作ゲーム、学習、運動へ再利用する。ゲームの計算を現実の化学・医療効果の証明にしない。
4. 生活機能を使う場合だけ、対象機器と許可範囲を本人が別に接続する。最初の候補は一室の照明だが、対応機器・プロトコル・実行器は未選定。
5. 同期や共同利用が必要なら通信する。回線が切れても、導入済み・ローカル対応のゲームと保存を続け、オンライン専用機能は利用不可または照合待ちと表示する。
6. 再接続しても古い家電操作や支払いをまとめて実行しない。失効・期限・実際の状態を再確認し、必要なら新しい承認を取る。

## 3. 責任と接続境界

| 層 | 役割 | 与えない権限 |
| --- | --- | --- |
| avocadoMini本体 | 身体・音声入力、ゲーム処理、描画、保存、電源・熱の制御 | 衛星受信だけによる物理操作・決済の承認 |
| RockstarOS共通Core | 本人・端末の分離、権限、停止、結果確認、保存・復旧 | AIや通信事業者への包括実行権限 |
| 生活機器adapter | 許可済みの機器・操作を限定し、応答と状態を照合 | 未登録機器の自動操作、別家庭への越境 |
| 通信管理層（提案） | 接続可否、費用制約、遅延・切断を表示し、許可した経路を選ぶ | 回線切替による外部送信同意の省略 |
| 同期・外部サービス | 明示同意した作品の共有、更新、共同利用 | 原音・生画像の既定収集、ゲーム入力ループの必須依存 |

既存のBroker、owner、capability、operationId、receipt、保存・復旧契約を再利用します。既存Web APIやAndroid／QEMUへ新しい通信管理層が接続済みという意味ではありません。Webのcamera/microphone禁止、既存四方向研究profile、E1専用入力profileの未実装を維持します。

## 4. 通信経路の設計案

初期の評価経路は「衛星網 → 屋外の衛星端末／ゲートウェイ → EthernetまたはWi-Fi → avocadoMini」。衛星端末は本体の20cm寸法・熱・電源予算に含めず、別機器として見積り・契約・検証します。携帯回線も、外部ルーター利用とモデム内蔵を区別し、E1候補BOMに未選定モデムを搭載済みとして加えません。

2026-09-21に確認したStarlink Mini公式仕様は298.5×259×38.5mm、平均25〜40Wです。これは外部通信端末の参考値であり、E1の消費電力や衛星モデムの選定値ではありません。[Starlink Mini仕様](https://www.starlink.com/public-files/specification_sheet_mini.pdf)

直接衛星通信は別経路です。例えば日本のau Starlink Directでは、空が見える屋外、対応機種・対応アプリ等の条件があり、任意の端末・アプリで自由な高速通信ができる前提にはできません。E1への適合や通信事業者との接続契約は未確認です。[au公式サービス説明](https://www.au.com/mobile/service/starlink-direct/)

自社衛星群には地上・宇宙側の通信設備と継続運用が必要で、周波数・軌道資源の国際調整と各国の許認可も別途検討します。これは打上げ計画、法的適合判断、予算承認ではありません。[ITUの制度説明](https://www.itu.int/en/mediacentre/backgrounders/Pages/Regulation-of-Satellite-Systems.aspx)

回線の優先順は固定の無制限自動切替にせず、利用者が許可した経路、上限、計測値、処理の必要条件で決める提案です。大容量ゲーム・モデル更新は従量回線で自動開始せず、必要容量・費用条件の確認と中断再開を設計します。衛星回線経由の対戦・クラウドゲームの性能は別測定です。

## 5. 状態、保存、失敗と復旧

通信状態は`offline`、`connecting`、`online`、`degraded`を候補とし、各機能の利用可否を別に持たせます。`online`は全サービスの成功を意味しません。経路変更中も、ゲームの保存先や利用者を切り替えません。

- 入力候補: ownerRef、deviceRef、networkProfileId、destination、allowedOperations、費用上限、同意の版・有効期限。秘密や生の音声・映像は診断入力に含めない。
- 表示候補: 使用回線、最終確認時刻、同期中／未同期、利用不可理由、変更操作の結果不明。推定値と実測値を分ける。
- ローカル保存: 作品とゲーム状態を版付きで保存する設計。クラウドへの送信は別同意。通信断をローカルデータ削除の理由にしない。
- 同期: owner・作品・版・内容hashを照合し、競合時は両版を残して選択を求める。端末が変わっても別人の作品へ混ぜない。
- 外部操作: operationId、対象、入力hash、期限、同意を固定。応答が消えた操作は`uncertain`として照会し、失敗と決めつけて再送しない。
- 切断中の安全: 家電等の新しい変更要求を勝手に蓄積しない。停止操作や手動復帰は通信事業者やクラウドの復旧待ちにしない。
- 電源: 衛星通信は電力を供給しない。E1初期案には内蔵電池がなく、停電時の自律稼働には本体・周辺機器それぞれの別電源設計が必要。

## 6. 最初の受入と未決定事項

下記はすべて未実施の製品受入計画です。既存140項目の算術・許可モデルや文書テストを、この経路の成功数へ加算しません。

1. `MAT09`で導入済みゲーム・日本語PTT・身体入力・保存をPC試作から20cm本体へ接続し、回線切断前後の入力遅延、描画、保存、再起動を測る。
2. 生活機器は最初に模擬照明を使う。利用者・機器・部屋を変えた越境拒否、同意撤回、期限切れ、二重送信、結果不明を確認する。
3. 遅延・帯域低下・損失・切断を人工的に与え、ローカル操作の継続とオンライン機能の正確な縮退を確認する。合成通信は実衛星試験と区別する。
4. 別承認後に既存衛星ゲートウェイで測る。地域、サービス／契約、端末・firmware、空の遮蔽、時刻、遅延分位、損失、停波、転送量、電力を記録する。
5. 対応する一台の生活機器で、許可、操作、状態読戻し、取消可能範囲、手動復帰を実測する。錠、加熱機器、医療、決済はこの初期試験に含めない。

`ROCK`は既存Coreに沿ったadapterと状態表示・模擬試験、`EXTERNAL`は通信・機器仕様と提供条件、`JOINT`は同一条件での実回線・機器・20cm本体受入、`OWNER`は対象地域・費用・機器・送信範囲の承認を担当します。通信管理のAPI、生活機器プロトコル、遅延／可用性の合格閾値、モデム・アンテナ・電源は未確定。用途別の要件と実測で決め、製造承認や一般提供を先に宣言しません。
