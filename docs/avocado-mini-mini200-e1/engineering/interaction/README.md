# avocadoMini E1 — 音声・身体入力の融合仕様

文書 ID: E1-INT-REF1 / 2026-09-21。**設計提案と実行可能な抽象モデル**であり、既存 RockstarOS に実装済みの機能、量産仕様、実機測定報告ではない。ここでいう粒子はゲーム内のデジタル粒子であり、現実の粒子放射や化学合成ではない。

## 1. 製品体験と範囲

TV 接続の 1 人用ゲーム機。手・上半身の位置で狙い、片手の小型ボタン操作でつかむ／放すことを明示し、粒子を投げて結合、保存、創作へつなぐ。声は選択・調整・保存・一時停止を補助する。音声入力のみから「avocadoMini 実機の身体入力で発射した」という記録を生成しない。

初期 E1 は前方 1～2 m の手／上半身、座位・立位の範囲を校正する。外観の 3 窓やカメラ候補だけから指先精度・全身追跡・360 度・複数人を保証しない。旧 4 台 × 3 眼の全身構想はこの初期範囲の必須条件ではない。身体入力を失うと発射を保留し、画面で位置調整を案内する。音声を代替の実機発射証拠として扱わない。

初回起動は MIC OFF、カメラも目的別同意前は利用不可。物理 MIC OFF ラッチはハード設計・実測の受入条件であり、本ソフトモデルでは論理的な初期 OFF だけを扱う。明示同意 → PTT ボタンを押して話す → 離す → 確定した内容を画面表示、という順とする。声が使えなくてもボタンと画面で同じ補助操作ができることを初期製品の条件にする。

## 2. 音声技術の選定境界

候補はローカル ASR の `whisper.cpp` と multilingual Whisper モデル。日本語 `ja` の文字起こしに固定し、翻訳モードを使わない。`.en` は選ばず、multilingual base / small を同一テストセットで比較し、端末内の実測結果で選ぶ。C/C++ 実装とモデルの利用条件は個別に固定・保存する。Whisper 公式は日本語指定と多言語モデルを説明しているが、本ゲーム機の雑音下精度や遅延を保証していない。[whisper.cpp 公式](https://github.com/ggml-org/whisper.cpp)、[Whisper 公式](https://github.com/openai/whisper)

起動語・VAD・AEC・ASR は別機能。`whisper.cpp` の VAD は別モデルを使う構成であり、音声区間検出は起動語の認証ではない。起動語「アボカド」の日本語学習データ、商用ライセンス、誤起動率は未確定なので、初期製品は **PTT 必須** とする。openWakeWord の公式 README は現在の対応を英語中心とし、同梱事前学習モデルは CC BY-NC-SA 4.0、コードは Apache 2.0 と区別している。同梱モデルをそのまま商用日本語起動語として採用しない。[openWakeWord 公式](https://github.com/dscripka/openWakeWord)

AEC は実際のスピーカー再生に対応する参照音と時間整合が必要で、ASR を導入するだけでは成立しない。HDMI の TV 音と USB 側参照ではクロック差、TV 内 DSP、遅延変動がある。別経路の放送音や他人の会話には適切な参照がない場合がある。最初は PTT 中のゲーム音量抑制を用い、AEC と割り込み発話は実測後の解放機能とする。外部 TV 音そのものを止められるとは限らない。[Speex の AEC 原理説明](https://www.speex.org/docs/manual/speex-manual/node7.html)

電気担当の候補は ReSpeaker XVF3800 USB（XIAO なし）、ファームウェア候補 `respeaker_xvf3800_usb_dfu_firmware_v2.1.0_48k2ch.bin`。本担当は USB 記述子・実チャンネル割当・DSP 処理・AEC 成立を検証していない。ファームウェア、モデル、ビルド、量子化、音声デバイスの識別子と設定ハッシュを試験記録に固定する。CPU / GPU の候補対応は、同時ゲーム実行時の性能保証ではない。

## 3. 音声パイプラインと保存制限

物理ミュート状態／PTT → 入力ルータ → 必要な音声前処理 → VAD／終端検出 → 16 kHz・mono・signed 16-bit PCM → ローカル ASR → 途中文は表示だけ → 最終文の限定文法 → 許可ゲート → UI。DSP が前処理済みなら二重 AEC を行わず、raw / processed のチャンネル実測で選ぶ。

PTT 初期構成の録音前バッファは 0 秒。最大発話 15 秒、PCM 本体の上限は 16,000 × 1 × 2 × 15 = **480,000 bytes**。これは ASR モデル、特徴量、ドライバ、DSP、OS の追加メモリを含まない。将来の常時起動語機能を明示 opt-in で解放する場合だけ、2 秒の揮発性 pre-buffer = 64,000 bytes を別途評価する。

原音ファイル保存、クラウド送信、音声入りログは既定 OFF。自動クラウド fallback は禁止。モデル未導入・ASR 障害では PTT を利用不可として表示し、ボタン操作を残す。モデルとruntimeが導入済みなら、ネットワークがオフラインでも端末内ASRとPTTは継続できる設計とする。外部サービスだけを利用不可として分離する。曖昧な最終文は復唱して再入力を依頼し、後で勝手に実行するキューを作らない。

ミュートまたは同意撤回で新規収音を止め、capture / resampler / VAD / ASR job / transcript / queued intent / UI 履歴の対象バッファを失効・削除し、mic epoch を更新する。ワーカープロセスの停止・削除 ACK 前には「処理中データの削除完了」と表示しない。OS や DSP のメモリコピー、DMA、デバイス側録音、給電／clock／data の物理遮断は、別の実装・測定項目である。本モデルの `list.clear()` はそれらの証明ではない。

マイクのミュートはカメラを止めない。カメラ遮光はマイクを有効化しない。各状態を別に表示する。ミュート前に組み立てた混合操作は取消すが、ミュート中に改めて始めた正当な身体＋ボタン操作は可能とする。

## 4. 日本語の初期コマンド 10 個

認識結果を自由な実行コードにしない。初期文法は下記の確定フレーズのみ。表記正規化は NFKC・前後空白・末尾句点までとし、否定を削除しない。言い換えは収集・試験してから追加する。

| 発話 | 許可する効果 | 許可しない効果 |
|---|---|---|
| 粒子を選択 | 架空粒子の sandbox プレビュー選択 | 発射・購入 |
| 赤い粒子にして | 色のプレビュー | 実物素材の変更 |
| 重力を弱く | ゲーム内設定案を表示（例 0.5 倍） | 現実の力・装置出力制御 |
| 重力を元に戻して | ゲーム設定案を 1.0 倍へ | 実機制御 |
| 結合モードにして | 次の操作を結合プレビューへ | 化学合成・自動発射 |
| 結合を解除して | プレビュー内の解除案 | 作品ファイルの破壊的変更 |
| ひとつ戻して | sandbox の直前操作を戻す要求 | 決済・外部操作の取消成功の偽表示 |
| 作品を保存 | ローカルの新バージョン保存要求 | 上書き確定・同期成功の偽表示 |
| 時間を止めて | ゲーム UI を一時停止 | 物理非常停止 |
| 止めて | ゲーム UI を一時停止 | 家電の安全停止・身体安全の保証 |

プレビューの実ゲーム適用は現在の操作をいったん解除し、画面確認と明示操作後に新しい状態で始める。保存はファイル書込・検証・永続化 ACK 後にのみ「保存済み」。抽象モデルは保存要求数を増やすだけで、ファイル保存を実装していない。「続けて」は初期音声文法に含めず、再開は明示ボタンとする。

「発射して／投げて」は音声発射禁止。「支払って／照明をつけて／鍵を開けて」は別権限が必要と返すだけ。ゲームの音声同意は生活・経済の承認ではない。生活機能を後日有効にする際も対象機器・具体操作・現在のセッション・有効期限を表示した独立承認を使い、オフライン要求を再接続時に自動実行しない。支払いは金額・宛先・通貨・手数料を含む別確認と認証が必要で、声紋識別だけで認証しない。

## 5. 文脈・身体入力の許可ゲート

実装時は端末内の信頼境界でイベントに `boot/session ID, purpose/mode, random nonce, mic epoch, state revision, sequence, captured/end monotonic time, expiry` を結び付ける。アプリが自己申告した `source=AVOCADO_LIVE` や `verified=true` は証拠にならない。デバイス由来情報、校正 ID、トラッキング品質、ボタンエッジを信頼したアダプタが検証し、署名・認証・再送排除などの設計と試験を別途行う。

ASR の途中結果は常に表示だけ。最終結果も、現在の PTT ticket と同じ文脈、単調増加 sequence、許可済み目的、最新状態が揃う必要がある。最終文の受付は発話終了から 2 秒以内の提案上限とし、過ぎたら破棄する。ASR 内部の log probability をそのまま正解確率と見なさない。モデルの `intent_score ≥ 0.85` は合成入力の閾値であり、実機では別の評価データで校正する必要がある。閾値未満、範囲外、NaN、型違いは非実行。

身体でのデジタル発射は GAME / CREATE・PLAY、カメラ同意、開放、実機由来の検証、校正一致、領域内の有効追跡、直前の明示つかみ操作、明示リリース、古くない未使用イベントが全て必要。提案上限は身体情報の age 150 ms、つかみ操作 lease 5 秒。lease 期限到来・遮蔽・領域外・FAULT では保留／取消して再操作を求める。これらは測定した追跡精度や遅延ではない。発射用イベントの取得時刻はつかみ操作より後でなければならない。

声で状態変更が確定したら旧身体イベントを失効させ、身体発射が確定したら旧音声結果を失効させる。同じ調停周期では PAUSE / STOP を先に処理する実装を要求する。直前の周期ですでに表示された発射を声が遡って「起きなかった」ことにはできない。マイク停止時・雑音下・故障時の音声「止めて」は届かない可能性があるため、音声停止は快適機能であり物理非常停止ではない。

録音の再生や TV 音が実際のマイクへ入ると、通常発話と識別できない場合がある。PTT は偶発入力を減らすが、本人性を証明しない。LLM が作った文、アプリが送った文字列、ファイルからの認識結果は非信頼入力で、ゲーム実行口へ直接接続しない。開発モードのシミュレーションには DEV_SIM の出所を付け、avocadoMini の実機起源証拠や経済価値へ昇格させない。

## 6. 遅延・精度の目標と実測計画

全て **未測定の受入目標**。音声の発話終了→UI 反映 P95 ≤ 1.2 秒を、終端判定 300 ms + 待ち行列 50 ms + ASR 700 ms + 許可判定 50 ms + UI 100 ms の設計配分で検討する。各段の P95 の単純合計は全体 P95 の証明ではなく、エンドツーエンドの同時計測で判定する。最終結果 TTL 2 秒は遅延目標ではなく、遅れた結果を捨てる上限。身体→表示 P95 ≤ 100 ms は別ループとし、ASR 高負荷でゲームが止まらないよう資源を分離・計測する。

| 項目 | 試験条件 | 初期の合否提案／報告事項 |
|---|---|---|
| 日本語短文 | 成人 12 人、複数地域アクセント、10 コマンド、各 5 回、距離 1 / 2 / 3 m、quiet / SNR +10 dB / SNR 0 dB | 基本組合せ 12 × 10 × 5 × 3 × 3 = 5,400 発話。属性別・距離別も報告し平均だけで隠さない |
| 初期利用範囲 | 1～2 m、正面、quiet および SNR +10 dB、座位／立位 | intent 正解率 quiet ≥ 95%、+10 dB ≥ 90%。3 m と 0 dB はストレス試験で、初期対応保証から除外 |
| 文字認識 | 上記データ、固定した正規化・参照文字列 | 日本語 CER = (置換 + 削除 + 挿入) / 参照文字数。目標 quiet ≤ 10%、+10 dB ≤ 20%。生 CER と正規化 CER を併記。CER 良好だけでは誤操作合格にしない |
| 雑音内訳 | ファン、ゲーム音、TV 会話、音楽、残響、距離変化 | 音圧・SNR 定義・マイク位置・再生経路・音量・ファームウェアを記録。quiet は試験環境の実測値を記録し無条件の静寂としない |
| TV／録音／複数人 | コマンドを含む TV・録音、別話者の同時発話、PTT 押下中も実施 | 非対象音での sandbox 誤実行率を数える。声のみの発射・支払い・家電実行は構造的に 0。PTT でも他人の声を本人確認できたとしない |
| 無操作負荷 | 30 時間の TV／ゲーム再生、PTT 無操作、MIC OFF 区間 | 新規 capture なし・UI 実行 0 を観測する。0 件でも母集団の発生率 0 を証明したとしない |
| 遅延と資源 | GPU / CPU ゲーム負荷、ファン作動、最大 15 秒発話、連続 PTT | 音声 E2E P50 / P95 / P99 と 2 秒 TTL 失効率、身体 E2E とフレーム落ちを同時記録 |
| AEC | 実 TV の HDMI 経路と参照の遅延変動、二重発話、別放送音 | AEC オン／オフの intent 誤り、残留エコー、本人音声欠損を比較。手元の音声が消える設定は不合格 |
| ミュートと取消 | 捕捉中／ASR 中／最終文待ち／再起動、カメラ独立動作 | 論理 job と buffer の消去 ACK、epoch 失効、遅延文非実行、物理給電／clock／data・DSP/DMA の別測定 |
| 故障・遮蔽 | カメラ閉、ボタン断、追跡欠落、ASR 異常、時計異常 | 発射保留、復帰後に古い要求を実行しない。FAULT をモード変更で解除できない |

将来の起動語はこの評価とは別に、商用日本語データ権利、誤受理／誤拒否、長時間 TV 再生、アクセント、同居人、プライバシーを審査し、未合格なら PTT のみを維持する。子供の声や複数プレイヤーを製品範囲へ加える場合は、同意設計と追加データ・試験を先に行う。

## 7. 今回実行した抽象テスト

`permission_model.py` は標準ライブラリだけで動く直列・インメモリ参照モデル。`tests.json` に **99 項目 PASS / 0 FAIL、実 ASR 実行 0、物理試験 0、外部操作 0** を出力した。主に次を検査した。

- 初期権限 OFF、厳密 bool、途中文非実行、低スコア、NaN / infinity、出所違い、最終結果の一回性。
- ミュート・同意撤回・モード変更による buffer / job / epoch 失効、再有効化で旧結果が復活しないこと。
- TTL、時刻巻戻り、起動し直したセッション、FAULT をモード変更で回避しないこと。
- 声だけの発射禁止、家電・支払いは別許可、カメラ閉／不正校正／領域外／不正型／追跡不良の発射拒否。
- つかむ前に取得されたリリースイベントの拒否、声→体と体→声の順序入替、停止後の発射拒否、ミュート中の新しい身体入力の独立性。

**証明していないもの:** Whisper / VAD / AEC / wake word、録音再生の音響的識別、暗号鍵・デバイス署名検証、本人認証、実ボタン／実カメラ、プロセス間競合、永続重複排除、実保存、物理ミュート、実際の家電・決済。`LOCAL_ASR` や `verified=True` は信頼アダプタの試験用入力にすぎない。テスト用 session / nonce はプロセス内の連番で、本番の乱数・永続 replay 対策ではない。実装では public な状態フィールドを外部アプリへ直接公開しない。

同フォルダの `fusion_permissions.svg` はこの許可境界の図であり、配線図ではない。図の矢印は権限を自動付与する接続を意味しない。
