# avocado Mini：GTA対応を成立させるための変更案

今回の範囲：ゲームの実行経路と、最初の実機試験を具体化する。元のPDFは変更しない。

追記：Robloxも対応対象に追加。ゲーム共通の起動・アカウント・入力・対応状態の管理は、[外部ゲーム接続仕様](/Users/kaiya/Documents/Codex/2026-09-26/n/outputs/avocadoMini_game_platform_integration_2026-09-27.md)にまとめる。本書のGTA固有の要件と未解決事項は維持する。

## 1. 目的と、まだ決めないこと

目的は、利用者がMiniからGTAを起動し、操作し、音と映像を受け取り、正常に終了できる構成を作ること。

- Miniは独立端末という要求を維持する。基本機能やMini用ゲームをPro必須に変更しない。
- GTAそのものもMini内で実行するか、GTAだけ外部PC／Proで実行してよいかはユーザー確認中。無回答を外部演算への同意とは扱わない。
- 検討は本体実行を優先するが、固定外形への収納・放熱が成立したとは扱わない。
- 使用時全高200mm以下、既定の外観、背面下部の洋梨形ボタンと蔦の位置を勝手に変更しない。R5図面の直径30mm／台座96mmは比較寸法であり、承認済み製品寸法として固定しない。
- テレビ・眼鏡・スマホを製品の必須表示先にしない。試験用モニターでの成功を製品の空間表示成功に数えない。
- RockstarOSという名称はRockstar Gamesとの提携・公認を意味しない。

## 2. 今回の試験対象案

タイトル未指定のため、公式PC要件を確認できる **GTA V Enhanced PC版・ストーリーモード** を仮対象とする。GTA VI、GTA Online、Legacyはそれぞれ別の互換性確認が必要。

一次評価の提案値：1280×720、低画質、フレーム生成なし、平均30fps以上、同じシーンと設定で30分の連続試験。読み込み区間と操作区間を分け、フレーム時間の分布と最低側の性能も記録する。起動しただけ、平均値だけの報告で快適性を保証しない。

これは最終製品の画質・fps保証ではなく、最初に計算機側を評価するための仮基準。Enhancedで不合格でも、報告せずLegacyにすり替えない。別版を試す場合は版と結果を分ける。

## 3. 本体実行案：必要な変更

| 項目 | R5の候補／現状 | GTA本体実行のための変更案 |
|---|---|---|
| 演算部 | CM5、Arm系 | Windows向けx86-64ゲーム実行環境を持つ計算基板を評価 |
| GPU | CM5内蔵GPU | PCゲーム向けAPUを候補評価。公式の独立GPU要件との同等性は実測前に認定しない |
| メモリー | 8GB候補 | 評価機は32GBを仮置き。内蔵GPUとの共有分とOS／認識処理の同時使用を測る |
| 保存 | eMMC 32GB候補 | 評価機はNVMe SSD 512GBを仮置き。ゲーム、OS、更新、一時領域、個人保存を積算 |
| OS | Linux系が基盤候補 | Windows 11基盤への変更案を審査。RockstarOSの共通機能層との境界を定義 |
| 電源・熱 | 未確定 | 計算部だけでなく光学・センサー・SSD・ファン・変換損失を含めて再計算／実測 |
| 操作 | 手・声・代替操作の設計 | 最初は対応ゲームパッドの標準入力で検証。身振り入力は別試験 |
| 出力 | 裸眼空間表示が未成立 | ゲーム実行の評価と別ゲートにする。製品表示が未成立なら完成品は未成立 |

評価部品例はAMD Ryzen Z2 Extreme。公式仕様の標準TDPは28W、設定範囲は15～35Wで、携帯ゲーム機向けの内蔵GPUを持つ。ただし、これは完成基板のサイズ、Mini全体の電力、GTA動作、供給契約の証拠ではない。採用判断には評価機と製造用基板の両方が必要。

ゲーム公式要件には内蔵GPUやモバイルチップの非互換可能性が記載されている。GPUのコア数やメモリー量だけで合格にしない。候補APUで合格しなければ、別構成を評価するか要求を再審査し、外形を無断で変えない。

## 4. OSと個人データの扱い

Windows基盤を選ぶ場合、RockstarOSは個人認証・権限・通知・アプリ管理・機器制御等の共通製品ソフト層として構成する案になる。R5のLinux基盤候補からの実質的な変更であり、単なる名称変更や互換保証ではない。

Mini／Proの共通機能・共通APIを維持することと、OSカーネル／ドライバーが同一であることを区別する。共通基盤の採用、機器ドライバー、更新、アプリ隔離、認証境界は変更審査が必要。Windowsに変更しても安全監視の独立性を維持する。

- ゲームは正規ランチャーと利用者の正規ライセンスで起動する。Rockstarの認証・利用権をMiniの顔認識で代替しない。
- Miniのプロフィールとゲームアカウントを明示的に関連付ける。人が交代しただけでゲームアカウントやセーブを誤って切り替えない。
- 共用Windowsアカウントのファイルを別ユーザーにも開放するような構成にしない。OSアカウントや保存領域の分離方式を検証する。
- ゲームが公開していないセーブ・一時停止機能を、Miniが自由に呼び出せると仮定しない。終了・保存完了は対応範囲で確認する。
- GTA Onlineは別の対応試験とし、必要なアンチチートを正規に動作させる。互換性のために回避・無効化する設計にしない。
- Miniの基本機能がネット不要でも、GTAの有効化・利用権確認やオンライン機能までネット不要になるわけではない。

## 5. 外部実行案：ユーザーが選んだ場合だけ

GTAを対応PC／Proで実行し、Miniから操作を送り、描画済みの映像と音を受信する。Steam Remote Play等が方式の参考になるが、独自Mini上の動作やGTA特定版への対応は未確認。

- Proをホストにするなら、Pro自身が対象ゲームの実行環境を満たす必要がある。保存容量の追加だけでは足りない。
- ホストの機器認証、利用者承認、セッション単位の入力権限を設ける。外部ネットワークへの無認証公開はしない。
- 通信断や画面停止を検知したら、押し続け状態の入力を解放し、以後の入力を止める。ホストのゲームが一時停止できない場合はその制限を知らせる。
- 復旧時に古い入力をまとめて再送しない。ユーザー交代後のセッションへ映像・操作・セーブを流用しない。
- 遅延は入力から実表示までを測る。ネットワークの往復時間だけを操作遅延と表示しない。
- 外部ホストが停止したら、そのGTAセッションは使えない。Mini本体の基本機能やローカルアプリの独立性とは分けて説明する。

## 6. 空間表示を別に判定する

通常の映像配信が返すのは、描画済みの映像と音である。自由視点のゲーム世界や車・建物の完全な3Dモデルを取得できたことにはならない。

製品要求である裸眼の立体空間表示には、表示方式と安全性の成立に加え、表示装置へ必要な視点／深度／シーン情報を供給する正規のゲーム側連携が必要になる。具体的に何が必要かは表示方式ごとに定義する。

現在は表示エンジン、GTA側の空間表示連携とも未確定。ゲーム実行テストに合格しても「GTAを部屋に立体表示できる」とは告知しない。映像からAIが推測した裏側や奥行きを、元ゲームの正確な世界として扱わない。

## 7. 一つずつ埋める試験台帳

全項目、現時点では未実施。

| 順番 | 確認すること | 残す証拠 | 現在の不足 |
|---|---|---|---|
| G0 | 本体実行か、GTAのみ外部実行も可か | ユーザーの選択 | 選択確認中 |
| G1 | 正規ゲームの起動と基本操作 | 版、OS、ドライバー、評価機構成、起動ログ | 評価機とゲーム実行環境へのアクセスなし |
| G2 | 指定条件で継続して遊べるか | フレーム時間、電力、温度、音声、入力遅延、保存・再開結果 | 実ゲームの測定なし |
| G3 | 固定外形へ収納し放熱できるか | 完成基板／冷却／ケーブル／光学系の実寸CAD、実測 | 採用基板・光学方式未定 |
| G4 | 認証・通知等と同時動作できるか | 高負荷時の性能・温度・騒音、ユーザー交代時の分離試験 | 製品ソフトと統合実機なし |
| G5 | 要求された裸眼空間表示で操作できるか | 光学・安全・視域・精細さ・遅延とゲーム連携の実証 | 表示原理と対応連携が未成立 |
| G6 | Online等の追加機能 | 対象版ごとの正規接続・互換試験 | 別試験未実施 |

G1・G2は試験用画面で評価してもよいが、その結果は計算機側の合格に限定する。G3とG5は早期に並行して成立性を確認し、表示や収納に見通しが立たないまま製造部品を大量調達しない。

## 8. 今回行ったことと、次に必要なもの

今回行ったのは、R5と公式要件の照合、変更案と試験台帳の作成。製品コードの実装、ゲームのインストール、実機の改造、購入、GTAの起動試験は行っていない。

この作業フォルダでは設計資料と画像類を確認したが、Mini向けの製品ソフトや動作試験記録は見つかっていない。実装・実測へ進むには、G0の方針選択と、選んだ経路の評価機／開発環境が必要。
