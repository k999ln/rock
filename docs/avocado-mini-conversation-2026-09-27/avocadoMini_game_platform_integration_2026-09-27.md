# avocado Mini：外部ゲーム接続仕様案（GTA / Roblox）

日付：2026-09-27  
状態：設計追補。公式資料を照合した接続方針であり、製品コード、動作するアダプター、実機でのゲーム対応は未実装・未検証。

## 1. 今回追加する要求

RobloxをGTAと並ぶ対応対象に追加する。Miniのゲーム一覧から公式アプリ／体験を起動し、対応入力で操作し、映像・音を受け取り、終了後にMiniへ戻れることを目指す。

- Miniは独立端末のまま。ゲームごとに本体実行と外部実行を区別する。
- 既存の全ゲームへ自動対応するとはしない。今後のタイトルは接続方式と互換試験を追加して増やす。
- 本体実行と外部PC／Pro実行のどちらを製品に採用するかは、前のGTA検討で未決のまま。Robloxの追加を、外部演算を必須にする同意とは解釈しない。
- 本体実行の評価では、GTAとRobloxの両方を扱えるWindows 11・x86-64構成案を優先して比較する。OS変更と部品採用は未承認。
- 外形・背面ボタンを変更せず、テレビやスマホを必須の製品表示先にしない。空間表示の未成立を接続設計だけで解消したことにしない。

## 2. Robloxで区別する3段階

| 段階 | 目標 | 必要な実装・確認 |
|---|---|---|
| R1：通常プレイ | 公式Robloxアプリを起動し、選んだ体験に参加して遊ぶ | 対応OS・GPU、正規ログイン、ネット、通常のゲームパッド／キーボード等、選んだ体験ごとの試験 |
| R2：Miniの入力 | 手・声を、対応済みの操作へ割り当てる | Mini側の認識と入力変換、利用者の明示許可、誤入力／解除／フォーカス制御、体験別互換試験 |
| R3：Mini向け体験・空間表示 | 制作者がMiniの操作に合う体験を作る。裸眼空間表示は別途検討 | Roblox側の正規開発機能による対応、必要な表示連携と光学装置の成立確認 |

R1の成功はR2・R3の成功を意味しない。Roblox Studioで自作体験を作れることも、任意の体験を空間表示へ変換できることを意味しない。

## 3. 公式環境を使う接続方針

Robloxの公式PC要件は64bit Windows 10／Windows 11とDirectX 10以上の機能レベルに対応するGPUを挙げている。Linuxは公式非対応。したがって、現在のCM5＋Linux候補へ公式Windowsプレイヤーをそのまま追加する設計にはしない。

- 公式のRobloxアプリと公式の体験ページ／共有リンクを使う。起動導線は対象OSの公式方式に従って検証する。
- 新規の公開リンクはShare linksを優先する。旧Deep links作成手順は公式資料で非推奨とされている。
- Share linksの生成は体験の所有者または所定のグループ権限を持つ制作者が行う。Miniが他者の体験の共有リンクを自由に生成するとはしない。既存の体験には公式ページや制作者が提供したリンクを使う。
- 起動URLへパスワード、Cookie、本人認証の証明、セーブの鍵を入れない。リンク内データを信頼できる認証結果として扱わない。
- 改変クライアント、ゲームへのコード注入、アンチチート回避を対応方法にしない。
- RobloxをMini内で実行しても、オンライン体験にはインターネットが必要。Mini単体とはProや外部ゲームPCが不要という意味であり、Robloxがオフライン化する意味ではない。
- 外部実行を選ぶ場合は、対応ホストでの正規アプリ実行、映像・音の取得、入力伝送を個別に検証する。RobloxがSteamのゲームである、Steam Remote Playへ追加すれば保証される、とは扱わない。

## 4. GTAと共通にする機能

以下はこれから実装する設計上の役割であり、公開済みAPIではない。

| 共通機能 | 責任 |
|---|---|
| ゲーム一覧 | GTAの版、Robloxの体験リンク、本体／外部実行、必要機能、確認済みの操作方式を表示 |
| 起動管理 | 公式アプリの有無、利用権、ネットと実行先を確認し、本人の要求で起動 |
| アカウント管理 | Miniの利用者とゲーム側アカウントの対応を本人に確認。プラットフォームの正規認証を尊重 |
| 入力管理 | 対象のゲームにだけ入力を送る。終了・切替・通信断・認識喪失時に入力を解放 |
| 出力・状態管理 | 映像・音と、確認できた実行状態を受け取る。起動要求の送信を参加成功と表示しない |
| 個人設定 | お気に入り、操作の割当、本人が選んだ起動先等をユーザー別に保存 |
| 対応台帳 | タイトル／体験、版、OS、機器、入力、出力方式、試験日、証拠と制限を保存 |

通常のゲーム映像から、完全な3Dシーンや任意の内部状態を取得できると仮定しない。アプリを起動できても、ミッション状態・セーブ完了・サーバー参加等を確認できるAPIがない部分は不明と表示する。

## 5. 操作とアカウントの境界

- 初回は通常の対応ゲームパッド等で確認する。Robloxはゲームパッドに対応し、制作者はInput Action Systemで操作を定義できるが、全体験の全メニューが同じ操作で使えるとは限らない。
- 手や声を標準入力へ変換する部分はMini側の新規開発。既存の全体験を自動的に手操作対応にしない。対応体験と操作を明示し、通常入力へ戻せるようにする。
- 生の顔画像・音声・身体映像をゲームへ標準で渡さない。必要な認識結果を許可された操作へ変換する。
- Miniの顔認証でRobloxのログイン、追加認証、利用制限を代替しない。共有端末では前の人のRobloxセッションを次の人へ公開しない。
- Robloxの保護者設定、利用可能な体験、チャット制限、購入確認を尊重する。Miniの自律機能が勝手に参加・投稿・購入しない。
- Miniに保存する操作設定と、各Roblox体験の進行データは別物。各体験のセーブを一律に読み書き・同期する機能は約束しない。
- ネット切断時は入力を解除し、未送信の古い操作を復帰時に再送しない。オンライン体験が一時停止できるとは扱わない。

## 6. 最初の確認項目

全項目未実施。GTAの試験とは別にRoblox用の記録を残す。

1. 評価機に公式Robloxアプリを導入し、本人が正規ログインできる。
2. 公式の体験ページ／共有リンクから、選んだ体験に参加できる。ログイン待ち、参加不可、ネット切断を成功扱いにしない。
3. 代表体験を選び、移動・視点・ジャンプ・メニュー・退出を通常入力で確認する。軽い体験だけで全体験の対応を宣言しない。
4. 体験ごとに解像度・画質・fps・入力遅延・温度を測る。GTAの試験結果をRobloxへ流用しない。
5. Miniへの復帰、ユーザー交代、入力機器切断、ネット切断で、旧入力や他人のアカウントが残らないことを確認する。
6. 通常入力が合格した後に、選んだ操作だけ手／声の入力を追加し、誤作動と解除を測る。
7. 空間表示はGTA追補と同様に独立した成立試験を行う。試験用画面の成功を製品完成に数えない。

現在、作業フォルダにMiniの製品コードや動作する接続アダプターは確認できていない。今回は対応対象と設計を追加した段階で、ゲームのインストール・アカウント接続・実機試験は行っていない。
