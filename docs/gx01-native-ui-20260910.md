# Gameのnative入口と所有者境界

RQ06/08/13〜15 / 0→1・明確な楽観主義 / 接続同意と購入、照合中と完了を見分けられない / 既存C UI・Wallet/authenticator Unix IPC・GX00/01検証器 / Game専用画面と要求経路 / 未確認を完了にしない・二度目の要求を作らない・Hubを止めない / [host操作・境界試験](evidence/gx01/native-ui-20260910/host-tests.json)。これは最終imageのGX01-UI合格ではない。

Gameから公開Game A/B、本人の接続、今回のquote、本人承認、履歴・照合へ進む。100 centsの購入額、試験手数料3、外部実費0、保留合計103、受取り10単位を別表示する。すべて固定公開fixtureで、本番料金を定めない。既存のATM手数料0、月額888は変更しない。

接続と購入は異なるintentと`auth.game.connect`/`auth.game.exchange`を使う。PINは明示入力し、UID1004の認証器へだけ送信。Platform/Walletへ送るのは固定intentに束縛したcredential。確認中は更新で内容を差し替えず、期限切れを承認できない。認証器の失敗ではPINを保持せず再入力を求める。

Gameの通信不明・不正応答は専用pendingに元要求を保存する。本人が同じ要求で照合でき、新しい交換は保留する。Hubの道具・履歴、Wallet、端末の正常終了への移動を止めない。APPROVEDは保留・送信待ちであり、Gameの確定receiptが来るまで交換完了としない。取消のクリックも返金完了ではない。

PlatformはUID1000の所有者だけを受け付け、列挙したowner operationをGX00/01の厳密なwire検証へ渡す。作者API・任意mint・追加のPIN/owner指定は通さない。通信中にHubのlockを保持せず、Walletの残高が変わった可能性があれば古い表示cacheを無効にする。購入用APIの実TLS・台帳検証はD担当のGX01受入で別に行う。

試験残高は登録・試験認証・Wallet利用条件を確認後の独立操作「公開テスト残高 $100 を追加」でだけ要求する。商品成功から残高を計算しない。既に追加済みなら入口を再表示せず、server側でも同owner一度限りの元receiptへ収束させる契約。月額契約への同意を自動で行わない。

Linux C UI実操作/描画回帰とPlatform境界6試験が成功。[quote画面](evidence/gx01/native-ui-20260910/game-quote-review.png)・[本人確認画面](evidence/gx01/native-ui-20260910/game-purchase-consent.png)はhost rendererの操作fixture。初回のtest helper誤名とheader hit不足の失敗を記録して修正した。次は実Game facade/authority、同じ配布imageでの実操作・再起動・復元へ接続する。


## 実OSで発見した購入承認の残り時間バグ

RQ06/08/13/14/16 / 秘密を探す・明確な楽観主義 / 条件を読んだ利用者の承認が止まる / 既存専用authenticator・署名quote / 残り有効時間の検証条件だけを修正 / 実OSの同意から確定まで・二重記帳0 / 失敗した実画面、停止後全台帳、時間差入り実TLS回帰、新image再試験。

中間`7ed6cf72d16f77c2cfb804914df1819b4282682d`の実OSで、登録→試験認証器→Wallet利用条件→明示の合成$100追加→Game A接続同意→購入quote→今回だけの購入承認画面まで進んだ。接続用PINは成功したが、購入用PINが拒否された。[実画面と元試験記録](evidence/gx01/real-os-auth-delay/summary.json)を保持する。

原因は`wallet_auth/fixture.py`の`_options()`が接続だけに1〜120000msを許し、交換をATMと同じ120000ms固定で検証したこと。quoteを読んでから購入承認を始めると残り時間が短くなるので拒否された。固定clockで即座に承認した先行試験では発見できなかった。修正`4e31554a5cfd415b0f9a9878e1e1306f949f1596`は専用exchangeも既存の期限内へ限定し、元quoteの期限・署名・purpose・device bindingを緩めない。実TLS SDK回帰では3秒のreview差を入れ、117000msの専用交換認証→Game10単位、同optionsのATM使用拒否を確認した。

失敗後は新しい購入要求を作らず、実画面の「戻る・承認しない」から正常終了した（8.524秒）。authorityも正常停止し、全lifetime lock下の[読取監査](evidence/gx01/real-os-auth-delay/stopped-ledger-audit.json)でAVAILABLE10000 cents、未確定売上0、交換/保留/付与0、月額同意・請求0、全資産の貸借一致を確認。元データ・receipt・画面を保持する。

観測器側にも修正が必要だった。試験残高の追加後はWalletへ戻るのが実装上の正常動作だが、初回probeはGame画面を待って期限切れになった。継続probeは元の同じOS・台帳を使い、登録やcreditを再送していない。helper名/indentation/返却専用metadata比較/lock名の準備失敗も別attemptとして保存し、製品の合格へ換算しない。

修正を含む新中間OSのbuild・freezeと、新しい空のauthorityからの実画面一周を進めている。host回帰成功だけでは新OSの合格・最終候補のD0〜D6完了とはしない。
