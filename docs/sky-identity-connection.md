# Skyの本人確認と1タップ接続

## 結論

Skyはマイナンバーそのものを保管・配布するハブにしない。最初の本人確認で作るRock IDと、ツールごとの最小権限grantを分離する。本人確認済みの利用者は、grantの内容が変わらない限り、各ツールを1タップで接続できる。

公的個人認証サービス（JPKI）はマイナンバーカードの電子証明書を使い、マイナンバー自体は利用しない。将来JPKIを導入する場合も、Skyが保持するのは本人確認の結果・時刻・保証レベル・失効確認に必要な参照だけとし、個人番号を汎用プロフィールへ保存しない。

## 役割の分離

| 層          | 保持するもの                                     | 保持しないもの                           |
| ----------- | ------------------------------------------------ | ---------------------------------------- |
| Rock ID     | 内部利用者ID、本人確認状態、確認時刻、保証レベル | マイナンバー原文、暗証番号、カード秘密鍵 |
| Sky grant   | ツールID、許可scope、同意版、接続時刻            | 住所・生年月日などの本人属性             |
| 実行context | 利用者が会話・共有操作で渡した案件文や原稿       | 別ツールの入力、不要なプロフィール属性   |
| receipt     | 実行先、許可scope、結果状態、時刻                | 原稿本文などの処理内容                   |

本人属性が必要な個別手続では、ツールが必要な属性を明示し、その時点で追加同意を取る。既存grantよりscopeが広がる場合は1タップ扱いにせず、差分を表示して再同意を求める。

## 画面と操作

1. タイムラインの未接続ツールは「接続」と表示する。
2. 接続画面はRock IDからSky担当への関係と、渡す情報・渡さない情報だけを表示する。
3. 「1タップでSkyに接続」で、利用者IDに紐づくツールgrantを保存する。
4. 接続後のカードは「頼む」へ変わり、独立したChatでそのアプリを開く。
5. Chatの既定はSky Autoとし、接続済みアプリから依頼内容に合う役割を選ぶ。直接指定は任意にする。
6. 案件文・原稿など毎回変わる情報はChatまたはOSの共有contextから渡す。長いフォームは必要な人向けの「手動入力」に畳む。
7. 判別不能・未接続・入力不足では自動実行せず、必要な追加情報または接続先をChatで示す。

## 現在の実装境界

現在はSitesが認証した利用者IDに、`tool / scope / consent_version / connected_at`だけをD1へ保存する。JPKIやマイナアプリとの実接続、本人属性の保管、外部サイトの自動読取はまだ実装していない。したがって画面上でも「マイナンバー登録済み」とは表示せず、Rock IDへのサインインとツール利用許可を区別する。

## 将来の本人確認接続

- デジタル庁の認証APIをOIDC/OAuth 2.0認可コードフローで接続する。
- nonce・state・PKCE・redirect URI固定・署名検証・失効確認をサーバー側で行う。
- ツールへは内部のpairwise IDと必要な属性証明だけを短時間tokenで渡す。
- 高リスク操作、送信、契約、支払、権限拡張では再認証または明示確認を行う。
- grantの確認・解除・監査履歴を利用者自身が管理できるようにする。
