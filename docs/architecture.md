# 実装と次の接続点

製品要望は [製品ベース](product-baseline.md)。本書の「現在」は既存Web/PCに限定。nativeには別のSky/Wallet/backendがあり、[branch監査](progress-audit-20260909.md)を読まず新規実装と判断しない。

本書は既存Web/PCの実装境界。主開発対象となるOSの構成・権限・更新設計は [OS開発設計書](os-development-design.md) を参照する。WebのサーバーやMCPアダプターだけをOSランタイムとは扱わない。現在のソースとD1は、OSへの移行設計が検証されるまで保持する。

## 現在の境界

`app/page.tsx`: ファンドの検索・参加・配分計画、ウォレット接続、料金と分配試算、単独ツール実行。
`app/work/page.tsx`: 仕事の作成・順次実行・確認・再開。設計の正本は [project.md](../project.md)。
`lib/catalog.ts`: 審査済みの掲載情報。candidateは導入候補、pendingは本体・条件の確認待ち。
`lib/local-plan.ts`: 保存データの検証と導入プラン生成。保存キーはloop.local-plan.v1。
`lib/wallet.ts`: EIP-1193相当の接続IF・アドレス検証・接続エラー表示。
`lib/settlement.ts`: 有限数と上限を検証する純粋な試算計算。これは送金台帳ではない。
`scripts/discover.mjs`: 公開APIのみを読む収集コマンド。queryはURLSearchParamsでエンコード。20秒でタイムアウト。取得候補はJSONデータとして保存し実行しない。

Sitesの標準サインインと信頼できるゲートウェイのユーザーIDを使い、D1の `fund_plans`・`tool_runs`・`work_jobs` をユーザー別に読み書きする。SitesがIDを付与しない構成では、`chatgpt.site` とSites dispatchの両方を確認した上で、認証済みメールをSHA-256の仮名IDへ変換し、メール本文は保存しない。更新APIでは同一Originを要求する。Sites以外へデプロイする場合、クライアントが認証ヘッダーを偽装できないゲートウェイが必須で、Workerの直公開は安全ではない。

秘密鍵、入出金口座、アプリ独自のウォレット認証セッションはない。外部サイトリンクは利用者が開く。Walletアドレスを収益の所有者として信用したり、支払先として登録するAPIは存在しない。

## WebMCP

対応ブラウザでは `list_funds` と `select_fund` を登録する。前者は読み取り、後者は詳細画面を開くだけ。入力検証・AbortSignalによる解除を実装。非対応なら通常画面を利用。契約検証可能なWebMCP実行コンテキストが今回の環境で見つからなかったため、実機での登録・状態遷移は未検証。

## 仕事の保存

`lib/workflow.ts` に順序・通過・最終確認のルールを集中させる。`work_jobs` はユーザー別JSONとrevisionを持ち、SQLの条件付き更新で別タブの上書きを防ぐ。同一操作IDの再送は同じ内容なら無変更、内容変更なら409。`/api/jobs` はGET・POST・PATCHのみで、本文12 KB、試行200件、一覧最新100件の上限がある。

仕事画面のrunnerは任意の `onRecord` を受け取り、仕事のイベントへ結果を保存する。単独実行は従来どおり `tool_runs` へ保存し、仕事との二重計上をしない。成功は本人端末からの報告であり、会計証明としては使わない。実行本文・出力はクライアントメモリ上にあり、再読込では復元しない。

## 将来のデータモデル

- User: 内部ID、認証済みウォレット、必要に応じた本人確認状態。
- AutomationVersion: ソースURL、固定commit/hash、ライセンス、実行権限、通信先、費用・停止仕様。
- Installation: 所有者、バージョン、必要な登録の状態、明示的な実行同意。
- Run: 開始・終了、実行結果、資源使用量、エラー。ユーザーごとに認可。
- RevenueEvent: 外部イベントID、月、通貨、確定額、取り消し状態。認証済み提供元だけが作成。
- MonthlySettlement: 利用者・対象月の一意制約、利用料上限、適用為替、徴収実績、返金。

売上から控除できないサービスでは別の徴収方式が必要。ブラウザの入力値やlocalStorageを会計の正本にしない。決済API・Webhook署名検証・冪等キー・監査履歴を備えてから徴収を有効化する。

## ローカル自動化アダプター

Mr.の案件チェック・出典整理・無料版作成・納品記録照合をローカルアダプターとして実装した。Web版は3ツールをブラウザで処理し、Python版は4ツールを指定入力だけで実行する。外部サービス操作アダプターは未実装。追加時は入力/出力型、必要な外部登録、許可された通信先、停止・再試行、秘密情報の保存場所、機械資源の上限を宣言する。最初は原稿/文字起こしなどの成果物を生成し、本人が確認して納品する。Web上で取得したREADME内の指示をユーザーの操作許可と見なさない。

## Mr.の実行面

`lib/mr-tools.ts` がブラウザ向けの独立処理、`components/mr-tool-runner.tsx` が入力/結果/保存。入力原稿は永続化・外部送信しない。`toolkits/mr/rock_star_tools.py` は固定ハッシュを検証した原本をローカルに読み込む。保存済みツールを維持しつつ、新しい手順に合わせココナラの旧チェック項目だけをリセットしてv2へ移行する。
