# Noah — 成果データの保存と提供

- 本人が言う一言: 「Agentから受け取ったデータを集めたい。選んだ成果をNoahの改善にも提供したい」
- Goal: 本人が成果を検索・出力でき、選択した成果だけを明示同意で運営へ提供・撤回できる。
- Noaがつなぐもの: 認証済みaccount、既存WorkのNoah実行成果、独立した提供台帳。
- AMC工程: 成果の一覧 → 内容を開く → 出力、または提供対象を選択 → 同意 → 提供 → 必要なら撤回。
- Jev合格条件: 他人の成果0件、未同意の提供0件、古い成果版の提供0件、撤回後の運営取得0件、同じ操作の再送による復活0件。試験で確認する。
- 出力先: 本人のWork、本人の端末へのJSON/ファイル、選択して同意した成果の専用台帳。
- Wallet: 新しい課金・支払い・利用権を発生させない。
- hardware profile依存: なし。Webに保存済みの成果を扱う。
- 失敗時: 認証・保存先を再確認する。未取得を空の成功にしない。操作IDを保持して安全に再試行する。

## 今回の実装範囲（task99）

本人が「1,2どちらも」と指定した追加範囲。既存のWeb Workに保存された `noahExecution.state=returned` の本文・ファイルを扱う。本人の成果はWorkを正本とし、自動で運営へ提供しない。ローカル専用Macの成果はアップロードしない。既存A2A/クラウドの成果は `/noah/outputs` の既存の保存・出力機能を維持し、今回の提供台帳には取り込まない。後続L6の道具実行がWorkへ同じ成果契約で保存された際にも利用できる。

## 画面とAPI

- `/noah/data`: 本人の成果を20件ずつ一覧・本文/Agent/ファイル名で検索し、成果単位のJSONとファイルを出力。取得した結果を合格と表示しない。
- `GET /api/noah/data`: 本人の一覧、`id`で詳細、`view=operator`で提供された成果の一覧。各一覧は続きを取得できる。
- `POST /api/noah/data`: `share`（成果版、選択本文・ファイル名、同意、固定目的版、操作UUID）と`revoke`（提供UUID）。本人scopeと同一Origin必須。書込はサーバーで成果を読み、本人が見た版と一致する時だけ行う。
- 運営権限は専用の `NOAH_DATA_ADMIN_USER_IDS`（JSON配列、最大100 ID）。空・不正は拒否。利用統計の権限やクライアントの指定では付与しない。運営画面では有効な提供だけを表示・出力できる。
- 初期の同意目的版 `noah-quality-v1`: Noahの品質確認・不具合調査のみ。学習・販売・一般公開への提供は含まない。提供しなくても本人の保存・実行・出力を使える。
- 本文とファイルを別々に選ぶ。初期状態は全て未選択、同意も未選択。提供する内容を送信前に表示する。個人情報・機密が含まれていないか本人が確認する。匿名化を保証しない。
- プロンプト、所有者ID、Work ID、課金情報、実行先の鍵は運営向けデータへ含めない。選択した成果自身に含まれる文字列はそのまま提供される。

## 保存・撤回・上限

`noah_result_contributions`に、本人/Work/成果版、操作IDと入力hash、目的版、提供時刻、状態、選択した成果の写しを保存する。成果のSHA256を記録し、選択ファイルのサイズとSHA256をサーバーで照合する。結果本文/ファイルは既存の実行上限（結果128KiB、12ファイル、1ファイル32KiB、合計64KiB）以内。

1 Workにつき1回の提供。再送は同内容なら現在の状態を返し、内容変更は409。撤回は写しをNULLにし運営一覧から除外する。最小限の操作記録を残し、古い再送で復活させない。同じWorkの再提供は今回含めない。本人あたり台帳10,000件を上限とし、超過は明示する。

本人の元のWorkは撤回で削除しない。既に運営がダウンロードした写しはシステムから回収できないことを同意前に示す。撤回後に新しく取得できないことを保証対象とする。

DB変更は開発用SQLと試験だけ。本番への適用、配備、権限設定は行わない。
