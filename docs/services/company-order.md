# 会社受注（company-order）

- 本人が言う一言: 「この仕事、会社で受けて回して」
- Goal（Eveが作る）: 目的＝顧客の依頼を会社名義で納品する / 入力＝依頼文・資料・受注額・納期・販売先・AI可否・資料の持ち出し可否 / 期待成果＝検収に通った納品物と分配の計算 / 予算上限＝受注額 − 販売手数料 − 予備 / 要る権限＝受注の記録、資料の読み取り。応募・契約・送金は本人。
- Noaがつなぐもの: lib/sky-recipe-planner.ts（工程の計画）、lib/sky-company-order.ts（実行先の判定・見積り確認・分配の計算）、lib/work-composition.ts（接続済みの処理）。足りない能力は planner の gap を Sky の検索語にする。
- AMCの工程:
  1. 条件の確認（担当: AMC）— 合格条件: `decideExecutionPlacement` が blocked でない。規約確認の記録がある。
  2. 見積り（担当: AMC）— 合格条件: `checkOrderQuote.acceptable === true`。
  3. 計画（担当: Noa）— 合格条件: `planRecipes` の候補が 1 つ以上。company_only の受注は参加者の端末・人を含む工程を除く。
  4. 実行（担当: Work）— 合格条件: 各工程の成果が次の工程の入力型に合う。
  5. 検収（担当: Jev）— 合格条件: 顧客と合意した検収項目が全て真。結果を planner の実績へ足す。
  6. 納品（担当: 本人）— 合格条件: 本人が送信し、顧客の受領を記録。
  7. 分配の計算（担当: Wallet）— 合格条件: `settleCompanyOrder` の各行の合計 ＝ 入金額。
- Jevの合格条件: 検収項目の真偽、入力型の一致、分配合計と入金額の一致（差 0）、同じ寄与IDの重複 0。
- 出力先: スマホ・Pro の画面（受注、残っている本人の作業、分配の内訳）/ ファイル（納品物）。
- Wallet: 費用＝販売先の手数料と外部の実費（会社）/ 作業料＝単価×検収量（参加者へ）/ 配当＝入金済み余剰の一部を等分 / 既存の earnings 天引きとは別の台帳。新しい課金型は作らない。
- hardware profile 依存: phone でも可。全部。
- 失敗時: 検収不合格は 3 へ差し戻し（別の工程を選ぶ）。入金が作業料に足りない時は会社の持ち出しとして表示し、配当は 0。blocked は受けずに理由を本人へ見せる。
- 記録: Receipt に、受注ID、販売先、条件（AI可否・持ち出し可否）、選んだ工程の key、検収結果、寄与ID・参加者・検収量・単価、入金・返金の参照番号。顧客の資料本文は残さない。
- 未実装: 応募・契約・入金確認の自動化、Wallet への記帳、参加者への送金。現金の移動は本人の明示許可が要る（AGENTS.md §6）。
