# 会社の窓口（gig-desk）

- 本人が言う一言: 「この募集、うちで受けられる？」／参加者は「確認の仕事ある？」
- Goal（Eveが作る）: 目的＝会社のアカウント1つで募集に応募し、受注した仕事の確認を参加者へ配る / 入力＝本人が開いた募集ページの文面、会社が売れる仕事の型、参加者の一覧 / 期待成果＝応募する・見送るの判定、額と納品日、提案の下書き、確認の問いの割当、作業料の寄与 / 予算上限＝1日の提案数（初期値5）/ 要る権限＝文面の読み取りだけ。送信・契約・納品は本人。
- Noaがつなぐもの: lib/sky-gig-desk.ts、lib/sky-recipe-planner.ts、lib/sky-company-order.ts。実行例は `node --experimental-strip-types scripts/sky-gig-desk.mjs examples/sky/gig-desk/desk.json`。
- AMCの工程:
  1. 読む（担当: Noa）— 合格条件: `parseCoconalaPosting` が題名を返す。取れない項目は null のまま。
  2. 決める（担当: AMC）— 合格条件: `triageGig` が propose か、理由つきの skip を返す。AI不可の募集、予算・納期・応募人数が合わない募集、作る工程が無い募集は skip。
  3. 選ぶ（担当: AMC）— 合格条件: `selectProposals` の send が1日の上限以内で、同じ募集を二度含まない。
  4. 下書き（担当: Eve）— 合格条件: 額・納品日・納品物・AIを使うこと・人が確認することが文面にある。`submission === 'owner_only'`。
  5. 送信（担当: 本人）— 合格条件: 本人が自分の手で送った記録。
  6. 受注後の確認を配る（担当: AMC）— 合格条件: 1つの問いを同じ人に二度渡さない。資料を外へ出せない受注は会社の管理下の人だけ。
  7. 答えをまとめる（担当: Jev）— 合格条件: 過半数がそろった問いだけ結論。割れた問いは会社の人へ。
- Jevの合格条件: 提案額 ≥ 型の最低額、`checkOrderQuote.acceptable === true`、寄与IDの重複 0、割当外・二度目の答えを数えていない。
- 出力先: スマホ・Pro の画面（今日出す提案、見送った理由、参加者には自分の問いだけ）。
- Wallet: 販売先の手数料（ココナラの通常の販売手数料 22% 税込を初期値）/ 作業料＝確認1件 × 単価、多数側の答えに払う / 分配は company-order と同じ台帳。
- hardware profile 依存: phone でも可。全部。
- 失敗時: 割れた問いは会社の担当者が見る。人数が足りない問いは short として表示。採用されない型は採用率が下がり、得にならなくなった時点で提案が止まる。
- 記録: Receipt に、募集ID、判定と理由、提案額、送信の記録、問いID・答えた人・結論。募集の本文と依頼者の名前は残さない。
- やらないこと: ココナラへの自動ログイン・自動巡回・自動応募・自動返信、参加者の個人アカウントの操作、複数アカウントの作成。理由は [sky-work-loop.md §7](../sky-work-loop.md)。
- 未実装: 画面と保存（[task 35](../../codex/tasks/35-gig-desk-screen.md)）、Eve による文面の仕上げ、参加者の携帯へ問いを届ける経路。
