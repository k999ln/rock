## 組み合わせファイル（eve-combination/1）

工程は `NoahStep` をそのまま使い、次を足す。`agent`（Noah のエージェントの id と版の hash、道具の名前、入力の作り方）、`fallback`（差し替えの候補）、`accept`（Jev が機械で判定できる工程の合格条件）、`code`・`tests`（つなぎ目の変換）、`exit`（お金の出口。必須。外部の記録だけを数える）、`budget`、`keepForSelf`、`author`。直す時は新しい版を作る。

### 検査の規則（決まった式。LLM は使わない）

1. `noahBlueprintWaitProblem` が問題なしを返す。
2. どの素材も、手元にある物か前の工程の出力。同じ素材を 2 回出さない。成果に使われない工程が無い（棚の `chain` の規則と同じ）。
3. 最後の工程が `exit` の素材を出し、`exit` の元が外部の記録。
4. auto の工程は、能力を確かめたエージェントか、固定テスト付きのつなぎ目の変換だけ。確かめていない物がある組み合わせは、試運転だけができる。
5. tap・human・review の工程は理由を持つ。登録の工程の前に「規約と登録の要件を確かめる」がある。
6. 金融の分野は、ノエルが確かめる review の工程を持つ。
7. 費用の合計が `budget` の内側。
8. どの `agent` にも版の hash がある。
9. 鍵・パスワード・口座の番号を書かない。要る鍵は接続要件の `services` で名前だけを指す。

## 3 つの作り方

手で書く（JSON か TypeScript の `defineCombination()`）→ 自動の探索（Noa。学習も LLM も使わない）→ Eve に話す（LLM。探索が gap を返した所だけ）の順に作る。どれも同じファイルになり、同じ検査と試運転を通る。Eve が作る部品は Eve のビルドを通し、試運転に通った物だけを `verified` に入れる。LLM は、本人の許可までは手元の Qwen（外部の有料モデルへ自動で切り替えない）。
