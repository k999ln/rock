# Noah — 大量の取り込み（口・名寄せ・接続試験・見回り）

- 本人が言う一言: 「まず自社 agent よりも agent を大量に扱うところから始めよう」（11-20）「ここにあるものまず全て noah の agent として入れて」（11-15）
- Goal（Eveが作る）: 目的＝外にある Agent を、1 件ずつ手で作らずに、つながると確かめた状態で並べる / 入力＝公開の台帳（MCP、Hugging Face、ACP）、今の調査台帳 / 期待成果＝系列ごとのカード、接続要件、接続試験の記録、見本 / 予算上限＝巡回の回数と月の上限（運営） / 要る権限＝公開情報の読取。鍵の要る接続先と、読み取りだけと宣言されていない道具は呼ばない
- Noaがつなぐもの: `data/noah-research-index.json`（今の調査台帳。残す）、今の発見（[noah-agent-discovery.md](noah-agent-discovery.md)。`lib/noah-discovery-provider.ts`、`lib/noah-discovery-store.ts`）、`lib/mcp-inspection.ts`、`lib/mcp-client.ts`、`lib/a2a-client.ts`、接続要件 `noah-connect/1`、接続計画、専用の端末（[noah-own-device.md](noah-own-device.md)）、Spider、Work
- AMCの工程:
  1. 取り込む（担当: Spider）— 合格条件: 出どころの URL・取得時刻・元の記録の hash を持つ。
  2. 名寄せ（担当: Noa）— 合格条件: 同じ提供者の量産・教材のコピー・版違いが 1 系列になる。1 系列が 1 枚のカード。
  3. 見分ける（担当: Noa）— 合格条件: 何も実行せずに、口・面・要る鍵・相手の許可の要否を決め、接続要件を下書きする。
  4. 確かめる（担当: Jev）— 合格条件: L1 は握手と道具の一覧。L2 は見本の入力で 1 往復。
  5. 載せる（担当: AMC）— 合格条件: L1 以上。日本語の 1 行説明、作者、出どころ、接続の手数。
  6. 見回る（担当: Spider）— 合格条件: 期限内に確かめ直した。通らない物の印を外した。
  7. 引き取り（担当: Broker）— 合格条件: 台帳の名前空間の持ち主だと確かめた本人だけが、説明・価格・取り下げを操作できる。
- Jevの合格条件: 台帳の文章から作ったコマンドの実行 0 件。鍵の要る接続先への自動の呼び出し 0 件。読み取りだけと宣言されていない道具の自動の呼び出し 0 件。寝ている Space を起こした件数 0。1 接続先への握手は 1 巡回に 1 回以下。L2 が通っていない系列のタイムライン表示 0 件。同じ系列の重複カード 0 件。私設アドレスへの接続 0 件。道具の定義が変わった後の、聞き直し無しの実行 0 件。取り下げの申し出から 24 時間（候補）を越えて残る掲載 0 件。引き取り前の課金 0 件。
- 出力先: Noah のタイムライン・検索・一覧、運営の集計（つながると確かめた数）。phone でも可。
- Wallet: 取り込みと握手はほぼ 0。道具を持つ担当はモデルの費用（1 回 約 $0.001）。無料枠と本人の月の上限で止める。取り込んだ Agent は引き取るまで無料。新しい課金型は作らない。
- hardware profile 依存: 全部（Web）。
- 失敗時: 取得の失敗は前の記録を保ち、次の巡回でやり直す。握手の失敗は理由（応答なし・許可が要る・版が合わない）を分けて残す。回数制限に当たったら、その出どころを止めて知らせる。
- 記録: 系列、出どころ、口、面、接続要件の hash、道具の定義の hash、L1・L2 の時刻と結果と秒数、巡回の回数。見本以外の入力と成果の本文は残さない。

## 口

1 件ずつ実行器を書かない。つなぎ方ごとに 1 つ作る。件数は 2026-11-20 の実測（[noah-agent-census-20261120.md](../noah-agent-census-20261120.md)）。

| 口 | 届く数 | 動く所 | 起動の作り方 |
| --- | --- | --- | --- |
| `mcp-remote` | 45,668。鍵なしで応答する host は約 1 万 7 千 | 提供者 | 台帳の URL へ接続。握手は最新の版（2025-11-25）を名乗り、断られたら 2025-06-18 で 1 回だけ試す。2024-11-05 を返す相手（1.5%）も受ける |
| `space-mcp` | 動いている 4,275 の約 82% | 提供者 | `/gradio_api/mcp/` と定義の取得。動いている物だけ |
| `acp` | 46 | 専用の端末 | 台帳の配布（npx・uvx・binary の URL と hash）を固定の型紙へ入れる |
| `mcp-package` | 25,063。鍵なし 12,649 | 専用の端末（雲） | 台帳の識別子と版を、種類ごとの固定の型紙へ入れる（npm・PyPI・OCI・MCPB） |
| `a2a` | 標本の 7.8% の host | 提供者 | カードを読む。0.3 系と 1.0 |
| `source` | 残り | 専用の端末 | Eve のビルド（[eve-agent-build.md](eve-agent-build.md)） |

- 起動に使えるのは、台帳の型の付いた項目だけ（配布の種類・識別子・版・引数・環境変数の名前）。README と説明文は使わない（`lib/noah-execution-contract.mjs` の決まり）。型紙は口ごとに運営が審査して固定する。
- 相手の許可（OAuth）: 保護された資源の公開情報 → 認可サーバー → client の登録（client 文書を先に試し、無ければ動的登録）→ PKCE。token は Broker が持ち、道具を持つ担当へは渡さない。

## 道具を持つ担当

道具だけの接続先を、1 文で頼める形にする Noah の基盤。自社の Agent ではない。

- 入力は本人の 1 文。その接続の道具の定義をモデルへ渡し、道具を選んで呼び、成果を返す。上限は `LIMITS`（モデル呼び出し 8 回、出力 2,048 トークン、240 秒）。
- 1 回の仕事で使う接続先は 1 つ。本人が組み合わせた時だけ複数。別の接続の成果や記憶を渡さない。
- 道具の説明は信用しない。モデルへの指示として読ませず、道具の定義の枠にだけ入れ、長さを切る（候補: 1 道具 1,024 文字、合計 32KB。標本の 90 パーセンタイルは 38KB）。
- 道具の定義の hash を Passport に固定する。変わったら実行を止め、差分を見せて聞き直す。
- 読み取りだけと宣言されていない道具の呼び出しは、最初の 1 回、本人に確かめる（道具の名前と入力を見せる）。外部への書き込みと金融は Broker の既存の確認。
- 道具が 1 つで必須の入力が 2 個以下なら、モデル無しの入力欄でも使える。
- 提供者へ送る物を、接続の時に 1 行で見せる。

## 接続試験と表示

| 深さ | やること | 自動でやってよい条件 |
| --- | --- | --- |
| L0 | 台帳の項目の検査だけ | 常に |
| L1 | 握手と道具の一覧 | 公開の接続先。1 巡回に 1 回 |
| L2 | 見本の入力で 1 往復 | 鍵が要らない。全部の道具が読み取りだけと宣言されている。入力を定義から埋められる。それ以外は、最初に使った本人の実行を L2 として数える |

- タイムラインに流すのは、L2 が 7 日以内に通った系列だけ。検索と一覧には L1 の物も出し、「まだ誰も動かしていない」と書く。L0 は今の調査一覧のまま。
- 見回りの間隔は使われ方で決める（候補: 使われている物は毎日、L1 だけの物は週 1 回）。30 日応答が無ければ隠す。
- 数えるのは「つながると確かめた数」。台帳の行数を成果にしない。

## 礼儀と取り下げ

巡回は名乗りと連絡先を出す。回数制限を守る（Hugging Face の Hub は未ログインで 5 分 500 回）。Space の GPU の枠は本人のログインで使う物なので、運営の巡回で消費しない。作者・提供者の「外してほしい」を受ける窓口を置き、掲載と巡回を止める。規約と商標の確認は設計書 10 章。

## 保存と API

- 取り込みの記録は、**別の表**に置く（`noah_intake_sources`・`noah_intake_candidates`・`noah_intake_checks`・`noah_intake_families`・`noah_probe_hosts`。DDL は [docs/contracts/noah-v1.sql](../contracts/noah-v1.sql)）。今の発見の表は、出どころを `github`・`huggingface` に限る CHECK を持ち（SQLite は CHECK だけを変えられない）、鍵がリポジトリで、上限が 10,000 件なので、足さない。巡回の作り（lease・内容 hash・取り下げ）は発見にならう。既存の行の意味は変えない。
- 候補の ID は `出どころ:鍵`（例 `mcp-registry:ac.mizan/registry`）。口・面・接続要件の下書き・接続試験の結果は `noah_intake_checks`、系列・引き取り・取り下げは `noah_intake_families`。1 件がどの列になるかは [実装仕様書 85](../noah/spec-85-intake.md)。
- 一覧は今の候補の API に、口・深さの絞り込みを足す。`POST /api/noah/intake`: `{ action: "claim" | "withdraw" | "restore" | "recheck", id, revision }`（系列の ID は `/` を含むので、パスに入れない）。同一 Origin と ownerScope が必須。
- 巡回は今の発見の経路（`scripts/noah-discovery-daemon.mjs`）と同じ置き方で動かす（空の `POST /api/noah/intake` 1 回で、期限の来た分を上限つきで進める。台帳は 1 回に 10 頁まで）。握手は 1 回に 8 件、同じ host へは 1 時間に 1 回まで。

## ローンチの範囲（2026-11-20。本人指示「ローンチするのに最小限」）

出すまでに作るのは、[ローンチの最小限](../noah/mvp-launch.md) の線の内側だけ。このシートのうち、次の所。

| このシートの節 | ローンチまで | 出した後 |

| 道具を持つ担当 | 入力欄で頼む（道具を選ぶ画面つき。モデルを使わない。[仕様書 87](../noah/spec-87-tool-agent.md) の 11 章） | 1 文で頼む |
| 接続試験と表示 | 握手まで（L1）と、本人の実行で付ける「動いた」（L2）。一覧は 2 段（[仕様書 88](../noah/spec-88-mass-probe.md) の 9 章） | Noah が自動で道具を呼ぶ見本 |

| 保存と API | 取り込みの 5 表、`noah_connections`、`noah_asks`。巡回は、専用の Worker の毎分の合図で動く（手元の daemon ではなく）。合図の終わりに、途中で落ちた依頼と、つなぐ途中で止まった接続を片付ける（相手へは送らない。[仕様書 88](../noah/spec-88-mass-probe.md) の 9.5） | 相手の許可の 3 表、鍵の表、継続運用、利用の記録 |
