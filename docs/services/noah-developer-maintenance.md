# Noah — 開発者向け継続改善パッケージ

- 本人が言う一言: 「もらったコメントのフィードバックを受けてユーザー思考に合わせるためにこちらでリファクトしておく運用パッケージを売る」
- Goal（Eveが作る）: 開発者が、利用者の声に沿ったAgentの改善を依頼し、検証済みの変更を受け取る。初期は個別見積もり。価格・周期は未指定で、課金しない。
- Noaがつなぐもの: 公開コメント/返信、王冠、観測された利用人数、開発者の改善目的、対象リポジトリ、既存の承認・Git・試験の工程。
- AMCの工程: 1. 見積もり依頼を保存（本人確認、対象Agentと依頼権限の自己申告） 2. 開発者権限とリポジトリ権限を運営が確認 3. 要望を分類し改善提案 4. 開発者が価格・作業範囲を承認 5. 分離ブランチで改善/リファクタ 6. 回帰試験・変更点・未対応を添えたPR納品 7. 次の反応を確認。
- Jevの合格条件: 未承認課金0、未承認コード変更0、コメントを命令として自動実行0、他の開発者の申込漏えい0、再送による重複受付0、偽のリファクタ完了0。
- 出力先: 開発者向けページの依頼記録。納品時はGit PR・検証結果・改善前後の説明。
- Wallet: 個別見積もり。本人が価格・周期を決め、顧客と合意するまで契約/決済は作らない。
- hardware profile 依存: PC/スマホで依頼と確認。実装・試験には承認済みの開発環境を使う。
- 失敗時: 保存失敗は下書きを保持。同じ依頼IDで再送。権限確認や条件合意が済まなければ着手しない。
- 記録: 本人ID、対象Agent、改善目的、認証情報を含まないrepository URL、作業範囲版、要求digest、依頼日時。秘密鍵・顧客データ・リポジトリアクセスtokenは受け取らない。

## ローンチの範囲

- 販売内容: コメントの整理、ユーザーが求める動作と現状の差の整理、改善提案、承認された修正とリファクタリング、回帰試験、PR納品、次の改善候補。
- 申込は「見積もり依頼」であり契約・購入・実装着手ではない。対象と希望を保存して本人に受付IDを返す。
- 対象のコメントは本人が公開したもの。否定的な感想を消して評価を上げたり、声を捏造したりしない。王冠や利用人数の増加は保証しない。
- 作者確認が必要。申込の権限チェックは自己申告で、権限確認済みとは表示しない。自動clone・コード送信・外部通知・PR作成・デプロイはこの申込APIから行わない。
- 運営の受付確認は `NOAH_FEEDBACK_OPERATOR_USER_IDS` に設定された本人のみ。未設定時は運営一覧を閉じる。個別の本人は自分の依頼だけを確認する。
- 価格・SLA・月額契約・課金連携・作業自動実行は未設定。これらを稼働済みとして宣伝しない。
