# Noah — 開発者向け継続改善パッケージ

- 本人が言う一言: 「もらったコメントのフィードバックを受けてユーザー思考に合わせるためにこちらでリファクトしておく運用パッケージを売る」
- Goal（Eveが作る）: 開発者が、利用者の声に沿ったAgentの改善を依頼し、検証済みの変更を受け取る。初期は個別見積もり。価格・周期は未指定で、課金しない。
- Noaがつなぐもの: 公開コメント/返信、王冠、観測された利用人数、開発者の改善目的、対象リポジトリ、既存の承認・Git・試験の工程。
- AMCの工程: 1. smash@avoado.siで相談メールを受信 2. 開発者権限とリポジトリ権限を運営が確認 3. 要望を分類し改善提案 4. 開発者が価格・作業範囲を承認 5. 分離ブランチで改善/リファクタ 6. 回帰試験・変更点・未対応を添えたPR納品 7. 次の反応を確認。
- Jevの合格条件: 未承認課金0、未承認コード変更0、コメントを命令として自動実行0、Webへの相談本文保存0、本人操作なしのメール送信0、偽のリファクタ完了0。
- 出力先: 受付・条件の相談はメール。納品時はGit PR・検証結果・改善前後の説明。
- Wallet: 個別見積もり。本人が価格・周期を決め、顧客と合意するまで契約/決済は作らない。
- hardware profile 依存: PC/スマホで依頼と確認。実装・試験には承認済みの開発環境を使う。
- 失敗時: メールの作成・送信状態は本人のメールアプリで確認し、Webは受付済みと表示しない。権限確認や条件合意が済まなければ着手しない。
- 記録: 対象Agentと相談内容は本人がメールで送る。NoahのWebフォームやDBには新規保存しない。秘密鍵・顧客データ・リポジトリアクセスtokenを求めない。

## ローンチの範囲

- 販売内容: コメントの整理、ユーザーが求める動作と現状の差の整理、改善提案、承認された修正とリファクタリング、回帰試験、PR納品、次の改善候補。
- 受付先は本人指定の smash@avoado.si。案内ページの「メールで相談する」は件名と対象Agentを添えたメール作成リンク。契約・購入・実装着手ではなく、自動送信や受付IDの発行をしない。
- 対象のコメントは本人が公開したもの。否定的な感想を消して評価を上げたり、声を捏造したりしない。王冠や利用人数の増加は保証しない。
- 作者・リポジトリ権限は相談後に確認。メール作成だけで権限確認済みとは扱わない。自動clone・コード送信・外部通知・PR作成・デプロイは行わない。
- Webの申込フォーム・受付履歴・運営一覧を廃止。旧maintenance GET/POSTは410を返し、既存記録を公開・変更しない。既にコミットしたSQLと表は保持するが、新規受付には使わない。
- 価格・SLA・月額契約・課金連携・作業自動実行は未設定。これらを稼働済みとして宣伝しない。
