# Noahの提供元API実行
- 本人が言う一言: 「Agentを選んだら、実行から成果の受け取りまで」
- Goal: 選んだ公開Agentへの依頼をNoahで受け付け、進捗と成果を本人の保存先に残す。Noah側の追加実行課金は0。外部の有料・認証APIには進まない。
- Noaがつなぐもの: 既存MCP経路と、公式Hugging Faceメタデータで照合した公開Gradio API。掲載リポジトリやパッケージも公式定義を探索し、公開MCPがあればNoahで実行する。
- AMCの工程: 公開API定義の取得→本人が入力/送信先を確認→Work受付→送信を1回→実行番号を保存→結果の照会→成果保存。
- Jevの合格条件: 同じ依頼IDの同時/再送で外部POSTは1回。別所有者から参照/停止不可。変更されたAPI定義で実行しない。停止後の成果で上書きしない。完了前の中間データを成果扱いしない。提供元エラーは理由付きで保存。結果通信は1本を最大10分維持し、保存済み成果は再表示できる。通信中断は結果不明にし、自動再実行しない。
- 出力先: スマホの既存「実行中」「保存」「仕事詳細」。文字とJSON、検査済み画像を保存する。
- Wallet: Noah側の追加課金0。HTTP 402は停止し、支払を自動で行わない。
- hardware profile依存: スマホとWeb。推論は提供元、受付・照会・保存はNoah Worker。
- 失敗時: 認証・混雑・GPU上限・対応外・結果不明を分けて本人へ返す。送信後に実行番号を失った場合は再送しない。
- 記録: 既存Workに本人scope、Agent、API定義hash、実行番号、状態、成果を保持。提供元の成功応答を本人の検収済みにしない。
- 実行上限: 公開API入力は16KB、同時3件、毎分6件/本人、毎分12件/提供元、1日100件/本人。応答は1MiB、画像総量512KiB、30分で未取得を結果不明にする。成果を受け取るまで仕事詳細を開いておく。閉じた後の長時間実行は保証せず、巡回は期限超過を結果不明へ収束する。
- 対応範囲: Gradio 4以降の名前付き公開API。文字・数値・真偽値・単一選択を入力できる。履歴の空配列と未添付ファイルnullは既定値として扱い、任意URLやファイルパスの送信は許さない。複雑な必須入力は対応外と表示する。
- API契約: [Gradio公式](https://www.gradio.app/guides/querying-gradio-apps-with-curl)。API受付と結果SSE取得を分離し、中間結果・完了・エラーを区別する。

## 掲載全体からの接続（2026-11-22）
GitHubのserver.json、npmのmcpNameと公式台帳の同一パッケージ/版、Docker公式台帳の固定commitから提供元を照合する。Hugging Face出典は全出典から探し、先頭のGitHub URLだけでCLI扱いしない。集約記事のURLを実行先にはしない。固定commitのmonorepoディレクトリにも対応する。
公開Streamable HTTP MCPの初期化とtools/listから単純入力フォームを作る。文字・数値・真偽値・選択・リストを扱い、必須秘密情報や未対応の複雑な入力は送らない。送信前の再初期化でtool全体hashが変わったら実行を止める。POST応答を実行と保存まで維持し、受信不明なら同じIDの受付だけを確認する。再送でtools/callを増やさない。
受入: 実SQLiteで別所有者・同じID・定義変更・直前停止・応答消失・保存再読込を検査する。ブラウザ320/390/1280pxで入力・タップ・通信中断・同じ受付確認・成果再表示を検査する。実公開MCPの処理成功は個別に記録し、全掲載の実行済みと扱わない。追加migrationなし。
