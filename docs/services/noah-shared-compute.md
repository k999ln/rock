# Noahの参加型計算サービス

状態（2026-11-27）　月額契約、別アカウントの端末への配分、固定モデルの推論と検収を実装。Android 11のエミュレーターで隔離したプロセスの分類と同意・給電・停止の操作を検証した。一般向けの課金開始と携帯実機での受入は未実施。

- 本人が言う一言: 「利用者の意思で利用者の計算資源を使う」「毎月クラウド代を取る」「他の利用者の処理にも提供する」
- Goal（Eveが作る）: 目的＝同意した端末の余力でAgentの計算を分担する / 入力＝仕事の固定版、許可済み入力、端末能力、同意版、上限 / 期待成果＝本人へ返す検収済み結果と利用明細 / 予算上限＝本人と運営の予約枠 / 要る権限＝端末資源の提供と、依頼者のデータ送信先の明示同意。
- Eveがつなぐもの: 既存Sky接続計画、Work/Job/Receipt、Broker、Wallet、Noah runnerのlease・heartbeat、固定版のモデル実行。新規Agent: 端末能力を検査して隔離された計算だけを実行する参加runner。既存の本人専用runnerを他人へそのまま開放しない。
- AMCの工程:
  1. 参加受付（担当: 接続管理）— 提供者が端末ごとに用途・時間・電力・通信・停止を確認し、明示的に参加した記録がある。
  2. 依頼受付（担当: Broker/Wallet）— 依頼者が参加端末を実行先に選び、対象データの取扱いと予算上限を確認している。
  3. 配分（担当: AMC）— 対応する能力・空き資源・許可されたデータ分類の仕事だけをleaseで割り当てる。
  4. 実行（担当: 参加runner）— 固定版の隔離された計算だけを行い、設定された上限で停止する。
  5. 検収（担当: Jev）— 期待成果・独立した再計算やサンプル照合・実行証拠を確認し、自己申告の完了をそのまま合格にしない。
  6. 照合（担当: Wallet）— 同じ仕事の結果と計測を1回だけ計上し、料金条件が確定した項目だけを明細へ出す。
- Jevの合格条件: 未同意端末の実行0件、未承認の第三者への入力送信0件、本人のファイル/認証情報へのアクセス0件、別仕事への残存データ読出0件、同一Receipt再送による二重計上0件。停止後の新規割当0件、取消しの受信から計算停止まで5秒以内を受入目標とし、未達端末は参加不可。隔離・停止・資源上限・出力検証を実機で通すまで課金対象にしない。
- 出力先: Noahのスマホ/PC画面で成果と実行先を表示。提供者の端末には他人の会話履歴や成果一覧を表示しない。
- Wallet: 既存の月額契約を用いる。支払者＝サービス契約者、受取先＝契約に明示する運営主体。金額・含まれる件数・契約主体は未確定。初期実装は税込の月額固定、無料期間・超過課金・提供者還元なし。課金と提供同意は別。既存Agent作者分や定期便の率は変更しない。
- hardware profile 依存: phoneも検討するが、対応判定は端末/OS/モデルごと。ブラウザーを閉じた携帯で常時計算できる前提は置かない。CPU/GPU/メモリー・熱・空き容量・中断復帰の実機測定を行う。
- 失敗時: 取消し・端末離脱・期限切れは結果不明としてAMCへ返す。確認できない完了を請求・還元に使わない。別端末や管理クラウドへの切替は同意済みの送信先・予算の範囲内だけ。外部への副作用を伴う仕事は自動再実行しない。
- 記録: Receiptには仕事ID、モデル/実行物のhash、同意版、実行先の種別と匿名化した端末識別子、lease、開始/停止、計測、独立検収、照合IDを記録。中央の計測ログには会話本文や入力内容を入れない。保持期間と開示範囲は契約前に確定する。

## 契約と同意

月額利用契約と端末提供同意を別操作にする。初期値は不参加。「参加する」は自動で月額契約を結ばず、「契約する」は自動で端末を提供しない。提供を止めても月額契約が残る場合、その条件と解約操作を同じ画面に示す。端末提供の停止は即時に受け付け、月額解約に依存させない。範囲を広げる時は改めて同意を得る。

料金名は実態に沿った「Noah月額利用料」を案とし、何に払うかを記載する。端末で計算する部分を管理クラウドで計算したように表示しない。電気代・通信量・発熱・電池への影響、他人の処理を実行すること、提供者の還元が未設定であれば還元を約束しないことを申込前に表示する。

## 初期実装の境界

- 提供条件は初期案として充電中・従量課金でない回線・端末が低電力/高温でない時に限定。時間帯、CPU/GPU、メモリー、保存容量、通信量の上限と一時停止を用意する。条件を測れない端末では有効化しない。
- 最初は公開データ/合成データの固定推論だけ。秘密鍵・認証トークン・私的な会話・健康等の機微情報を参加端末へ配らない。提供者の同意は、仕事を頼む本人のデータ送信同意の代わりにはならない。
- 通信の暗号化やプロセス隔離だけでは、端末管理者から処理中の平文を隠せない。機密計算の保証を表示しない。私的データは管理クラウドか本人端末に留める。
- 任意コード、ブラウザー操作、端末の共有フォルダー、利用者のアカウント、自由な外部通信を仕事へ渡さない。モデル配布と用途のライセンスも版ごとに検査する。
- リース取消し・端末離脱・停電・熱停止・更新時の破棄と再配分、偽の性能/完了報告、結果改ざん、同意撤回の競合を試験する。Jevの独立検収とWalletの照合を省かない。
- 契約額・枠・請求名義、将来の還元、正式な契約文と記録の保持期間は運用開始前に確定する。既存のEveチャットはクラウド計算＋端末履歴保存で先に提供する。

## 実装前に確認した制約

AppleのBackground Tasksは実行をOSが管理する。端末を閉じて常時稼働する保証には使わない。[Apple公式](https://developer.apple.com/documentation/backgroundtasks)
Android WorkManagerは充電・回線・電池等の条件を指定でき、条件が崩れると停止する。[Android公式](https://developer.android.com/develop/background-work/background-tasks/persistent/getting-started/define-work)
これらはOSの機能確認であり、本サービスが各端末で動いた証拠ではない。

## 利用者が行う操作

1. Noahの「操作の設定 → 参加型計算」からアカウントでログインする。依頼者は税込の月額料金・件数・請求元を確認し、明示的に同意してStripe Checkoutで契約する。
2. 入金を照合すると期間内の利用枠が開く。依頼者は公開されている英文を入力するか、用意された例文を選ぶ。ブラウザーが公開辞書に一致する単語を4組に分けて数える。参加端末へ渡す4個の数値（各0〜15）を画面で確認し、送信に同意して依頼する。結果と検収記録は本人の一覧に戻る。
3. 提供者は自分のアカウントから端末ごとに登録する。Webに一度表示したキーをAndroidの参加アプリかLinuxの専用プログラムに入力し、その端末で開始する。提供者の契約は不要。初回の対応処理は会議・在庫・研究の3分類。自分の公開英文のほか、同梱の4件の例文でも試せる。会話履歴・任意のプログラム・外部URLを扱う機能はない。
4. 参加プログラムを閉じると、その端末のセッションが終わる。Webの「この端末の提供を停止」は登録キーを無効にする。「登録情報と任せる範囲」で委任を停止した場合も、それまでの依頼・提供資格は停止する。再開には新しい依頼または端末登録が必要。月額の「次回からの自動更新を停止」は支払済み期間の終了時に適用される。

LinuxはNode.js 22以降、NetworkManager、iproute2、power-profiles-daemon、電源とCPU温度の読み取りに対応する端末で利用する。Androidは11以降の画面を開いている間に限り、電源・従量制でない回線・低電力モード・温度を確認する。セッションは最大15分、30件、アプリの通信量256 KiB。分類モデルと辞書は配布時に固定する。サーバーは例文IDまたは範囲内の4個の数値だけを受け取り、入力した本文は保存・送信しない。辞書への一致が0件なら依頼の前に表示する。サーバーはモデルの版とハッシュ、短いリース、現在も有効な契約期間・同意を確認し、結果を再計算して一致した1件だけを月の利用枠に計上する。

## 月額の設定

契約・端末登録画面は `/noah/shared-compute`。料金条件を設定するまでは申込みを閉じる。Stripeは税込・固定単価の月次Priceを使う。無料期間と自動超過課金は設けず、提供者への還元も設定しない。新しい価格と既存契約の条件は別々に保持する。

| 設定 | 内容 |
| --- | --- |
| `NOAH_COMPUTE_BILLING_MODE` | `test` または `live`。未設定なら新規受付停止 |
| `NOAH_COMPUTE_TEST_` または `NOAH_COMPUTE_LIVE_` に続く設定 | `STRIPE_ACCOUNT`、`STRIPE_KEY`、`WEBHOOK_SECRET`、`PRICE_ID`、`AMOUNT_MINOR`（最小通貨単位）、`CURRENCY`（JPY、USD、EUR）、`MERCHANT`、`MONTHLY_JOBS`、`TERMS_VERSION` |
| `NOAH_COMPUTE_LIVE_DEVICE_ACCEPTANCE` | 対応端末で隔離、資源上限、撤回、検収を受け入れた後に運用側が `approved` を設定する |

契約発行先のStripeアカウント、モード、価格、請求と入金を検証する。署名済みWebhookは `POST /api/noah/shared-compute/plan/webhook`。Checkoutの完了・非同期決済・期限切れ、Subscriptionの変更、Invoiceの入金・失敗・無効化・回収不能、返金・異議申立て・早期不正警告のイベントを受ける。キーは環境ごとの秘密設定に置く。再送・順序逆転時は現在の決済状態を再取得する。契約・実行の追加テーブルは `0062_noah_shared_compute` と `0063_noah_compute_subscriptions`。本番D1への適用、決済サービスの設定、実機受入は別途行う。

動作確認には `node --experimental-strip-types --test tests/noah-compute-subscriptions.test.mjs tests/noah-shared-compute-queue.test.mjs tests/noah-shared-runner.test.mjs` を使う。決済事業者の応答を模擬し、2アカウントでの依頼・配分・端末推論・検収・更新終了を実際のAPI処理で検証する。

## Eveの組み合わせを試す

1. 運営者は本人が管理する依頼用・端末提供用の2アカウントを指定する。各アカウントで `/noah/shared-compute` にログインして試験用IDを確認する。`NOAH_COMPUTE_PILOT_OWNER_SCOPES` にはその2件をカンマ区切りで、`NOAH_COMPUTE_PILOT_UNTIL` にはUTCの終了時刻（YYYY-MM-DDThh:mm:ssZ）を設定する。期限内は1アカウント30件まで無料。Stripe契約は不要。
2. 提供用アカウントでEveの工程に同意し、新しく端末を登録する。Linuxは同じフォルダーに `runner.mjs`、`model.json`、`eve-agents.mjs` を置き、`node runner.mjs --device <端末ID> --eve` を起動する。Androidは対応する参加アプリでEveの工程を選ぶ。アプリに表示された条件を満たした時間だけ受け付ける。
3. 依頼用アカウントで `/noah/engineering` を開く。Eveが提案した引用一覧・無料記事の工程は掲載順に、CSV整理は表データで実行できる。各依頼で参加端末に渡す公開入力（UTF-8で最大4,096バイト）を確認する。記事のURL・価格は生成原稿に記載する情報。会話履歴は送信対象に含めない。
4. 検収済みの成果と実行した工程を依頼者が確認する。公開原稿を扱うため、提供者には入力が読める。依頼の完了・取消時に待ち行列の原稿を消去する。受付後15分を過ぎた入力は配分対象から外れ、キュー利用時または定期処理時に原稿を消去する。

`0064_noah_eve_participant` が入力の有効期限と検収済みの結果を管理する。参加者による実機受入を終えて有料提供する場合は、既存の料金契約・実機受入設定に加えて `NOAH_COMPUTE_LIVE_EVE_ACCEPTANCE=approved` を設定する。
