# Noahの参加型計算サービス

状態: 2026-11-27 本人指示に基づく設計。端末への実装・配信・実仕事の配分・契約・課金は未開始。

- 本人が言う一言: 「利用者の意思で利用者の計算資源を使う」「毎月クラウド代を取る」「他の利用者の処理にも提供する」
- Goal（Eveが作る）: 目的＝同意した端末の余力でAgentの計算を分担する / 入力＝仕事の固定版、許可済み入力、端末能力、同意版、上限 / 期待成果＝本人へ返す検収済み結果と利用明細 / 予算上限＝本人と運営の予約枠 / 要る権限＝端末資源の提供と、依頼者のデータ送信先の明示同意。
- Eveがつなぐもの: 既存Sky接続計画、Work/Job/Receipt、Broker、Wallet、Noah runnerのlease・heartbeat、固定版のモデル実行。新規Agent: 端末能力を検査して隔離された計算だけを実行する参加runner。既存の本人専用runnerを他人へそのまま開放しない。
- AMCの工程:
  1. 参加受付（担当: 接続管理）— 提供者が端末ごとに用途・時間・電力・通信・停止を確認し、明示的に参加した記録がある。
  2. 依頼受付（担当: Broker/Wallet）— 依頼者が参加端末を実行先に選び、対象データの取扱いと予算上限を確認している。
  3. 配分（担当: AMC）— 対応する能力・空き資源・許可されたデータ分類の仕事だけをleaseで割り当てる。
  4. 実行（担当: 参加runner）— 固定版の隔離された計算だけを行い、設定された上限で停止する。
  5. 検収（担当: Jev）— 期待成果・独立した再計算やサンプル照合・実行証拠を確認し、自己申告の完了をそのまま合格にしない。
  6. 照合（担当: Wallet）— 同じ仕事の結果と計測を1回だけ計上し、料金条件が確定した項目だけを明細へ出す。
- Jevの合格条件: 未同意端末の実行0件、未承認の第三者への入力送信0件、本人のファイル/認証情報へのアクセス0件、別仕事への残存データ読出0件、同一Receipt再送による二重計上0件。停止後の新規割当0件、取消しの受信から計算停止まで5秒以内を受入目標とし、未達端末は参加不可。隔離・停止・資源上限・出力検証を実機で通すまで課金対象にしない。
- 出力先: Noahのスマホ/PC画面で成果と実行先を表示。提供者の端末には他人の会話履歴や成果一覧を表示しない。
- Wallet: 既存の月額契約を用いる。支払者＝サービス契約者、受取先＝契約に明示する運営主体。金額・税込/税別・含まれる枠・超過条件・無料期間・契約主体・提供者への割引/還元は未確定。自動超過課金なし。課金と提供同意は別。既存Agent作者分や定期便の率は変更しない。
- hardware profile 依存: phoneも検討するが、対応判定は端末/OS/モデルごと。ブラウザーを閉じた携帯で常時計算できる前提は置かない。CPU/GPU/メモリー・熱・空き容量・中断復帰の実機測定を行う。
- 失敗時: 取消し・端末離脱・期限切れは結果不明としてAMCへ返す。確認できない完了を請求・還元に使わない。別端末や管理クラウドへの切替は同意済みの送信先・予算の範囲内だけ。外部への副作用を伴う仕事は自動再実行しない。
- 記録: Receiptには仕事ID、モデル/実行物のhash、同意版、実行先の種別と匿名化した端末識別子、lease、開始/停止、計測、独立検収、照合IDを記録。中央の計測ログには会話本文や入力内容を入れない。保持期間と開示範囲は契約前に確定する。

## 契約と同意

月額利用契約と端末提供同意を別操作にする。初期値は不参加。「参加する」は自動で月額契約を結ばず、「契約する」は自動で端末を提供しない。提供を止めても月額契約が残る場合、その条件と解約操作を同じ画面に示す。端末提供の停止は即時に受け付け、月額解約に依存させない。範囲を広げる時は改めて同意を得る。

料金名は実態に沿った「Noah月額利用料」を案とし、何に払うかを記載する。端末で計算する部分を管理クラウドで計算したように表示しない。電気代・通信量・発熱・電池への影響、他人の処理を実行すること、提供者の還元が未設定であれば還元を約束しないことを申込前に表示する。

## 初期実装の境界

- 提供条件は初期案として充電中・従量課金でない回線・端末が低電力/高温でない時に限定。時間帯、CPU/GPU、メモリー、保存容量、通信量の上限と一時停止を用意する。条件を測れない端末では有効化しない。
- 最初は公開データ/合成データの固定推論だけ。秘密鍵・認証トークン・私的な会話・健康等の機微情報を参加端末へ配らない。提供者の同意は、仕事を頼む本人のデータ送信同意の代わりにはならない。
- 通信の暗号化やプロセス隔離だけでは、端末管理者から処理中の平文を隠せない。機密計算の保証を表示しない。私的データは管理クラウドか本人端末に留める。
- 任意コード、ブラウザー操作、端末の共有フォルダー、利用者のアカウント、自由な外部通信を仕事へ渡さない。モデル配布と用途のライセンスも版ごとに検査する。
- リース取消し・端末離脱・停電・熱停止・更新時の破棄と再配分、偽の性能/完了報告、結果改ざん、同意撤回の競合を試験する。Jevの独立検収とWalletの照合を省かない。
- 端末内モデルの配信方法、OSごとの参加機能、料金と還元、契約文、利用量の保持期間は後続実装の未決事項。既存のEveチャットはクラウド計算＋端末履歴保存で先に提供する。

## 実装前に確認した制約

AppleのBackground Tasksは実行をOSが管理する。端末を閉じて常時稼働する保証には使わない。[Apple公式](https://developer.apple.com/documentation/backgroundtasks)
Android WorkManagerは充電・回線・電池等の条件を指定でき、条件が崩れると停止する。[Android公式](https://developer.android.com/develop/background-work/background-tasks/persistent/getting-started/define-work)
これらはOSの機能確認であり、本サービスが各端末で動いた証拠ではない。
