# Noah — 相談とアフィリエイト運営Agent

- 本人が言う一言: 「相談用と運営用の両方を組み合わせて、Noahに載せれる形にして」
- Goal（Eveが作る）: 悩みに合う解決策の比較と、案件点検・原稿下書き・集計。入力は相談条件、本人が確認した案件台帳、個人情報を含まない集計。新しい課金・外部申込は行わない。
- Noaがつなぐもの: 新規Agent「Web・PC相談」「紹介案件の運営」。既存noah-agent/1 + noah-terminal/1のZIP、および提供者側MCP HTTPの共通処理。
- AMCの工程: 1. 台帳検査（期限・提携・媒体許可・広告リンク） 2. 適合分野で比較 3. 下書きと未確認事項を返す 4. 発生・承認・否認の集計を分ける。外部への公開・送信・申込は工程に含まない。
- Jevの合格条件: 停止・期限切れ・未提携・媒体未確認の紹介リンク出力0、相談応答への非公開報酬漏えい0、報酬変更による順位変更0、無認証の運営MCP呼出成功0。両ZIPのmanifest・entrypoint・固定テスト・成果hashがNoah契約に適合する。
- 出力先: Noahの既存Workへ文章とJSON/Markdownファイル。MCPは既存の接続・入力フォーム・成果受取を使い、新しい主要メニューは作らない。
- Wallet: 今回は課金・支払を追加しない。ASP報酬は外部での承認待ちの情報であり、Wallet残高や入金済みへ昇格しない。
- hardware profile依存: source ZIPは既存の専用実行環境。スマホだけの利用はMCPを提供者サーバーへ配備しNoahへ接続後に受入する。ZIP生成だけではスマホ稼働済みとしない。
- 失敗時: 不正入力は明示エラー。紹介可能案件0なら無料の確認手順と不足条件を返す。料金未確認は比較の注意として明示する。
- 記録: 台帳版・案件ID・参照日・適合理由・未確認事項・集計期間。本文の個人情報や認証情報をログへ残さない。

## 登録と境界

- `toolkits/noah-affiliate-agents/` が再利用可能な本体。汎用コードと合成テストのみGitへ入れる。実ASP台帳・報酬・トラッキング識別子は公開Gitへコミットしない。
- 相談側の配布ZIPには、許可された案件の公開用投影だけを入れる。運営側のZIPは本人用として保存する。モード切替は権限の代用ではなく、配布物とMCP経路を分離する。
- 公開MCP `/consult/mcp` は相談Toolのみ。`/operations/mcp` はサービス所有者用のBearer鍵を要求し、鍵未設定は閉じる。マルチテナント共有の運営口としては使わない。
- 台帳は事業者がWorkerの秘密設定へ投入。利用者の入力から台帳・媒体許可を上書きできない。MCP応答は公開フィールドのallowlistで構成する。
- 任意URLの取得、自動スクレイピング、購入、提携申請、投稿、収益保証は実装しない。API/チャット媒体の許可はASP側の確認済み情報として台帳へ記録する。
- 商標・媒体の条件、無料案、広告表示、利用者の適合度を保持する。指定予算に対する価格情報が無い場合は適合判定できない旨を返す。
- `README.md` に入力例・パッケージ化・配備後の登録手順を記載。初版は規則による相談整理・原稿下書きで、自由会話モデルや自動投稿の実装ではない。
