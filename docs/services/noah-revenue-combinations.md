# Noah — Agentと成果報酬案件の組み合わせ

- 本人が言う一言: 「実際に使える運用botとレントラックスの口座開設案件を照合」「こんな感じでどんどん掛け合わせを作れるから作ってこ」。
- Goal: 実サービスの対応関係とASPの許可・成果条件を照合し、利用者の準備支援から許可済み紹介、実成果の承認追跡を継続する。紹介報酬と利用者の投資損益は別に扱う。
- Noaがつなぐもの: 公開根拠を持つサービス、本人管理の非公開ASP条件、匿名相談MCP、既存ChromeのASP読取。
- AMCの工程: 候補照合→条件点検→自社Webの準備記事→利用条件の整理→許可済み媒体への正式紹介→実注文/承認の取込→費用控除後の実績点検。追加サービスも同じ台帳で評価する。
- Jevの合格条件: 未提携・媒体不許可・対象外チャネル・条件矛盾・根拠期限切れの紹介0件。個人の接続鍵/口座情報の公開0件。重複成果の加算0件。クリックや利用者の自己申告を承認報酬へ昇格する件数0件。非対象媒体/IDの成果の帰属0件。無認証の運営操作成功0件。
- 出力先: Noahの公開入口とMCP、本人用の採算/承認待ち台帳。公開記事は出典付きの事実と準備事項。成果単価・正式URL・契約情報は秘密設定に保持。
- Wallet: 外部報酬の観測のみ。送金・投資の発注権限を持たない。初期広告予算0円。実費と承認額を区別する。
- hardware profile依存: Webの継続処理は独立Worker。既存ChromeによるASP読取は端末とログイン状態に依存し、未接続を接続済みと表示しない。
- 失敗時: 根拠不足は準備支援のみ。提携や媒体登録の申請は本人の明示許可を得た送信だけ。取引目的でない申込・報酬目的の不要な取引を作らない。
- 金融の範囲: サービスの対応・費用・必要条件を整理。本人確認、口座開設、入金、運用設定、売買は本人と提供者の手続き。Noahは投資判断/運用益を提供・保証せず、投資口座の鍵や注文権限を要求しない。
- 記録: 検証日・出典・判定理由・匿名uix・媒体ID・案件ID・実成果番号・承認状態・報酬。未完了の工程と次回の実行を保持する。

## 自動化の受入
公開記事の生成、組み合わせの定期再判定、匿名準備票、条件が揃った紹介、実ASP取得記録の保存と重複排除、承認追跡までを検証する。ASPの常時読取、提携、媒体、実注文が未確認なら全工程稼働・収益獲得とは扱わない。
