# Noah — 法人si導入準備と成果報酬運営

- 本人が言う一言: 「①から実装して。集客から成果承認・入金確認まで回せる形にして、Noahに載せる」「会員登録制排除」
- Goal: 法人の業務棚卸し・研修相談準備、許可済み広告への引継ぎ、ASP承認と銀行入金の照合。入力は業務条件と本人用の証拠付き実績。広告費・送金は実行しない。
- Noaがつなぐもの: 提供者側の公開MCPと会員登録不要のWeb入力。同じ純関数を使う。本人用運営は別のBearer認証口。
- AMCの工程: 1. 需要/対象確認と相談票 2. 掲載ゲート 3. 匿名識別子による引継ぎ 4. ASP実績の取込 5. 承認・否認管理 6. 支払履歴と入金明細の照合 7. 全費用込みの採算確認。
- Jevの合格条件: 対象外/許可不足の広告リンク0件。公開応答の秘密/報酬漏えい0件。重複取込による金額増加0。未承認・差額・重複入金の入金済み昇格0。Noah入力schema/MCP互換、未ログインの相談→結果を確認する。
- 出力先: スマホの相談票・計算根拠、JSON/Markdownの成果。運営の状態は本人用台帳と証拠参照。既存Work経由の接続も保持。
- Wallet: 外部ASPの観測台帳のみ。承認/入金照合はWallet残高・送金の許可にしない。初期の利用者相談は無料、提供者側の費用を運営で記録。
- hardware profile依存: スマホから提供者サーバーへ入力。Mac導入と利用者会員登録は不要。
- 失敗時: 対象外は有用な整理票のみ。媒体条件未確認は広告を停止。古い版、同一IDの不整合、証拠のない入金は拒否し、保留理由を表示。
- 記録: 相談本文/メール/社名/IPを台帳に保存しない。匿名ID・流入キャンペーン・判定・日時とASP成果ID・入金参照を記録。運営の生ファイルは端末側で正規化し、必要列だけ送る。

## 実装範囲
- `toolkits/noah-affiliate-agents/` の既存相談基盤と別の `business-*` モジュール。公開コードは汎用条件と合成試験のみ。実案件の単価/識別子/条件は秘密設定。
- Worker独立ストレージを使う。既存Noahの本番D1 migrationは行わない。書込は原子的・版付き。運営の証拠は入力元の実績で、プロバイダーによる確認を装わない。
- 集客原稿・掲載予定表・流入URLを生成し、ASP媒体許可がある範囲のみ有効化。外部SNS投稿/営業送信/ASP申請は自動送信しない。
- 有料契約を強制しない。研修需要のない利用者も業務表を受け取る。研修相談の申込と有料研修の契約を区別する。
- 実成果の認定はASP、実入金は支払履歴と入金明細の一致。テスト入力を運用台帳に投入しない。テスト合格だけで収益化完了と呼ばない。


## 自動運用の合格条件（2026-11-22 本人の補足）
- 手動フォーム・CSV取込・原稿下書きだけではAgent完成としない。人は初期接続と本人意思が必要な操作に限って関与する。
- 継続実行器は保存したGoalと工程状態から次の仕事を選び、入力画面を閉じても実行する。開始/停止、再起動、重複配信、取得障害を検証する。
- 自社Webの集客原稿を作成・公開し、匿名相談と成果の実績から改善先を決める。架空の実績、承認額、受賞や導入効果を生成しない。
- ASPの成果/承認/支払の実取得と銀行の読み取り専用接続が必要。未接続の汎用HTTPアダプターや合成試験を実接続と呼ばない。
- 本番で工程ごとの取得元・実行時刻・次回・失敗/本人対応待ちを表示する。未接続でも経過時間によって完了や承認に昇格させない。
- 現状の公開Webと台帳は基盤。外部取得と継続実行の受入が揃うまで一連の自動化は未完了。

## 実画面の取得記録（2026-11-22）
- 認証済みChromeの注文/承認/支払画面を読取元とする。Cookie・ブラウザプロファイル・認証情報を移送しない。UIの対象期間、全状態、見出し、小計を検証し、非対象媒体の成果をNoahへ帰属させない。
- 必要列への変換は端末内。取得受領票は取得元、日時、範囲、件数、SHA256を保持。0件も記録し、同じ取得の再送は原子的に重複排除。24時間経過で古い取得を警告する。単発の取得は継続接続の受入にしない。
- 銀行自動照合は読取接続と実明細が揃った後。摘要・金額・日付が一致する一意な対応だけを候補にし、同額複数件や不明な振込元は保留。ASP支払予定だけから入金を作らない。

## 登録済み媒体への案内（2026-11-22）
- `registeredArticle` は記事URL・媒体origin・サイトID・掲載許可・原文タグ照合・確認証拠を保持する。正式広告URLのサイトIDと照合し、異なるorigin/query/hashを拒否する。Noah自身の `mediaApproved` とは独立。
- 対象相談だけ記事URLを返し、正式タグも記事URLも相談IDで改変しない。直接紹介も `trackingApproved` が明示trueの場合だけ追跡情報を付ける。
- 成果取得は案件名と登録媒体IDの両方を照合する。媒体全体の承認額と、個別相談へ帰属できない成果を区別する。匿名相談数と媒体成果数から個別の因果関係を捏造しない。
- 受入: 対象外の紹介0、記事の媒体不一致0、タグ改変0、未許可追跡0。実Worker/SQLiteで匿名相談→公開記事URLを検証する。
