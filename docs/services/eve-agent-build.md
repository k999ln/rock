# Eve — Agent のビルド（見分ける・整える・縮める・試す・載せる）

- 本人が言う一言: 「agentを載せる際にファイルをアップして載せるのだが、そこでリファクタしてあげたり、モバイル用に使えるように圧縮したりできるようにしたい」「Eveはagentをビルドする役割」（11-20）「開発者が入りやすいビルドを作る」（10-07）
- Goal（Eveが作る）: 目的＝作者のファイルを、他の人が 1 クリックでつなげる版にして載せる / 入力＝ファイル・貼付・ZIP・リポジトリの URL・Eve の担当・接続先の URL、権利の確認 / 期待成果＝保存版、公開仕様の下書き、接続要件、接続証明、作れた時はスマホ内版 / 予算上限＝作者の無料ビルド枠（候補: 1 日 5 回）/ 要る権限＝作者自身の下書きと登録の読み書き
- Noaがつなぐもの: `noah_agent_drafts`、`/api/noah/import`、`/api/noah/agents`、`/api/noah/publisher`、構文整理（`noah-upload-refactor`）、固定テスト付きの si 整理（`noah-project-refactor/1`）、隔離環境（[noah-cloud-place.md](noah-cloud-place.md) か作者の Mac runner）、Spider
- AMCの工程:
  1. 受け取る（担当: Eve）— 合格条件: 既存の上限内。権利の確認が 1 回ある。
  2. 見分ける（担当: Noa）— 合格条件: 何も実行しない。読み取った内容が既存の parser を通る下書きになる。
  3. 整える（担当: Work）— 合格条件: 各変更で、変更の前後に同じ固定テストが通る。
  4. 縮める（担当: Work）— 合格条件: [noah-mobile-variant.md](noah-mobile-variant.md) の合格条件。
  5. 試す（担当: Jev）— 合格条件: 何も入っていない環境で接続を再現し、手数・秒数・通信先が宣言と一致する。
  6. 確かめる（担当: Spider）— 合格条件: 機械審査の不一致 0。
  7. 載せる（担当: 作者）— 合格条件: 作者が 1 回押す。無料かつコード公開は掲載、それ以外は人の審査へ。
- Jevの合格条件: 作者が必ず書く欄 0。原本の download が入力 bytes と完全一致。固定テストが失敗した変更の採用 0 件。鍵を含む版の公開 0 件。宣言に無い通信先を使った版の「1 クリック」表示 0 件。接続証明の無い版の印 0 件。自己審査 0 件。同じビルド ID の二重実行 0 件。別 owner の読取 0 件。
- 出力先: Eve の仕事（進み具合）、Noah の「載せる」画面（結果、差分、見本、価格）。phone でも可（ファイルを選べる端末）。
- Wallet: 無料ビルド枠の中は 0 円。枠を超える分の扱いは未決（本人）。価格と手数料は変えない。
- hardware profile 依存: 全部（Web）。段 3〜5 は隔離環境が要る。
- 失敗時: 原本と直前の保存版を保ち、止まった段と理由を見せる。整える・縮めるが通らなくても、元の版で載せる所まで進める（印は付かない）。結果不明は同じビルド ID で照合し、自動で再実行しない。
- 記録: Work に、ビルド ID、原本・保存版・スマホ内版の hash、各段の処理器と版、採った変更、固定テストの結果、接続証明、機械審査の報告。コードの本文は Work に入れない。

| 読む物 | 決める物 |
| --- | --- |
| 拡張子、`package.json`、`pyproject.toml`、`requirements.txt` | 言語、入口、依存 |
| `SKILL.md`、プロンプトだけのファイル、Eve の担当 | 種類＝担当（コード無し） |

| 環境変数の参照、鍵らしい文字列 | 要る鍵。直書きの鍵は公開を止める |
| README、LICENSE | 名前、説明、使い方の例、ライセンス |

種類は `role`（担当）/ `code`（Node・Python）/ `tool`（MCP）/ `provider`（A2A・MCP HTTP・Web）/ `model`（重み。次の段階）。読み取った内容で `noah-agent/1`・`sky-tool-package/1`・`noah-connect/1` を下書きする。全部、作者が直せる。

## 整える

| 順 | 内容 | 採る条件 |
| --- | --- | --- |
| R1 | 入口を足す（`noah-terminal/1`）。元の入口は残す | 固定テストが新しい入口で通る |
| R2 | モデルの呼び出しを中継へ付け替える。OpenAI 互換の呼び出しは、実行先の外向き中継で受けられるならコードを変えない | 同じ固定テストが中継のモデルで通る |
| R3 | 直書きの鍵を消し、要る鍵を接続要件の `services` へ出す | 鍵らしい文字列 0 |
| R4 | 依存の版を固定し、導入済みの層を作る | 層の hash が固定され、導入無しで起動する |
| R5 | 固定テストが無ければ、README の例から案を作る。期待値は作者が確かめる | 作者の確認がある |
| R6 | 構文整理（既存の規則） | 既存の合格条件 |

- 変更は 1 つずつ別の差分にし、作者が採否を決める。si の出力だけで合格にしない。
- 原本は変えない。固定テストの無い版は「動作未確認」と表示し、R1〜R4 を自動で採らない。
- 外部の有料モデルへ自動で切り替えない。整える担当のモデルは本人が決める（設計書 §9）。

## 接続証明

段 5 の結果。版の hash に結び、実行先ごとに、接続の手数、最初の成果までの秒数、使ったメモリ、実際に通信した host、見本（入力と成果）を持つ。「1 クリック」の印はこれが通った版だけに付く。公開後は Spider の巡回が同じ試験をやり直す。

## 機械審査（Spider）

1. 鍵・個人情報らしい文字列が無い。
2. 宣言した権限・通信先と、接続試験で観測した物が一致する。
3. ライセンスが読め、公開の形と合う。
4. 任意の shell 起動、宣言外の書き込み先が無い。
5. 説明文と見本の成果が食い違わない（Jev）。
6. サイズと上限の内側。

不一致は「直す所」として作者へ返す。無料かつコード公開は、全部通れば載る。有料またはコード非公開は、作者の名前（会社名）と所在地の確認と、人の審査へ進む（10-10）。人が見るのはこの報告と差分。自己承認は不可（現行）。

## API と状態

- `POST /api/noah/builds`: `{ id, draftId, revision }`。Work を 1 件作る。同一 Origin と ownerScope が必須。
- `GET /api/noah/builds/[id]`: 段ごとの状態、下書き、差分、接続証明、見本。
- `POST /api/noah/builds/[id]`: `{ action: "accept" | "reject" | "stop" | "publish", revision, changes? }`。
- 状態: `queued → classifying → normalizing → shrinking → probing → reviewing → ready`。作者待ちは `needs_author`。ほかに `failed`・`stopped`・`unknown`。
- 上限は既存どおり（ファイル 10MiB、貼付 64KiB、ZIP 128 entry、下書き 32 件）。1 ビルドの時間は候補 10 分。
- 既存の `/noah/agents/new`・`/noah/publisher` は「細かく直す」入口として残す。API と保存先は変えない。
