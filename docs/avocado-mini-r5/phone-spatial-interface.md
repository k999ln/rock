# avocadoMini R5 — 携帯の新しい形と空間インターフェース

更新: 2026-10-19。主担当: Material Invention / avocadoMini、MAT15（JOINT）。RockstarOS共通CoreはOS10／DSP01、通信はSIM01、Gameと外部アプリ接続はそれぞれの既存gateに従う。

## 1. 製品要求と参照映像

利用者が指定した**最低機能**は、センサー、生体認識、対応機器やサービスとの連動、RockstarOSとその中のSky／Zema等の利用、衛星からMini自身への通信、Wi-Fi共有、取り外した後のポケットWi-Fi動作である。携帯電話の新しい形として、手持ち画面に依存する操作を空間の検知と表示へ移す。着信時には情報が空間に現れ、本人が空間をタップして応答・拒否できる。住まいでは同じ仕組みで生活の状態や対応候補を扱い、ゲーム・制作にも使える。R5の200mm以内・1本自律・同型増設・別演算Hub不要を維持する。

提供された約11.45秒の画面収録は、都市の円筒状の看板と重なる発光表現を示す**見え方の参照**である。電話画面、空間タップ、裸眼投影方式、衛星通信が実装された映像ではない。Miniでは「端末の近くに現れる、読める状態と選べる操作」という体験へ翻訳し、光学方式を同一試作機で検証する。原映像を製品素材や実機証拠として再配布しない。

## 2. 本人の一周

1. 建築・家具に固定したMini、または持ち出したMiniが、契約中の回線・RockstarOS利用権・端末能力を別々に確認する。
2. 着信イベントを受ける。共有空間にはまず個人情報を含まない小さな光・音の合図を出す。本人が近づくか明示操作したときだけ、本人認証後に発信者と操作候補を見せる。
3. Miniは手の位置と表示面を校正し、`応答`／`拒否`を短い明示的な動作で選ばせる。選択を視覚・音で返し、実行前の誤タップを取り消せる。着信通知と応答成立は別状態で表示する。
4. 応答が成立したら、相手・音声経路・ミュート・終了を本人に示す。自宅では許可済みの室内音声経路、携行時はMini本体または本人が選んだ対応音声機器を使う。
5. 通話を終えても通知履歴と必要なZema仕事は本人別に残す。端末を外した時は場所の設備権限を失効させ、個人の仕事・通信を継続する。

同じ空間インターフェースは、メッセージ、Agentの結果、ゲーム中の通知、家の状態候補へ再利用する。発信、支払、解錠、設備変更、外部送信などの作用は種類ごとに本人承認を確認する。着信を空間で受けられても、緊急通報や全スマートフォン機能を満たしたとは表示しない。

「携帯でできることをセンサーで賄う」は、タッチ画面の代わりに**本人の動き・声・周囲の状況から入力し、適切な空間表示・音声・触覚で返す共通操作方式**として扱う。通話、メッセージ、撮影、検索・browser、地図、決済、ゲーム、Agent／Toolの各機能は、通信契約・権利・端末能力・本人の承認が個別に必要である。対応機能は同じ操作語彙（選ぶ／確認／戻す／止める）を使い、未対応の機能と理由を明示する。手を使えない時やセンサーが見失った時にも音声・物理入力などで電話の基本操作へ戻れるようにする。全アプリ対応や緊急通報の認定は、個別の受入なしに製品表示しない。

## 2.1 何もない場所に建築を見せ、そこで設計する

2026-10-19の利用者の明示補足: **何もなかった空間に、avocadoMiniによって建築物のデモや設計中の空間が見える。実物には触れられないが、そこにあるかのように歩いて見て、より精密な設計へ使う。** 続く「トンネルの中の蝋燭」の比喩は、選んだ自分たちの観察範囲では同じ空間が明瞭に見え、その外へ設計の像を広げない体験目標として扱う。実際に蝋燭、トンネル、光の輪を置く形状指定ではない。通知カードだけをMiniの空間表示の代表体験にしない。建築だけに製品用途を固定せず、同じ空間基盤をインテリア、素材、ゲーム、制作にも使う。

利用者の一周は、空間／図面の選択→現場の寸法と基準点の取得または既存実測図の取込み→設計案を空間へ位置合わせ→縮尺模型と原寸の部屋・部材を切替→利用者が歩いて複数方向から確認→声・手の指示で壁、開口、家具、素材等の候補を変更→寸法・干渉・視線・動線・採光等の差分と不確実性を表示→版付きCAD/BIM等の成果へ保存→専門家が実測・法規・構造・施工可否を別に検収、で閉じる。空中の像は視覚表現であり、触覚や実体の壁ではない。手の動きは候補の選択・編集入力として扱う。

入力は承認された図面／3Dモデル、その座標系・単位・版、現場の測定値と測定誤差、Miniと観察者の姿勢、表示光学の校正、本人の操作。RockstarOSはowner／place／project／revision／共有範囲を強制し、Skyは対応する作図・解析Toolを接続し、Zemaは同じ設計仕事の比較案・費用・承認・成果を保持する。保存するのはモデル原本と変更差分、基準点・測定source・校正版・見積誤差・表示方式・観察条件・検収者を結び付けた版付き成果。生の室内映像と生体情報は既定保存しない。表示の誤差をCAD/BIM原本の精度と混同しない。

センサーだけでは光は出ない。部屋を測り、本人の視点と手を追跡して位置を合わせる**入力系**と、裸眼で複数位置から見える像を実際に作る**光学出力系**を別に設計・実測する。近距離の一枚の通知カードや床・壁への単なる表面投影は、利用者が求める「何もない空間の建築物」を満たした証拠にしない。眼鏡なし・Mini単体・使用時200mm以内を現行目標に維持し、建築スケールの視域、奥行き、遮蔽、複数人、通常照度、消費電力、熱、眼の安全を同じ閉箱で検証する。縮尺模型、原寸の一室、建物全体は別の表示範囲として判定し、一つの成功を他へ拡張しない。

閲覧者をownerが招待した共同設計者と同じscene/revisionへ結び、各人の視点から矛盾なく見える範囲を**共同観察域**として記録する。人数、立ち位置、視線高さ、入退出、周囲照度を変え、誰がどこから何を読めるか測る。認証やソフトウェア権限だけでは、空中に出た光を第三者から隠せない。共同観察域の外で像が見えない／設計の細部が読めないという目標は、光学的な漏れを全周・高さ・反射面から実測できた範囲でだけ表示する。未確認の時は機密図面を空間へ出さず、本人と招待者の個別表示または閲覧専用画面を使う。このfallbackを裸眼の共同空間表示が成立した証拠にはしない。

校正失効、姿勢追跡喪失、図面の単位・座標不一致、測量不足、光学範囲外では像を確からしい実寸設計として表示し続けず、理由と測定済み範囲を示して閲覧専用の2D／既存画面へ戻す。変更候補は本人の保存承認まで案のまま扱い、生成案・視覚デモを測量図、構造安全、法規適合、施工済みの証明へ昇格させない。

MAT15の独立した空間建築受入は次のとおり。閾値は対象空間と用途を定め、試験前に版付きで固定する。**AS01**: 空室の実測基準点と模型／原寸モデルの座標・縮尺・登録誤差を独立測定する。**AS02**: 通常照度で複数の観察位置から奥行き・遮蔽・読める寸法・視域を測り、像が消える範囲を記録する。**AS03**: 歩行と手・声による編集の誤操作、遅延、校正ドリフト、取消・復旧を測る。**AS04**: 同一jobの設計変更が版付きCAD/BIM等の成果と表示へ一致し、再起動後に同じ版を読める。**AS05**: Mini単体の同一閉箱で光・熱・電源・眼の安全と他の最低機能との干渉を測る。**AS06**: 招待者複数人が同じsceneを各視点から確認でき、共同観察域の外と反射経路から第三者が読める情報を測り、機密図面の露出基準を満たす。現時点でAS01〜06の物理受入は0件。先に限定範囲の光学・計測benchとscene／成果契約を作り、その結果で一室・建物規模と閲覧範囲の制御へ拡張可能か判断する。

最初に対象地の識別子、自治体/住所または街区等の範囲、公的資料の出典と取得日、所有/立入/撮影/共有の許可状態を**人が確認**して案件へ結ぶ。Miniは許可された範囲で寸法、基準点、光、音、温熱、動線等を測る候補となり、実測値・機器/校正版・誤差と、図面からの値・AI推定を別記する。RockstarOSは`owner/place/project/revision`と現場でのsensor/共有scopeを強制し、Skyは図面・解析Toolと建築家等の専門家への依頼を接続する。Zemaは候補案、費用、所有者/利用者の判断、専門家の検収、施工後の使われ方を同一jobに版付きで残す。Mini上の空間表示はAS01〜06に合格した範囲だけを使用する。

最初の受入は**同意を得た一つの実在空間**で、敷地資料の出典、実測基準点、図面/CAD・BIMの版、表示の位置合わせ誤差、専門家の判断、利用者の一日の課題と事後の評価を同じ案件から読み返せること。端末なしの運営、Miniを加えた運営、Skyの仕事まで加えた運営を比較し、利用者が目的を果たせたかと負担を記録する。Miniのsensorでは所有権、通行権、構造・防火・文化財等の適合を確定できないため、該当資料と責任者の判断がない案件は候補のまま止める。この研究接続はMAT18の設計具体化であり、現地導入・現場実測・光学受入・論文の提出/検収を完了した記録ではない。

## 3. 一体のcoreと外側の責任

```text
センサー（手・距離・周囲光・任意の声／カメラ）
  → 空間入力adapter（位置・確信度・校正・誤操作抑制）
  → RockstarOS（owner／生体照合／権限／通話状態／保存・復旧）
  → 空間出力adapter（表示・音・触覚または物理入力）
  → Sky／Zema・対応アプリ・許可済み住設

衛星WAN ⇄ Miniのmodem／antenna ⇄ MiniのWi-Fi AP ⇄ 本人の接続端末
固定dock ⇄ 給電・保持・任意の有線WAN／空間校正
```

センサーは入力と状況を測る。情報を空間に見せるには投影、光学合成、近眼表示等の**別の出力方式**が必要で、空中の任意位置へ光が浮くことをセンサー性能として扱わない。候補方式は、実際の室内照度、視点、表示距離、視野角、遮蔽、解像度、消費電力、光安全、携行中の使用姿勢で比較する。設置中だけ成立する方式では「携帯の新しい形」の受入を満たさない。携行中も着信を認識し、応答・拒否・終了をできる入力／出力を必須にする。

生体認識は本人特定と個人情報表示のgateにする。顔・声・身体特徴の候補は端末内の保護された照合と生体提示攻撃への試験が必要で、声や近接検知だけを支払・解錠・外部送信の承認にしない。登録、再登録、認識失敗、紛失、共同居住者、来客、本人が使えない状況にPIN／物理操作等の復旧経路を用意する。生体の生データは既定でクラウドに送らず、保存・削除・backup範囲を本人へ示す。

RockstarOSはMini上で利用する機能の本人性、capability、承認、予算、仕事、成果、更新、復旧を担当する。Skyは対応Agent／Toolと接続条件、Zemaは同じ仕事の進捗と成果を担当する。Gameと住宅機器は許可されたadapterの範囲で連動する。OSやAgentの提案が生体認証、通話成立、設備作用の実証へ自動的に昇格することはない。

衛星からの**受信だけではWi-Fi経由のInternet共有は成立しない**。Mini自身から衛星へ送信する上り、下り、modem、antenna、回線契約、地域、消費電力、熱、屋外の見通し、Wi-Fi APを同一coreで受け入れる。屋外terminalを使う案は比較・開発用に保持するが、利用者が求めた「外してポケットWi-Fi」を合格にしない。地上回線や建物WANは選べる代替経路であり、直接衛星gateの代替合格にはならない。

## 4. 状態・保存・失敗・復旧

| 系統 | 分けて示す状態 | 復旧の要点 |
| --- | --- | --- |
| 本人 | 未登録／照合待ち／本人確認／失敗／失効 | 他人の通知詳細を出さず、登録済み代替手段と紛失失効へ |

| 表示・入力 | 校正待ち／表示可能／低信頼／遮蔽／停止 | 低信頼gestureは作用させず、音・物理入力へ切替。状態は保持 |
| 通信 | 衛星探索／登録／IP接続／Wi-Fi共有／切断／上限到達 | 「電波あり」とInternet接続を分け、切断時に共有中と偽らない |

通話・通知・仕事にはowner、device、通信経路、event ID、job ID／revision、表示先、承認、結果、時刻を必要最小限で記録する。発信者、部屋の状態、生体原本、音声内容は保存目的と期限を決めるまで既定保存しない。通信断・停電・熱保護・OS更新では確定状態から復帰し、未確定の発信、支払、住設作用を自動再送しない。電池低下や過熱時は新しい高負荷処理を抑え、通話終了・保存・安全停止を優先する。本人は通信共有、センシング、音声、空間表示、Agentを個別に停止できる。

| MP04 通話 | 実際の着信・応答・発信・終了、双方音声、切断・再接続、通知履歴を回線契約と端末能力が一致する環境で受け入れる | JOINT／EXTERNAL |
| MP05 直接衛星Wi-Fi | dock外・外部terminalなしで衛星の上り下り→IP→Mini Wi-Fi client通信を実測。電池、熱、携行姿勢、地域・契約を固定する | JOINT／EXTERNAL |
| MP06 RockstarOS継続 | 同じownerと仕事でdock→携行→再装着、Sky／Zema、通知、Game／住設adapter、失効、更新・再起動・成果回収を確認する | ROCK／JOINT |

MP01〜06は既存MG01〜07（Game）、DP01〜05（着脱通信）、OS実機gateと併存する。数値閾値は対象利用者・照度・通話用途・地域・電池目標を決め、候補部品のbench前に版付きで固定する。実機試験は現時点で0。どれかが未合格なら、最低機能を備えた「携帯の新しい形」や直接衛星ポケットWi-Fiとして販売表示しない。

## 6. 未決定の決め方

OWNERは最初の販売地域、利用者、電話番号／音声契約、携行時間・共有台数・通信費上限、空間表示の使用場所、住宅機器の最初の対象を決める。ROCKは既存RockstarOS／Sky／Zema契約とDevice Profileを再利用し、機器候補ごとの測定計画を作る。EXTERNALは衛星・音声網、RF、光学、sensor、住設の仕様と契約条件を示す。JOINTは同一200mm以下の閉箱試作機でMP01〜06を実測する。表示、衛星antenna、電池、GPU／SoCの同時収納が成立しない場合は包絡、実測、不成立理由を並べ、利用者へ製品要求変更の判断材料として示す。比較案の成功を元の最低機能の合格へ置き換えない。
