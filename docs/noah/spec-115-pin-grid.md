## 1. 完成の姿

- ホーム（`/noah`）を開くと、**今動かせる Agent**（取り込んで握手が通った物）が、高さの違うカードで 2〜6 列に敷き詰められている（スマホ 2 列）。
- カードは、分野の色の面に頭文字（Agent に画像が無いため）、名前、説明 2 行、出どころの host。押すと詳細（`/noah/ready/agent`）が開き、そのまま「接続」して頼める。
- カードの「保存」で、自分のボードへまとめる。ボードは公開も選べ、公開ボードは他の人がフォローできる。フォローしたボードに入った Agent は、ホームの最初の頁に混ざる。
- 「表示しない」で、その人のホームから外れ、全員の並びでは強く下がる。
- 詳細の下に「これも使われています」（その Agent を保存した他の人のボードから。5 人以上の時だけ）。
- 上の帯に、ロゴ・メニュー（ホーム・ボード・Agentを探す・実行中・成果データ・登録サポート）・検索・ポスト・アカウント。900 px より狭い時は、メニューが下。

## 5. 並び（`lib/noah-pins.ts`。学習なし・乱数なし）

X の For You（github.com/xai-org/x-algorithm、Apache-2.0）の**作りの形**に、Reddit と Pinterest の式を入れた。

1. **候補の出所**（X の Thunder・Phoenix の取り出し・人気の代わり）
   - personal（最初の頁だけ・サインイン）: フォローした公開ボードに新しく入った物（15 件）＋本人の保存から Pixie で行き着く物（15 件）。
   - popular: 票が 1 以上の物を hot の順（`noah_pin_stats_hot` の索引）。
   - ran: 人が動かして成果が返った物（L2）で票の無い物。新しい順。
   - fresh: まだ実績の無い物。その日の並び（`shuffle`）。
2. **外す規則**: 載せていない・取り下げ・隠した系列（SQL）、本人の「表示しない」、前の頁で出した物。
3. **点**（X の重み付きの和の代わり）: 票 = 保存した人 × 1 + 成果が返った人（直近 90 日）× 2 − 表示しない人 × 5（どれも人数）。hot = sign × log10(max(|票|, 1)) + (載った時刻 − 1134028003 秒) / 45000（Reddit の `_sorts.pyx` と同じ式。12.5 時間ごとに、票が 10 倍の物と並ぶ）。保存・外す・表示しないの時は、その Agent だけ数え直す。成果が返った人は、一覧を返した後に UTC の 1 日に 1 回だけ数え直す（本番の巡回を開けなくても動く）。
4. **混ぜ方**（`noahComposePins`）: 席の順 [personal, popular, ran, popular, fresh]。**5 枚目ごとに fresh**（X の新しい投稿のお試し・棚の 5 枚に 1 枚と同じ考え）。無い出所は次の出所から。
5. **続けない**（X の同じ作者を下げる決まりの代わり）: 同じ提供者は直近 6 枚に 1 枚まで、同じ分野は 2 枚まで続く。守れる候補が無い時は緩める（空きを作らない）。
6. **本人へのおすすめ**（Pinterest の Pixie を決まった値で）: 起点 = 本人の新しい保存 20 件（新しいほど重い・半減期 7 日）。起点の Agent を含む**他の人の**ボードを経て行き着く Agent の見込み = Σ 1 / (起点を含むボードの数 × ボードの件数)。合わせ方は Pixie の (Σ√(重み × 見込み))²（複数の起点から届いた物を強くする）。**行き先へ届いた人が 5 人より少ない物は使わない**（少ない人の保存から、誰のボードか分からないように）。
7. **頁の印**: 出所ごとに、前から続けて出した所までの位置（`[hot, id]` など）と、飛ばして先に出した物（30 件まで）。base64url の JSON。形の違う印は 400。

借りなかった物: X の重みの数値（学習モデルの予測確率に掛ける物）、Pinterest の TransAct・PinSage（学習モデル）、写真の色の近さ（Agent に写真が無い）。
