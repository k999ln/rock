### 9.3 表の通しで見つけて、直した所

**5 章の 10（「切る」。成果は、仕事の一覧に残る）が、通らなかった。**

- 見つけた事: 詳細の画面の「仕事」は、つないでいる接続の依頼だけを出していた（`GET /api/noah/ask?connection=`）。「切る」と、一覧ごと消える。記録（`noah_asks`）と成果（Work）は残っていて、1 件ずつなら読めたが、「切っても、受け取った成果は残ります。」と書いてある成果へ、その画面から行けなかった。
- 直した形: 仕事の一覧を、接続ではなく、その Agent（系列）で読む。`GET /api/noah/ask?agent=<系列の ID>` は、本人の、その Agent への依頼を、切った接続の分も含めて、新しい順に 50 件まで返す（成果の文は持たない。D1 への往復は 1）。詳細の画面は、サインイン済みの人に、つないでいない時・切った後も「仕事」を出す。切った時は、一覧を読み直す。
- 変えていない事: 接続で絞る読み方（`?connection=`）。依頼を受け付ける条件（切った接続では、頼めない）。未サインインの人には、何も返さない（401）。
- 重さ: 本人の依頼を、新しい順に読み、その Agent の物が 50 件そろうか、本人の依頼が尽きるまで見る（今ある、接続で絞る読み方と同じ索引 `noah_asks_owner` を使う）。依頼が多い人の所で重くなったら、`noah_asks(connection_id)` の索引を足す（migration が 1 本増えるので、出した後に、数を見て決める）。
- 残る事: 依頼が多い Agent では、「仕事」が長くなり、その下の「切る」が遠くなる。出した後、件数を見て、畳むかどうかを決める。
