## 画面

- Agent の詳細では接続ボタンの下に、説明の先頭の一文・「渡す物 → 返る物」・工程の段を表示する。task 123 の日本語訳が台帳にある場合は日本語の画面で使用し、原文も開ける。根拠のある図がない詳細では従来の提供元説明を表示する。
- 同じ段の工程は同時に進められる。本人の工程には点線と動作の印を付ける。押して種類・本人が入る理由・待つ物・待つ理由を確かめられる。札、画面用の文、進行段のラベルは Noah の 6 言語へ切り替わる。道具名は照合できるよう配布元の名前を表示する。
- 棚の詳細も同じ部品で表示する。棚に載る既存条件と公開条件を通過した `pkg:` のみ、カードの宣言済みの素材を使う。審査者の稼ぎ方の設計図も共通部品を使う。ピンや一覧の画像には工程を入れない。

## 図の根拠

- Agent の道具の札は、現行の系列代表と握手の固定版が一致する記録だけを使う。モデルの提案は既存の `parseNoahCardProposal` で検査する。契約の JSON は `produces` に要素 1 個の配列を置き、検査後の型では札 1 個になる。入力・出力に裏付けがある札だけを採る。
- 一致する素材の上流が明確な場合に線を引く。一般的な素材や、出力候補が複数ある場合は対応する入力・出力のスキーマ項目で裏付けを取る。循環して工程順を決められないときは図を出さない。接続に本人の操作が必要なときは接続計画から工程を加え、接続済みになったら共通関数で外す。
- 棚の工程は検証済みカードの `have`・`want` と `consumes`・`produces` に従う。元から使える水準を上げたり、Agent を起動したりする機能ではない。

## 運営と公開

- 握手で得た道具の名前・説明・スキーマは外部資料として扱う。台帳は固定版ごとに札を持ち、対象の定義が変わったらその版の札を準備し直す。閲覧時に外部 Agent やモデルは呼ばない。
- `NOAH_EXPLAIN_PUBLIC` の既定は閉。閉じている間は認証された審査者が既存の閲覧権限内で確認する。本番 D1 を更新する前に本人の承認を得る。開く前に現行の対象系列と札がある系列を集計し、対象から無作為抽出した 200 系列を運営が目視で照合して 190 以上の一致を確認し、本人の公開承認を得る。
- 指示書の 17,046 系列は [task 123](../../codex/tasks/123-noah-all-agents-usable.md) に記録された手元の時点値。本番の現在件数や札がある件数には置き換えない。
- [札付け手順](spec-127-label-pipeline.md) と [200 系列の抽出・目視集計](agent-human-audit.md) を作業の引継ぎに使う。
