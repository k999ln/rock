# Sky MCP導入・利用体験の改善

更新日: 2026-09-12

## 解消した詰まり

- PC接続がMCPツール総数を4件に固定していたため、追加ツールがあるだけで失敗していた。必須4ツールの名前を確認し、追加ツールは許容する方式へ変更した。
- 接続後の通信が常にMCP 2025-11-25を送っていた。初期化で合意した対応版をタブ内に保持し、その版でpingと実行を続ける。
- 本人限定の現行SiteがPCパックの許可Originに含まれていなかった。`https://rockstaros-kaiya.noellesugar1.chatgpt.site`を追加し、再配布ZIPへ反映する。
- ToB掲載フォームはMCP接続先を保存するだけだった。公開HTTPSの接続先へ`initialize`と`tools/list`を行い、ツールを一件も実行せず、確認件数と名前を表示する掲載前診断を追加した。
- ToC向けの主要ボタンと状態表示からMCPという内部用語を外し、「PC接続」「PCで実行」へ統一した。開発者向けの接続方式選択とCodex設定ではMCP表記を維持する。

## 安全境界

- 掲載前診断は同一Skyからサインイン済みの利用者だけが実行できる。
- 接続先は認証情報を含まない公開HTTPSのみ。IP直指定、localhost、内部ネットワーク用の名前、リダイレクト、256 KiBを超える応答、100件超または5ページ超のツール一覧を拒否する。
- OAuthが必要な401応答は到達確認として扱うが、ツール一覧確認済みとは表示しない。403などの拒否は接続成功にしない。
- 診断ではツールを実行しない。掲載申請は引き続き審査状態で保存し、即時公開しない。
- PC接続tokenはタブの`sessionStorage`に限定し、永続保存へ広げない。接続アプリはloopbackへbindし、許可OriginとBearer tokenを引き続き確認する。

## 検証結果

- 合成MCPでJSON応答、Streamable HTTPのevent stream、MCP版の後方互換、追加ツール、OAuth待ち、内部URL拒否、必須ツール不足を試験した。
- `npm run verify`で130件の単体・統合試験と、仕事APIの143 assertionsが合格した。Sitesの正式buildも完了した。
- PCパックを再生成し、現行Site Originからのpreflightとtoken発行が成功することをloopback HTTPで確認した。
- Codexのアプリ内ブラウザではloopbackへ到達せず、接続失敗案内を表示した。利用ブラウザのローカルネットワーク許可が必要であり、通常ブラウザを含む実利用環境ごとの確認は残る。

第三者の実MCPと実OAuth認証は未接続であり、この変更だけで安全審査、料金、外部アカウント、長時間job、取消・失効の相互運用を完了とはしない。
