# 01 — サービス体験：ひとつの依頼を、使える成果へ

この章は、変わっていない製品要望を、一人の利用者が理解できる体験へ組み直す。主担当はWeb / Product UX（ROCK）、既存taskはWEB04 / G04。Jennifer・Sky・Zema・OSの役割を接続し、画面の整理を新機能の実装済み証拠にはしない。

確定方針は[製品ベース](../product-baseline.md)と[機械可読ベース](../../data/product-baseline.json)、現行実処理は[全Tool詳細](../sky-tools-complete-design.md#仕事の組み立てとレシピ2026-10-13web04--g04)、責任は[責任分界](../workstreams/00-responsibility-boundaries.md)に従う。

Jenniferの根拠は[PR #113のJennifer設計・SHA `3349c247`](https://github.com/k999ln/rock/blob/3349c2475468443bc7ecd94a4e3782343f514a8f/docs/jennifer-coordination.md)。これはPR #113でmain `01d2e418`へ統合済みのsourceであり、公開配備・真正review・実Provider受入とは分ける。以下のJennifer中心体験はこのsourceと今回の本人指示に基づく目標構成である。

## 1. 利用者への約束

**「やりたいことを持ってくれば、使う道具、途中の確認、仕上がった成果まで、一つの場所で扱える。」**

商品入口は2026-10-15の通信＋si利用権bundle、本人/仕事の正本は無料avokadoアカウントとし、**Jenniferへ依頼し、Skyで必要な能力を選び、Zemaで仕事を進め、Jenniferと成果を確認する**。会話で利用者が話す窓口はJenniferで、Zemaはその裏で仕事を保存・管理するsystemとする。RockstarOSは本人、権限、保存、停止、復旧の共通基盤を受け持つ。スマホ・PC・ブラウザから始められ、専用機器やSIM購入を利用開始条件にしない。

最初の客は、文章を納品する個人事業主。最初の価値は「原稿を生成できる」だけでなく、依頼条件と素材を揃え、加工と検査を通し、確認済みの納品用成果を取り出せること。顧客の受領、支払い、売上は別の確認として残す。

ゲストは説明を読み、対応するToolのローカル下書きを試せる。本人別に保存する時、接続・有料実行・公開へ進む時にサインインの理由を示す。ゲストの入力を自動でアカウントへ送らない。サインイン後の記録には一人のownerを持たせ、複数端末利用を複数人共同編集の完成と扱わない。

料金の確定条件は、2026-10-15に商品入口だけを更新した[既存の料金・account方針](../product-baseline.md#2026-10-10-現行製品方針-アカウントを入口にしsimは機器の任意部品にする)を引き継ぐ。アカウント無料と、Tool購入・si従量・外部実費・機器回線料を別表示する。本番課金・Provider・規約等の受入が揃うまで、見積画面や試験台帳を実請求と表示しない。

## Skyが受け持つmodel・Agent・実行先の選択

本人の2026-10-15指示により、Skyはcloud Agentと導入したlocal LLMの双方を選ぶ入口とする。modelの推論先とAgent runnerを区別し、端末内/cloud/明示した工程ごとの組合せ、必要な導入・接続・データ送信・費用・準備状態を示す。Zemaは選んだ経路の仕事/成果/費用を保持し、Brokerは権限/予算/承認を強制する。使えない時の自動fallbackは行わず選び直す。[詳細契約・現在地・未実行SC01〜05](../llm-evaluation-architecture.md#skyでmodelとagent実行先を選ぶ)に従い、6 adapterの定義と本番接続を区別する。

### si専用端末を通常の操作面にする

2026-10-15の本人指示により、Pixel参照機はunlock後にJenniferへ依頼し、進捗・成果・費用・承認・停止へ戻れるsi Homeを主役にする。Sky/Zema/Brokerは同じ一仕事を裏で支え、利用者が毎回appやmodelを選ぶことを通常操作の条件にしない。通信＋si利用権商品と、Miniから同じ仕事へ入る携帯不要の目標を維持する。一般appの扱いは未決定で、設定/復旧/mute/手動停止は残す。[端末の保存・失敗・復旧・DT01〜06と実装差分](../native-os-integration.md#si専用端末の利用体験と実装境界)が詳細正本。現在のShellは通常起動appで、専用Home/音声role/全OSの実機受入はこれから行う。

### 携帯を持たず、PCや対象物の前にもいない制作体験

2026-10-15の本人指示を、機器の機能数より上位の体験要件とする。**考えた場所から作り始め、手元の携帯を開かずに話し、直し、確認し、続きへ戻れること。** 設置済みMini/対応hostのある一室を最初の検証範囲とし、建物全域や外出先へは入力・応答・本人性・通信の受入範囲を追加して広げる。新しい携帯端末や常時携行する機器の購入をここで必須化しない。

1. 本人が部屋でJenniferへ目的を話す。Mini/対応hostが入力と応答を担い、Skyが必要な制作Toolを選ぶ。自分の作品と他人の資料を分ける。
2. 言葉や対応する手/空間入力で案を直す。表示がある環境では版を比較し、音声だけでは変更点/寸法/不確かさを読み戻す。精密確認が必要な時は対応固定表示等を使い、電話へ強制handoffしない。
3. Zemaが同じJob・素材grant・Artifact版・確認待ちを保存する。Pro/PCは離れた計算先として任意に使い、cloudは送信条件と見積/上限を確認して使う。選んだmodelがない時に自然文Agentが動くと表示しない。
4. デジタル作品は保存/再表示/取得を確認する。実物の製作は検査済み図面・寸法・材料/公差・相手・確定版・見積・本人承認を揃えてから、対応設備/製作者へ渡す。既存WorkJob四状態を維持し、「案/検査/引渡し/製作確認」は成果の版と工程記録で表し、新しい万能Job状態を増やさない。
5. 発送・メッセージ・注文・製作開始は、宛先/内容/費用/作用を別承認する。声が似ている、同じ部屋にいる、返事をしたという理由だけで許可を発行しない。初回登録/紛失復旧/実行承認を通じたMini側/対応固定端末等の電話に依存しない強い本人確認方式は未受入で、成立まで作用を保留する。
6. 途中で部屋や端末を変えても既存Jobを再取得する。出力先/本人を確認するまで私有内容を読み上げず、切断/応答喪失時は同じ実行IDを照合する。新しい版への変更は以前の製作承認を再利用しない。

保存は既存のowner別Job/版付きArtifactと各端末local保存を再利用する。部屋の無断常時録音は前提にせず、mute・停止・本人切替・誤起動・騒音・通信断を扱う。物理設備の現地安全確認/停止系は専用担当と設備に残し、制作者が対象の前にいないことを安全条件の省略へ転換しない。

**合格条件**は[baselineのAC01〜AC06](../../data/product-baseline.json)で管理する。AC01は電話を取り出す回数0・PC前での必須操作0で案→2回修正→比較→保存/再表示→停止/再開を同じ作品で通す。AC02は対象不在で図面/寸法の由来と不足を照合する。AC03は非電話の本人確認と版付き製作引渡しをsandboxで検証し、AC04〜06は他人/騒音/mute、切断/移動、未接続能力を検証する。所要時間・認識誤り・修正回数・費用・再開時間は実測して記録し、目標値を実績にしない。全ケースは設計段階で未実行。

主担当はDOC04/H1（ROCK、設計同期）。実現はWEB04/SKY21の仕事・能力接続、MAT15のMini入力/表示/停止、Coreの本人/保存/予算、JOINTの実host/製作先受入へ分ける。最初の制作物、部屋、精密確認方法、非電話の本人確認方式、対応製作先は次の試作briefで具体化する。Miniの全空間表示や量産、実製作の受入をこの設計変更で完成と呼ばない。

## 2. 名前が体験のどこに現れるか

- **avokado**：サービス全体とアカウントの入口。利用者が毎回system名を選び直さなくても仕事を始められる。
- **Jennifer（利用者表記Jenniffer）**：Rockstar全体のプロジェクト統括窓口。依頼をGoal・意図・成功条件へ整理し、projectと担当を選び、確認待ちと成果受領をまとめる。実行権限を持たず、計画作成だけで仕事や費用を発生させない。
- **Sky**：目的に合うAgent / Toolを探し、作者・版・範囲・費用・接続条件を確認する場所。Jenniferから必要な能力を選び、Zemaの同じ仕事へ渡す。直接探す入口も残す。
- **Zema**：Jenniferの裏で依頼、計画、承認、進捗、停止、成果、利用額、Receipt、履歴を保持する仕事system。利用者と話す競合人格にはしない。
- **RockstarOS**：実行条件と本人境界を守るruntime。Broker / Platform Coreがowner・権限・上限・入力digest・期限・失効を強制する。Webにないnative能力は端末適合と受入が済んだ範囲だけ追加する。
- **avocadoMini**：単独でも遊び、操作し、保存・停止する空間体験の機器program。Proを必須にしない。
- **avokadoPro**：高性能NVIDIA si PCを主眼とする独立program。既存のPCゲーム目標も維持し、Miniとの接続は任意。今回の方向確認を最終部品・性能保証・製造受入にせず、構成・互換性・販売受入は[Pro設計](../avokado-pro-pc-design.md)に従う。
- **rocketstar**：独立したhardware / mission program。共通OSの地上支援と飛行安全系を分け、Webの仕事承認で飛行を許可しない。

GitのJennifer project担当はRockstarOS、Hardware、rocketstar、Jennifer / Zema、AMC、Spider Security、Business / Wallet、Governance / Releaseの8つの社内開発/運営profile。一般利用者の顧客案件とは別の権限領域で、普通のaccountから社内task・private Git・運営命令を操作しない。一般利用者は自分のproject/Goalと許可資料を同じ会話方式で扱い、依頼時に必要な担当だけを使う。常駐processや独自credentialを8つ作る意味ではない。

Sky直接操作とhost appの有限処理は会話を必須にせず、同じowner/job/成果とBroker gateへ接続する。Jenniferの会話、Skyの能力選択、Zemaの仕事panel、ホストアプリ内の成果表示を一つの体験にまとめる。現行の専用画面は段階的に接続し、同じjobと成果を参照する。埋め込みは新しい実行権限を作らない。

## 3. 基本画面と情報の置き場所

画面入口は既存routeを使う。mainにはSky / Zema / composeとPR #113のJennifer sourceがある。以下は目標の情報構成であり、全画面受入・公開配備済みを意味しない。

### Home — 内部`/`、公開`https://avoado.si/os`

目的は、Jenniferへ最初の一件を頼み、前の仕事へ戻れること。入力は目的の短文または既存仕事の選択。出力はGoal、対象project、次の確認と仕事への入口。サインイン後にowner別の保存済み仕事を読む。未送信文は保存済みと混ぜず、取得失敗は空の仕事一覧と表示しない。

### Sky — 内部`/sky`・`/sky/marketplace`、公開`https://avoado.si/os/sky`

目的は、使える道具を安心して選ぶこと。入力は目的、対応環境、送信可否などの選択条件。カードに「できること」「できないこと」「実行場所」「データ送信先」「料金の種類」「準備状態」を示す。選択結果はTool IDと明示した依頼だけをZemaへ渡し、私有本文をURLへ入れない。未接続候補は実行ボタンの代わりに必要条件を示す。

### Zema — `/zema`、`/zema/compose`、`/work`

目的は、Jenniferと確認した依頼を検収可能な成果へ進めること。入力は目的、完成条件、素材、処理、検査、必要なら期限・上限。出力は計画、途中成果、検査、承認待ちの内容、最終成果。owner別WorkJobとrevisionで保存する。実行中も「何ができたか」「次に何を確認するか」「停止」を同じ位置で見せる。

複数工程ではZema内AMCが確認済みGoalを`Goal → milestone → work package → task → step`へ有限分解し、実行担当とreviewerを分ける。担当の提出、証拠の検収、ownerの最終受入を別に表示する。Jenniferの計画はadvisory-onlyで、Tool選択・見積・Broker確認・本人承認を省略しない。COLOMBIAは原本未登録の参照contextで、名称から内容を推測して適用済みと表示しない。

現在の組み立ては接続済みの引用整理、無料記事加工、CSV整形、成果結合、形式検査を使う。最大12手順・12,000文字・予算0の実装境界を保持する。入力を理解したモデルの万能計画として見せず、編集可能な候補として扱う。

### 成果・Library — `/zema/library`と仕事詳細

目的は、成果を読む、取得する、改訂する、再利用すること。入力は保存済みjob / artifact / revisionの選択。出力は本文、検査結果、元仕事、実行記録、取得可能なファイル。本文と検査を近くに置き、合格の範囲を表示する。別owner・消去済み成果・版競合は取得を止め、旧版を黙って新しい版に置き換えない。

### 接続・費用・設定 — `/sky/network`、`/wallet`、`/settings`

目的は、仕事の不足条件をその場で解消すること。入力は接続先、scope、Provider、上限、失効・停止の選択。出力は接続状態、見積、予約、使用額、照合済みreceiptを別項目で示す。接続済みでも実行承認は必要。送信先・scope・価格が変われば再確認する。接続の再確認だけで古い仕事を自動再送しない。

### 作者の制作 — `/studio`、`/sky/publish`

目的は、自作Toolを利用者へ届ける準備をすること。入力は作者、版、license、入出力、必要権限、環境、提供URL / package、保守窓口。出力は診断、検査結果、公開対象の確認、版付き登録候補。公開コード、catalog審査、実行権限、有料販売をそれぞれ別の状態で持つ。

## 4. 体験A：原稿を納品用成果へ仕上げる

例は「支給原稿から無料公開版を作り、出典と必須文言を揃えて納品用ファイルにする」。最初は既存の有限処理で一周し、有料siを必須にしない。

1. Jenniferに目的を伝え、Skyの引用整理・無料記事能力を選ぶ。現行の直接入口として、Skyカードの「このToolで仕事を組む」も使える。
2. Jenniferと原稿、読者、必須文言、文字数などの完成条件を確認し、Zemaの仕事へ置く。入力素材の保存対象と取り扱いを見て本人が保存を選ぶ。
3. 引用整理 → 無料記事加工 → 完成条件の検査を組む。並び、入力元、各Toolの限界が見える。提案の手順を編集できる。
4. 実行前に処理範囲を確認する。現行compositionでは外部si・課金・顧客送信を開始しない。
5. 途中成果を開き、出典の整形と形式検査を確認する。引用整理は事実確認、文字数検査は品質保証として表示しない。
6. reviewでJenniferが成果と未達条件をまとめ、本人が原稿を読んで検収する。修正が必要なら原成果を残し、編集版を新しい仕事へ渡して再検査する。現行composeの形式検査を独立si reviewerの実証にしない。
7. 確認済みファイルを取得する。外部への実納品は本人操作または個別の接続・承認契約を使い、ファイル取得だけで納品完了にしない。
8. 次回用にレシピを保存する。手順と安全な初期設定だけを再利用し、原稿、顧客情報、予算承認、receipt、旧検査合格を持ち込まない。

保存するものは明示同意した素材、固定した計画、途中成果、検査、本人の完了記録。レシピから新しい仕事を作る時は新しい目的・完成条件・素材を入れる。未保存memoryと保存済みrecordの境界を各操作後に表示する。

合格は、実入力の二種類以上の処理から検査・保存・再表示・ファイル取得・新素材でのレシピ再利用を一周できること。原成果と旧承認が変わらず、PCと390pxでも成果を見失わない。顧客受領と有料取引は[事業pilot](../workstreams/09-business-pilots.md)の別証拠で扱う。

## 5. 体験B：作者がToolを作り、Skyへ届ける

例は「手元の小さなCSV検査Toolを、自分にも他の利用者にも分かる形で公開する」。公開手順に成功しても売上を約束しない。

1. JenniferにTool公開の目的を伝え、Skyで必要なSDK / MCP契約を選び、Studioで入出力、対応環境、上限、失敗時の動作を定義する。制作の仕事と承認はZemaで追う。
2. 作者自身のテスト入力で実行し、結果・停止・再接続・失効を診断する。必要な権限を最小に絞る。
3. Skyカードの説明と権限を利用者の目線で確認する。署名は作者の同一性を示し、安全認定として表示しない。
4. コードを公開する場合は全文・license・版・保護方式を確認して明示送信する。SPIDERの非送信検査と公開投稿を区別する。
5. 登録候補の審査結果と不足条件を見る。登録、実行、購入可能の状態を別に確認し、未受入を「公開販売中」にしない。
6. 利用者がJenniferまたはSkyから選択した後、Zemaの仕事へToolを渡す。新しいscope・送信先・課金は利用者本人が確認する。
7. 不具合時は停止・失効・版の取り下げ・supportへ進める。旧版で作られた成果とreceiptは追跡できる状態を保つ。

保存は作者別metadata、版、manifest、明示公開したコード、審査記録。資格情報と利用者原稿を公開packageへ含めない。第三者ToolをOS platform鍵で署名せず、実行の資源制限と権限はOS側で強制する。

合格は、別ownerの利用者が対象Toolの範囲を読み、許可された入力で結果を受け取り、失効後は新規実行が止まること。支払い・返金・作者払出しはProviderと本番gateを別に満たす。[Sky詳細](../sky.md)と[課金設計](../sky-billing.md)に接続する。

## 6. 体験C：遊ぶ・制作するを、非金融のまま進める

例は「自作ゲームの小さな体験を作り、対応機器で試す」。Game / IPは文章仕事とは別の用途として残し、金融系の完成待ちで止めない。

1. Jenniferとゲーム制作・IP素材・公式ゲーム接続のどの目的かを整理し、Skyで能力を選ぶ。制作物の導入と既存タイトルのプレイを混ぜない。
2. Zemaに体験の目的、素材の権利、対象機器、完成条件を置く。対応する既存SDK / adapterを選び、候補だけのProviderは実行しない。
3. 素材を生成・加工する場合は送信先、商用権利、費用上限を確認する。生成結果をAsset IDと版で追い、Provider URLだけに依存しない。
4. 作者sandboxで実行・停止・保存・再起動を確認する。作者のゲームポイント発行を実資金記帳の権限へ広げない。
5. 公開・ゲーム導入は生成と別に本人が確認する。対応機器だけへ渡し、hostでの成功をMini実機成功にしない。
6. 既存タイトルなら正規clientへ明示引き継ぎし、接続・起動・操作・セーブを別々に確認する。起動commandの成功をゲーム起動成功にしない。
7. Jenniferと結果、対応条件、素材の版、未達項目を確認し、Zemaの記録から次の制作仕事へ戻す。ゲーム内交換、資産売買、外部残高移動は開始しない。

Miniは単独経路、Proは独立PC経路として診断し、任意接続を追加する。対象ゲーム・OS・機器・client版が合格した範囲だけ対応表示する。[Game workstream](../workstreams/08-game-market-fund.md)、[Mini接続契約](../mini-game-client.md)、[si native設計](../ai-native-os-architecture.md)へ受入を分ける。

合格は、非金融sandboxで制作・実行・停止・保存・再開を一周し、owner交代と接続断で前の入力・権限が残らないこと。実公開、外部client、Mini実機、商用権利、売上はそれぞれ別証拠を要する。

## 7. 一貫した状態と承認

仕事状態は[`lib/workflow.ts`](../../lib/workflow.ts)の`active` → `review` → `completed`、または`cancelled`を使う。下書き、接続待ち、見積中、承認待ち、保存確認中は画面・step・operationの状態であり、新しいWorkJob状態を追加しない。

- **active**：確定した仕事を進めている。最後に保存された手順と今の処理を区別する。
- **review**：必要な処理が終わり、本人の内容確認を待つ。Tool成功を本人検収や外部納品へ昇格させない。
- **completed**：本人が当該仕事の完了を記録した。顧客受領・請求・入金を別に表示する。
- **cancelled**：仕事を止めた。保存済み成果や外部確定済み作用の削除・取り消しまで含めない。

承認は「何を、どこへ、どの版・条件・上限で実行するか」を短いカードにまとめる。保存同意、見積のための本文送信、有料実行、外部公開、削除を一括承認にしない。LLMの提案・Toolの`ready`・接続済み表示を本人承認へ代用しない。

独立reviewの目標受入は、実行担当と別reviewerのdelegation、同じowner / Goal / leaf / 対象artifactと版、認証済みreview結果、署名済みusage Receiptを相関して確かめること。PR #113のUIはownerによる手動検収を持ち、AMC PATCHは認証済みA2A reviewer artifact / usageを横断照合していない。手動の合否入力を自動検証済みの独立reviewと表示しない。

## 8. 失敗した時も仕事を失わない

応答喪失では「保存できていない」ではなく「結果を確認中」と表示し、同じowner / job / command / payloadで照会する。新しいcommandを自動発行して同じ作用を繰り返さない。Providerの結果不明は再生成・再送より先に同じoperationを照合する。

サインイン失効では私有入力を隠す。別タブで元ownerを確認してから同じ仕事へ戻す。別ownerには入力を見せず、再試行・明示破棄も元owner確認後にする。下書きmemoryはバックアップではなく、タブ閉鎖や強制reloadで失う可能性を保存表示の近くで説明する。

revision競合では本人の入力を残して最新保存版を読み直し、比較してから新しい編集を始める。古い応答を新しい仕事へ反映しない。形式検査失敗は該当条件・手順と修正方法を示し、他の確定済み成果を消さない。

停止は新しい処理を止め、確定済み作用と保存済み成果を示す。取り消せない外部作用はその事実と照合先を示す。外部契約や端末適合が不足する時も、許可されたローカル下書き・確認・exportを続けられる。

## 9. 触り心地の共通規則

各画面は目的、いまの状態、次の一手を先に示す。主操作は一つに絞り、危険・費用・データ送信の情報を操作の直前に置く。system内部名を使わなくても「素材」「手順」「検査」「成果」「使用額」で進める。

Jenniferの会話を保ちながらSkyのTool選択とZemaの仕事panelを開き、選んだ後に同じ素材・計画へ戻る目標とする。専用画面が必要な時は戻り先と保存状態を示す。成果は同じ画面内で読めて取得でき、外部リンクだけを渡して終わらない。
