# RockstarOS Wallet — 設計・実装 v0.3

更新日: 2026-09-12。対象: Web / PC Developer Preview の `/wallet`。

## 目的

Walletを、**自動化で生まれたお金と受取額を短時間で確認できる画面**にする。情報量を絞り、Skyの商品実行、Provider入金、実費、Sky利用料、利用者の受取予定を混同させない。

今回の範囲は設計、フロント、Wallet専用API。既存のD1台帳を使い、アカウント別の残高、売上・経費の追加、取消、入出金履歴を保存する。新しい決済、資金保管、払出し、料金、通貨換算は追加しない。

## 情報設計

Walletは状態に応じて入口を変える。ログイン後は説明ページを挟まず、残高と操作を最初に表示する。

### 初回利用

1. **主操作** — 「サインイン」の1操作だけを表示する。
2. **所有者境界** — 残高と記録が本人のアカウントだけに保存されることを伝える。

### 利用中

1. **記録残高** — 売上から経費を引いた円建て残高を最も大きく表示する。
2. **主操作** — 「売上を記録」「経費を記録」を残高の隣に置く。
3. **入力** — 金額、記録元、日付だけを受け取り、その場で保存する。
4. **入出金** — 新しい順に履歴を表示し、誤入力は削除せず取消記録で戻す。
5. **外部送金境界** — 銀行口座との入金・送金は接続済みになるまで準備中と明示する。

## Backend

- `GET /api/wallet` は本人の円建て残高、売上、経費、最新100件の記録を返す。
- `POST /api/wallet` は売上・経費の追加または既存記録の取消を保存し、更新後のWalletを返す。
- D1の `book_records` を追記型台帳として使い、同じ操作IDの再送は二重計上しない。
- 取消は元記録を書き換えず反対額の記録を追加し、同じ記録を2回取り消せない。
- 全クエリを認証済みuser IDで絞り、別ユーザーの残高・明細・取消対象を参照できない。
- 書込APIは同一OriginのJSONだけを受け付け、件数・金額・日付・記録元を検証する。

## 状態と表示

| 状態         | 金額表示 | 主操作         | 誤認防止                     |
| ------------ | -------- | -------------- | ---------------------------- |
| 読込中       | 非表示   | 読込中         | 仮の金額を実額として出さない |
| 未サインイン | 非表示   | サインイン     | 本人のWalletだけを開く       |
| 記録0件      | `￥0`    | 売上・経費記録 | 空状態からすぐ入力できる     |
| 記録あり     | 集計値   | 追加・取消     | 通貨を混ぜず円だけを合算     |
| API障害      | 非表示   | 再試行         | 入力を成功扱いしない         |

## ビジュアル

- ログイン前は小さな認証カードだけを表示する。
- 利用中は黒い残高面、白い集計・履歴面、明るい緑の売上ボタンで操作の優先度を示す。
- 大きなラベル、広告的なコピー、装飾的な進捗ゲージは置かない。
- デスクトップでは3つの内訳を横並び、スマホでは縦に並べる。
- Developer Previewと実送金未接続を画面内に固定し、本番Walletのような誤認を避ける。

## 次の実装候補

1. Provider sandboxを接続し、Receiptの状態（照合中・払出準備・受取済み・要確認）を実データで確認する。
2. Receipt詳細でExecution Receipt、Provider参照、証拠hash、返金・disputeを確認できるようにする。
3. 払出先の登録と変更は本人再認証、cooldown、監査記録を含む別フローとして設計する。
4. 通貨別の残高を分け、換算レートなしに複数通貨を合算しない。

実Provider sandboxと認証済み実取引が未接続のため、今回の完成は「本人別に永続化する収支Wallet」に限定する。実入金・実送金の接続はProvider確定後の別工程とする。
