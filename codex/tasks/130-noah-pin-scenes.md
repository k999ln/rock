## 2. やる事（この順で。1 つずつ PR にして、合格条件で確かめてから次へ）

### 2.1 保存する場所
- `noah_intake_candidates` に列を足す migration（番号は次の空き）: `pin_json`（`parseNoahPin` が通る JSON。2 KB まで）、`pin_source_sha256`（作る元にした文の hash。下の 2.2）、`pin_model`（使ったモデルの名前）、`pin_at`（作った時刻）、`pin_skip`（作らなかった理由。下の 2.2）。
- 集めた紹介（R2 の `noah/collection/v1/*.json`。task 120・121）の 1 件には、`pin` の項目を足す（`parseCollectionSnapshot` が `parseNoahPin` で確かめる。形が違えば、その項目だけ落とす）。
- 取り込み（`lib/noah-intake-import.ts`）で本番へ送る。**本番 D1 の migration は、本人の許可の後**（AGENTS.md §6）。

### 2.2 書く仕組み（収集機）
- 対象: 載っている系列（`noah_listing` が listed）と、新しい紹介。`pin_json` が無い物と、`pin_source_sha256` が変わった物（名前・説明・`summary_ja`・道具の名前と説明のどれかが変わった）だけ。同じ元からは二度作らない。
- AI に渡す物（これ以外は渡さない）: 名前、提供者の説明（原文）、`summary_ja`（task 123 の 2.6 で入っていれば）、握手で読んだ道具の名前と説明（`tools/list`。長ければ先頭の 20 個）、`noahPinTemplateGuide()` の全文、見本 17 枚（カードの題・入れる物・返る物と、その絵の JSON）、下の決まり。
- 返させる物: JSON 1 つだけ。`{"title","give","get","scene":{"template","labels","parts","variant"}}`、または作れない時は `{"skip":"理由"}`（理由は `unclear`（何をするか説明から分からない）・`no_template`（どの型にも合わない）・`not_for_people`（人が頼む物ではない。例: 開発の試験用）のどれか）。
- **決まり（AI への指示に、そのまま入れる）**:
  1. `title`: 何をするかを、使う人の言葉で、日本語 20 字以内。「〜を探す」「〜を確かめる」「〜を計算する」のような、動きで終わる形。製品名・宣伝の言葉・「最強」「AI で」などは入れない。
  2. `give`・`get`: 頼む人が入れる物と、返る物。説明と道具の定義に書いてある事だけ。30 字以内。
  3. 札の言葉（`labels`）は、説明・道具の定義・自分が書いた `title`・`give`・`get` に、そのままある言葉だけ。**数・日付・固有の例を作らない**（「120m」「11月中旬」のような、どこにも無い数は書かない）。
  4. 型は `noahPinTemplateGuide()` の 16 個から、何をする Agent かが一番伝わる物を選ぶ。迷ったら `transform`（入れる物 → 返る物）。部品と種類は表にある物だけ。
  5. 説明から何をするか確かに言えない時は、作らずに `skip`。分かったふりをしない。
  6. 説明が英語でも、題・入れる物・返る物・札は日本語（英単語そのものが入れる物の時は、その単語のままでよい。見本の `comfortable`）。
- 確かめ方: `parseNoahPin` が通る事。加えて、札の言葉が、渡した文（説明・道具の定義・`summary_ja`）か、返った `title`・`give`・`get` に含まれる事（`tests/noah-pin-scene.test.mjs` の 17 枚の試験と同じ考え。関数にして lib に置く）。通らなければ、エラーの中身を添えて 1 回だけ書き直させる。それでも通らなければ `pin_skip = 'invalid'` にして、カードは今のまま。
- モデルは Luna Max が選んでよい（小さいモデルで足りる見込み）。鍵は Actions secret に入れる。チャット・Git・ログに書かない。
- 1 回の巡回で作る上限と、月の上限（費用の目安が分かる値）を置く。上限で止まった数は、収集機の状態に出す。

### 2.3 中身が合っているかを確かめる
- 審査者の画面（運営の画面か `/noah/ops`）に、無作為の 200 件を並べる: 左に提供者の説明（原文）、右に作ったピン（`components/noah-pin-scene.tsx` で描いた絵・題・入れる物 → 返る物）。審査者が「合う／合わない（理由）」を押す。
- **合う割合が 95% 以上になるまで、一般の人のグリッドには出さない**（審査者だけに出す。切り替えは `NOAH_INTAKE_PUBLIC` と同じ考えで 1 つ足す）。合わない物は理由ごとに数え、決まりか型を直して作り直す。
- 本人にも、200 件の画面のリンクを渡す（本人の目で「一目で分かるか」を見てもらう）。

### 2.4 画面
- `noahReadyItems`（`lib/noah-intake-store.ts`）とディレクトリ（`lib/noah-agent-directory.ts`）のカードに `pin` を載せる（読む時にも `parseNoahPin` で確かめ、通らない物は載せない）。グリッドは、もう `pin` を描ける。
- 題の下に「Noah の説明」と小さく添える（棚のカードと同じ。提供者の言葉ではない事を示す）。提供者の原文は、押した先の詳細の画面にそのまま出す。
- 詳細の頁（`/noah/ready/agent`）の上にも、同じ絵と「入れる物 → 返る物」を出す。
- 工程を「何を待つか」で段に並べた図は、ピンには入れない（本人の判断「ピンには分かりにくすぎる」）。入れるなら詳細の頁。

### 2.5 型が足りない時
- `skip` の `no_template` が全体の 10% を超えたら、多い物から型を足す（`lib/noah-pin-scene.ts` の表と `components/noah-pin-scene.tsx` の両方。試験も）。足した型は、本人に画面を見せてから使う。
- 絵柄（淡い空と地面・紺の髪と黄色い服の人・白い札・影なし）は変えない。札の字は幅 300 のうち 19 以上（スマホの 2 列で 11px 以上）。
- 足した型にも、画面に入った時に 1 回演じる動く部分を 1 つ以上入れる（`<M>` で囲む。動かすのは形・透明度・線の描き足しだけ）。札・✓・地図のピンのような大事な形は、右上の `NOAH_PIN_KEEP_OUT` に置かない。どちらも `tests/noah-pin-scene.test.mjs` が確かめる。
