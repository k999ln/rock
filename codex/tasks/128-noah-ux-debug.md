## やり方（全部の小項目で同じ）

- 1 つの小項目を 1 つの PR にする。PR 本文に「わかった事・やった事・確かめた事・次の事」を書く。
- 確かめの道具: `node scripts/noah-public-walk.mjs <origin> [画面の一覧]`（スマホ幅で開く。はみ出し・44px より小さい押す所・失敗した API）と、`node scripts/noah-public-probe.mjs <origin> [出力.json]`（GET を返す API を、知らない人とブラウザの本人の 2 通りで呼ぶ）。どちらも読むだけ。
- 本番で書き込む確かめ（接続・依頼・保存・登録情報）は、本人の許可がある時だけ。許可が無い時は、手元で本番と同じ形に build して確かめる（`npm run build` の後、`dist/server/.dev.vars` に試験用の `NOAH_PROFILE_KEYS` と `ROCKSTAR_LOCAL_DEVELOPMENT_USER_ID=""` を入れて wrangler で動かす。値は試験用だけ。本物の鍵を入れない）。
- してはいけない事は AGENTS.md の 6 のとおり。特に: 本番 D1 への migration の適用、外部への登録・申込の送信、試験の削除と書き換え。
- 判断が要る所（下の「本人の判断」）は、作らずに本人に聞く。

## 小項目

### D1 ブラウザだけの本人の、全体の上限（抜け道 S1・重さ 高）

- わかっている事: ブラウザだけの本人は、Cookie を捨てるだけで何人でも作れる。上限は本人ごと（下書き 64MiB・ファイル 512 個・下書き 32 件・Agent 100 件・依頼 1 日 200 回）なので、全体の上限にならない。R2 と D1 が際限なく増える。
- やる事: `noah-browser:` で始まる持ち主の書き込みに、Noah 全体の 1 日の上限を足す（下書きの新しいバイト数・ファイルの数・Agent の登録数・登録情報の書類・GitHub と Hugging Face からのコードの取得（`/api/noah/import`。Noah の外向きの IP で GitHub の API の枠を使うので、全体で使い切られると誰も取り込めなくなる））。登録の代行（`lib/noah-registration.ts`）の「1 人 1 日 10 件・全体 1 日 200 件」と同じ、条件つき INSERT の形で、数えるのと書くのを 1 つの文にする。数える列に索引が要るなら、migration の file を足す（`drizzle/` と `drizzle-main/` の両方。本番への適用は本人）。
- 合格: 上限を越えた書き込みが 429 と日本語の理由を返す試験。サインインした本人は、この上限に数えない試験。今の本人ごとの試験が全部通る。

### D2 1 つの相手への依頼を、1 人で使い切れないようにする（抜け道 S2・重さ 中）

- わかっている事: 1 つの相手への依頼は、Noah 全体で 1 分 30 回まで（`NOAH_ASK_LIMITS.hostPerMinute`）。D1 の理由で、1 人が何人分にもなって、この枠を使い切れる。
- やる事: 同じ相手への枠のうち、1 人（ブラウザの本人）が使える分を決める（例: 3 分の 1）。
- 合格: 1 人が 30 回送った後でも、別の人の依頼が通る試験。

### D3 設定の有無を、知らない人に返さない（抜け道 S4・重さ 低）

- やる事: 本人の確かめを、設定の確かめより先にする。知らない人には 401 か 404 だけ。
- 合格: `scripts/noah-public-probe.mjs` で、2 つとも 401 か 404。
