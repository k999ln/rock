# 105 自社クラウドの回し方 — 約束・見張り・知らせ・費用の上限・バックアップ

本人の決め: K5〜K7・K9（2026-11-21 22:54。[07](../../docs/structure/07-decisions-from-minutes.md)）。設計は [compute-placement.md 0.5](../../docs/compute-placement.md)。

## 決めてある事（変えない）

- 約束（SLO）: 受付の API は月 99.5%（月 3.6 時間まで止まってよい）。最初の成果は 95% が 30 秒以内。預かったデータの消失は 0。
- 夜中に起こすのは「データの消失・お金・安全」の 3 つだけ。他は朝に知らせる。
- AI の運用担当（Spider は読むだけ、手順は Codex か Claude）がしてよいのは、見る・知らせる・戻すまで。壊す操作・お金・本番の DB は人が承認する（AGENTS.md §6）。
- クラウドの月の上限: 全体 $30（「1 文で頼む」を開ける時 $150）と、1 人あたりの上限。

## やること

1. **費用の上限で止める。** `lib/cloud-cost.ts`（実装済み）の実費で、今月の全体と 1 人の合計を出し、上限に達したら新しい実行の受付を止める（理由を画面に出す）。走っている仕事は止めない。上限は環境変数 `CLOUD_MONTHLY_CAP_USD`（既定 30）と `CLOUD_USER_MONTHLY_CAP_USD`。
2. **約束を測る。** 受付の API の成否（5 分ごとの合成の確かめ）と、最初の成果までの秒数を、日ごとに集計する読み取り専用の関数と、運営の画面の表。
3. **知らせの振り分け。** 出来事の種類（消失・お金・安全・その他）から、「今すぐ起こす／朝にまとめる」を決める純関数と、その表の試験。通知の送り先は本人の許可の後に設定する。
4. **バックアップ。** D1 を毎日書き出して R2 に置く手順と、戻す練習の script（試験の D1 で、書き出し → 空の D1 へ戻す → 行数と hash が一致）。黒殿へ写すのは task 101 の後。
5. **手順書。** 黒殿が落ちた時・Cloudflare が落ちた時・上限に達した時の手順を [sky-cloud-operations-runbook.md](../../docs/sky-cloud-operations-runbook.md) に足す。

## 合格条件

- 上限を超える実費を入れた試験で、新しい実行が理由つきで拒まれ、走っている仕事は続く。
- 知らせの振り分けの表の全行が試験で通る（消失・お金・安全は「今すぐ」、ほかは「朝」）。
- 戻す練習で、行数と hash が一致する。
- `npm run typecheck`・`npm run lint:product`・関係する試験。

## やらないこと

- 本番の通知の送り先・本番の cron・本番 D1 の書き出しの開始（本人の許可の後）。AI の運用担当に、壊す操作・お金・本番の DB を任せること。
