### 2.2 書く仕組み（収集機）
- 対象: 載っている系列（`noah_listing` が listed）と、新しい紹介。`pin_json` が無い物と、`pin_source_sha256` が変わった物（名前・説明・`summary_ja`・道具の名前と説明のどれかが変わった）だけ。同じ元からは二度作らない。
- AI に渡す物（これ以外は渡さない）: 名前、提供者の説明（原文）、`summary_ja`（task 123 の 2.6 で入っていれば）、握手で読んだ道具の名前と説明（`tools/list`。長ければ先頭の 20 個）、`noahPinTemplateGuide()` の全文、見本 17 枚（カードの題・入れる物・返る物と、その図の JSON と、なぜその図かの 1 行）、下の決まり。
- 返させる物: JSON 1 つだけ。`{"title","give","get","scene":{"template","labels","parts","variant"}}`、または作れない時は `{"skip":"理由"}`（理由は `unclear`（何をするか説明から分からない）・`no_template`（24 種類のどの図にも合わない）・`not_for_people`（人が頼む物ではない。例: 開発の試験用）のどれか）。
- **決まり（AI への指示に、そのまま入れる）**:
  1. `title`: 何をするかを、使う人の言葉で、日本語 20 字以内。「〜を探す」「〜を確かめる」「〜を計算する」のような、動きで終わる形。製品名・宣伝の言葉・「最強」「AI で」などは入れない。
  2. `give`・`get`: 頼む人が入れる物と、返る物。説明と道具の定義に書いてある事だけ。30 字以内。
  3. 札の言葉（`labels`）は、説明・道具の定義・自分が書いた `title`・`give`・`get` に、そのままある言葉だけ。**数・日付・固有の例を作らない**（「120m」「11月中旬」のような、どこにも無い数は書かない）。札の数と、札ごとの字の上限は、`noahPinTemplateGuide()` の図ごとの決まり（`札の字の上限`）に合わせる。長い言葉は、元の文にある短い言い方を選ぶ（言い換えて作らない）。
  4. 図は `noahPinTemplateGuide()` の 24 種類から、何をする Agent かが一番伝わる物を選ぶ。目安: 1 つを分ける → ロジックツリー（tree）、中心から広げる → マインドマップ（mindmap）、確かめて分かれる手順 → フローチャート（flowchart）、担当が分かれる手順 → スイムレーン図（swimlane）、順に進む工程 → 矢羽根図（chevron）、絞り込む → ファネル図（funnel）、2 つの重なり → ベン図（venn）、目安・上限 → ゲージチャート（gauge）、内訳 → 帯グラフ（stacked）かツリーマップ（treemap）、期間 → ガントチャート（gantt）、順番の出来事 → タイムライン（timeline）、範囲・距離 → 同心円図（concentric）、気になる所の濃さ → ヒートマップ（heatmap）。迷ったら `tree`。`parts` は空、`variant` は null。
  5. 説明から何をするか確かに言えない時は、作らずに `skip`。分かったふりをしない。
  6. 説明が英語でも、題・入れる物・返る物・札は日本語（英単語そのものが入れる物の時は、その単語のままでよい。見本の `comfortable`）。
- 確かめ方: `parseNoahPin` が通る事。加えて、札の言葉が、渡した文（説明・道具の定義・`summary_ja`）か、返った `title`・`give`・`get` に含まれる事（`tests/noah-pin-scene.test.mjs` の 17 枚の試験と同じ考え。関数にして lib に置く）。通らなければ、エラーの中身を添えて 1 回だけ書き直させる。それでも通らなければ `pin_skip = 'invalid'` にして、カードは今のまま。
- モデルは Luna Max が選んでよい（小さいモデルで足りる見込み）。鍵は Actions secret に入れる。チャット・Git・ログに書かない。
- 1 回の巡回で作る上限と、月の上限（費用の目安が分かる値）を置く。上限で止まった数は、収集機の状態に出す。

### 2.5 図が足りない時
- `skip` の `no_template` が全体の 10% を超えたら、多い物から図を足す（`lib/noah-pin-scene.ts` の表と `lib/noah-pin-diagram.ts` の両方。試験も）。足す図は、資料で使う名前のある図解にする（例: ステップ図・比較表・ウォーターフォール図）。元の作者の Motion Prompt に同じ図があれば、それを書き写す（MIT。許諾の表示を残す）。足した図は、本人に画面を見せてから使う。
- 見た目（元のパックの図の色の役割・書体・539×208・時刻の純関数で組み上がる・作り話の数を描かない・70:25:5 の 3 色・ポップな 8 組）は変えない。足した図も、塗りの面積が 70:25:5 に近い事（`tests/noah-pin-scene.test.mjs` の面積の試験）と、どの枚の色でも字が WCAG 4.5 以上で読める事（色の役割 `mark`・`onBlue`・`onM`・`onL` を使う）。部品は `pose`・`put`・`say` で出す（ぽよんと出る）。札の字は絵の幅 539 のうち 14 以上。
- 足した図も、0 秒では札が見えず、4 秒までに組み上がる（`noahPinHold`）。字のはみ出し・作り話の数・組み上がりは `tests/noah-pin-scene.test.mjs` が確かめる。
