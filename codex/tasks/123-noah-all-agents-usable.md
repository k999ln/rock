## 2. やる事（この順で。1 つずつ仕上げて、合格条件で確かめてから次へ）

### 2.1 握手の済んだ 17,046 系列を、本番のグリッドへ入れる
- クラウドの収集機（`.github/workflows/noah-agent-collection.yml`）の握手の量を上げ、台帳の全件を握手し終える。1 回の巡回の握手の上限・同時の数を、8 分の実行時間の内で最大にする。同じ接続先へは 1 時間に 1 回の決まりは守る。
- 自動の取り込みの上限（`scripts/noah-collector-import.mjs` の `NOAH_COLLECTOR_IMPORT`。1 日 400・1 回 120）を、本番 D1 の 1 日の書き込みの枠に合わせて上げる。新しい系列 1 つで約 13 行。D1 の料金の区分（無料なら 1 日 10 万行）を確かめ、枠の 7 割を超えない値にする。
- 合格: 本番の `GET /api/noah/intake` の `counts` の合計が、収集機の DB の載る系列の数と一致する（差は、その日の上限で待っている数だけ）。グリッドの頁送りで重なり・抜けが無い。

### 2.2 量産の系列（89 系列・13,054 件）
- 握手は代表だけ（spec-88 の 9.7 の決まり）。代表が通った系列は、1 枚のカード（「同じ作りの物が N 件」）で出す。中の 1 件ずつは詳細の頁で選べる。

### 2.3 サインイン（OAuth）が要る 10,214 件と、鍵が要る 4,198 件
- つなぐ前に、本人が相手のサインイン・自分の鍵で許可する流れ（接続計画 spec-96 の「入力する物」）を、実際の相手で通す。鍵は本人の端末かサーバーの暗号化した保存だけ。Noah の画面・ログ・Git に出さない。
- 通った物は、グリッドに「サインインが要る」「鍵が要る」の印を付けて出す（`noahListing` の needs_permission・needs_key を、印付きの掲載に変える。グリッドの並びでは、押すだけで試せる物の後）。
- 合格: 実際の OAuth の相手 3 件・鍵の相手 3 件で、つなぐ → 頼む → 成果が返る。

### 2.4 手元で動かす配布 18,904 件
- Noah のクラウドの実行先（画面を奪わない専用の端末。`app/api/noah/cloud-work`）で、配布を固定の版で起動し、MCP の握手をする仕組みを作る。権限は入力の読み取りと成果の保存だけ。外への書き込み・支払いの権限を持つ物は対象外。
- 通った物は、グリッドに「Noah のクラウドで動く」の印を付けて出す。
- 合格: 鍵の要らない npm の配布 3 件・Docker 3 件で、つなぐ → 頼む → 成果が返る。

### 2.5 応答なし・形が合わない・対応外
- 応答なし 2,319 件は、7 日ごとに握手し直す。3 回続けて通らなければ「止まっている」として出さない。
- 古い SSE だけの 704 件は、SSE の口を足して握手する。
- 支払いが要る 132 件は、今は出さない（有料の Agent の決まりは別の task）。

### 2.6 Agent の説明を日本語にする（日本語だけ）
- `lib/noah-i18n.ts` の決まり「provider descriptions and results are never translated」を、本人の指示で変える: Agent の名前の下の説明だけを日本語に訳す（成果・利用者の入力は訳さない）。
- 訳すのは収集機。新しく載る・説明が変わった系列だけを LLM で訳し、`noah_intake_candidates.summary_ja`（今は空）に入れて、取り込みで本番へ送る。「新しく見つかったAgent」のカードも同じく訳す。同じ説明は二度訳さない（説明の hash で保存）。
- 画面は、言語が日本語の時は `summary_ja` を出し、「自動翻訳」の印と、原文を開く操作を付ける。
- 費用の目安: 7 万件でも 1,000 円前後（小さいモデル）。鍵は Actions secret に入れる（チャット・Git に書かない）。1 回の巡回で訳す上限と、月の上限を置く。
- 合格: グリッドの 1 頁目の全部と、詳細の頁に日本語の説明が出る。原文に戻せる。

### 2.7 画面の言葉の切り替えを全部の画面に
