# 126 Noah のトップの最初の列をパッケージにする（Eve が組む・Switch の部屋の形を手本に）

本人の言葉（2026-11-22 19:36）「でそれを繋げるのが Eve ね」「最初は Noah は単発機能じゃなくてパッケージにしてもいいのかも」。同日の回答「パッケージを上、単発は下」。Switch は「パッケージの手本にする」。

パッケージとは「1 つの仕事を最後までやる組合せ」（2026-11-20 の本人の決定。[spec-110](../../docs/noah/spec-110-shelf.md)）。

## 1. 今あるもの

- 棚とパッケージの形・載せる条件・並び: `lib/noah-shelf.ts`・`lib/noah-shelf-store.ts`・`lib/noah-shelf-api.ts`（task 110・111・113）。
- 最初のカード 17 枚（1 枚 = Agent 1 つの道具 1 回）: `data/noah-shelf-first-cards.json`（spec-110 の 18 章）。
- 本番の `/api/noah/shelf` は 404。切り替え（`noahShelfOptions` の `visible`）が閉で、カードもまだ置かれていない。
- トップは単発の Agent のピンタレスト風のグリッド（[spec-115](../../docs/noah/spec-115-pin-grid.md)、`components/noah-pin-home.tsx`）。

## 2. Switch から借りる考え方（コードは使わない）

Switch のコードは Apache 2.0 + Commons Clause なので、Noah には入れない。借りるのは考え方だけ。

| Switch | Noah |
| --- | --- |
| 部屋（room）: 人と複数の Agent が同じ会話と文脈で働く | パッケージ: 役割ごとの Agent が、前の成果を次の入力にして 1 つの仕事を終える |
| 役割（PM・作る・確かめる・直す）と指示 | パッケージの工程（`steps`）ごとの役割名と、その工程が受け取る物・出す物（札） |
| 人が承認してから進む所（「ロールバックは人が承認」） | 人が押す工程（支払い・送信・公開の前で止まる） |
| 誰が話しかけられるか（owner_only など） | パッケージを始められる人と、各 Agent へ送る物を、始める前に見せる |
| Switch Buddy: 「こういうチームが欲しい」と言うと、Agent と部屋を作る | Eve: 「こういう仕事をしたい」と言うと、今動かせる Agent を当てはめたパッケージを組む |

## 3. やる事（この順で。1 つずつ PR）

### 3.1 Eve の組み方（決まった手順。学習したモデルは使わない）

- 仕事の型: 棚の話題（`NOAH_SHELVES` の topics）と、task 122 の工程の能力（`lib/noah-business.ts` の `NOAH_CAPABILITIES`）から作る。
- 型ごとに、役割の枠（例: 調べる → まとめる → 確かめる）と、各枠が受け取る物・出す物（札）を決める。
- 各枠に、今動かせる Agent を当てる。対象は、本番の一覧にあり、握手が通っている物だけ。
- 当てる順:
  1. 能力の語が道具の説明と一致する。
  2. 成果が返った数（Noah の実績）が多い。
  3. 押すだけで頼める。
  4. 札がつながる（`noahPackageChainProblem` が null）。
- 枠が 1 つでも埋まらない型は、パッケージにしない。
- 組んだパッケージは下書きで置く。運営が 1 回動かして最後の成果まで返ったら「確かめた」にして棚に出す。これは spec-110 の 4 章の決まりのままにする。

### 3.2 画面

- トップの最初の列にパッケージのカードを並べる。カードには、名前・何をするか・中の Agent のアイコン（役割の順）・「始める」を出す。
- その下に、今の単発のグリッドをそのまま残す。
- パッケージを押すと、役割ごとの Agent と順番、人が押す所、各 Agent へ送る物が見える。
- 「新しく見つかったAgent」の列（task 121・125）は、今の位置のまま。

### 3.3 動かす

- 「始める」で、Noah の頼む流れを役割の順に回す。前の工程の成果は、次の工程の入力にする。
- 人が押す工程では止まり、知らせる。
- 途中で失敗した時は、そこまでの成果を残す。同じ Agent を 2 回まで試し、だめなら次の候補に替えて再開する。

### 3.4 公開

- 本番で棚を開ける（`visible`）。最初の 17 枚（1 工程）と、3.1 で組んで確かめた複数工程のパッケージを出す。
- 開ける前に、ノエルに見せて答えをもらう。

## 4. 合格条件

- 本番のトップの最初の列に、棚 3 段（稼ぐ・仕事を省く／教育／暮らし）それぞれ 3 個以上のパッケージが出る。
- そのうち、2 工程以上のパッケージを 3 個以上含む。
- 2 工程以上のパッケージを 1 つ、本番で始め、最後の成果まで返る（実際の Agent で。画面の記録を PR に貼る）。
- 単発のグリッドが、パッケージの列の下でこれまでどおり動く（頁送りに重なり・抜けが無い）。
- 試験: `tests/noah-shelf*.test.mjs` に、組み方（枠が埋まらない型は出ない・札がつながる）を足す。`npm run verify`。

## 5. やらない事

- 学習したモデルでの並び替えはしない。乱数も使わない（spec-110 の 5 章）。
- 支払い・送信・公開を、人が押さずに進めない。
- Switch のコードは使わない。Switch を Noah のクラウドで動かして売らない。
