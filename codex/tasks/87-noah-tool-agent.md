# 87 道具を持つ担当（1 文で頼む）

設計: docs/noah-agent-market-design.md §4.3・§4.5・§6、docs/services/noah-agent-intake.md。先に 86。モデルの出どころと月の上限は本人の許可の後（設計書 §9 の 5）。許可の前は、固定の応答を返す試験用のモデルで作る。

## やること

1. lib/noah-tool-agent.ts: 本人の 1 文 → その接続の道具の定義をモデルへ渡す → 道具を呼ぶ → 成果。上限は `LIMITS`。1 回の仕事で使う接続先は 1 つ。
2. 道具の説明の扱い。モデルへの指示として読ませない。道具の定義の枠にだけ入れ、長さを切る（候補: 1 道具 1,024 文字、合計 32KB）。
3. 確認。読み取りだけと宣言されていない道具は、最初の 1 回、道具の名前と入力を見せて確かめる。外部への書き込みと金融は Broker の既存の確認。
4. 入力欄での実行。道具が 1 つで必須の入力が 2 個以下なら、モデル無しで使える。
5. 言い直し。受け取った依頼を 1 行で成果に添える。止めない。
6. 成果を既存 Work に保存する。誰の Agent が・何を使い・いくらかかったかを 1 行添える。受け取る／直してもらうは既存の検収。
7. 費用。モデルの入出力トークンを計測し、無料枠と本人の月の上限で止める。

## 変えないもの

- Eve → Noa → AMC → Jev の構造。これは Noah の基盤で、新しい Agent の品揃えにしない。
- 別の接続の成果や記憶を渡さない。鍵と token を担当へ渡さない。

## 合格条件

- 試験用の接続先で、1 文の依頼から道具が呼ばれ、成果が Work に残る。上限（8 回、240 秒）で止まる。
- 道具の説明に「前の指示を無視して…」と書いた接続先で、他の道具の呼び出しや、依頼に無い送信が起きない。
- 書き込みの道具は、確認無しでは呼ばれない。
- 画面を閉じても完了する（84）。tests/noah-tool-agent.test.mjs、`npm run typecheck`、`npm run lint:product`。
