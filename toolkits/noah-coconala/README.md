# Noahでココナラの仕事をする

## DaisukeのココナラAgent

MacでPython 3.9以降とOllamaを使います。`ollama list` に `qwen3:4b` があることを確認し、接続プログラムを `npm start` で起動します。Noahの「Agentを探す」で「Daisuke」または「ココナラ」を検索し、[Agent](https://avoado.si/noah/coconala/agent)を選びます。「案件を探して下書きする」で開始し、結果が出たら、案件名から公開元を開けます。下書きと選定理由は本人Mac内に保存され、同じブラウザで再び開けます。実行中または停止後のページURLを保存すると、同じMacの別ブラウザからもその下書きを開けます。Ollamaには公開募集だけを渡します。公開募集の読み取りにログインは不要です。

Macが起きている間は直前の探索が終わってから15分後に次を開始します。「Agentを停止」は進行中の読み取り・生成プロセスの終了を待ち、次の探索を取り消します。Macの接続プログラムを再起動した場合は中断として表示します。

Daisuke134/anicca の固定版の Apply から `application_eligibility.py` の判定、`application_planner.py` の `planner_prompt` と共通方針、`buyer_voice.py` の文体、`work_fit.py` の分類を使います。下書き用には公開本文を渡し、元の出品者の履歴や実績を読み込む部分を除きました。Noah側が取得、ローカルモデルへの入力、成果の保存・停止を担当します。通常の出品・応募・交渉・納品の自動実行器は起動しません。[上流の固定版](https://github.com/Daisuke134/anicca/tree/5ea3222c3280c5a96172e9eedb1b733e3576ca73/skills/earn/gig) · [MITライセンス](anicca/LICENSE)

## 手動の返信・応募・納品

MacでNoahのメニューから「ココナラの仕事」を開きます。実行中は専用のヘッドレスChromeが仕事を続けます。Macと接続プログラムは起動しておいてください。依頼後は別のアプリに移ることも、Noahのタブを閉じることもできます。

## 最初の接続

このリポジトリと、Node.js 22.13以上、Google Chromeが必要です。Macのターミナルで実行します。

```sh
cd toolkits/noah-coconala
npm ci
npm run login
```

初回ログイン用のウィンドウで、ご自身のココナラアカウントにログインして閉じます。二段階認証もこのウィンドウで行います。次に `npm start` を実行し、Noahの「このMacに接続」を押します。接続ボタンでブラウザからローカルネットワークの利用を尋ねられたら、自分のMacへの接続を選びます。ログインの更新も同じ手順です。

## 返信・応募・納品

| 操作 | 入力するもの | 送信後の確認 |
| --- | --- | --- |
| メッセージに返信 | メッセージURL末尾のスレッド番号と本文 | 同じスレッドを再読込し、自分が送った本文の件数が増えたこと |
| トークルームに返信 | トークルーム番号と本文 | 同じルームで自分が送った本文の件数が増えたこと |
| 応募 | 公開依頼番号、提案文、金額、納品予定日 | 自分の応募一覧に追加された応募の案件番号 |
| 正式な納品 | 通常取引のトークルーム番号、本文、ファイル名、SHA-256 | 納品段階が進み、自分の本文と添付名が新しく表示されたこと |

納品ファイルは先に次のコマンドで登録します。出力された名前とSHA-256をNoahへ入力します。1操作で1ファイル、上限32 MiBです。

```sh
node mac.mjs stage "/path/to/納品ファイル.pdf"
```

「送信内容を確認」で宛先・本文・取引条件・添付を見直し、対象の操作を確定します。申し込みは金額と納期の表示を照合してから進みます。受付番号はブラウザに保存され、再接続後も直近の結果を確認できます。

画面変更やログイン切れで送信前に止まった場合は、原因を修正して再確認できます。アップロードや送信後の結果が不明なときは、ココナラ側の履歴を確認してください。同じ対象・操作の未確定記録がある間、再送を止めます。本人が履歴を照合できた場合だけ、Macで `node mac.mjs reconcile 受付番号 sent`（送信済み）または `node mac.mjs reconcile 受付番号 not-sent`（未送信）を実行します。後者は再度の本人確認を受け付けます。どちらのコマンドもココナラへの送信は行いません。

## Macに保存する情報

専用のログイン状態、添付と受付記録は `~/Library/Application Support/Noah/coconala/` に置きます。Chromeは専用プロファイルとプロセス間のパイプを使用します。普段のChromeや公開のデバッグポートに接続する設定はありません。接続プログラムは `127.0.0.1:38483` で、起動時に選んだNoahのOriginに限って既存のMCPの確認・実行手順を受け付けます。終了は接続プログラムのターミナルでCtrl+Cです。

## 検証

リポジトリのルートで以下を実行します。

```sh
node --test tests/noah-coconala.test.mjs
npm ci --prefix toolkits/noah-coconala
npm test --prefix toolkits/noah-coconala
```

Macの画面とNoahのUIの受入試験では、ルートで `npm run dev -- --port 3000` を起動し、別のターミナルで `node toolkits/noah-coconala/test/mac-acceptance.mjs` を実行します。試験専用のChromeから出るリクエストはテスト用ページで受けます。対象プロセスが前面に出た回数、ウィンドウの出現、並行するファイル保存、Noahを閉じた後の納品結果を確認します。
