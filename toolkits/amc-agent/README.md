# AMCをCodexで使う

このプロジェクトの現在のCodexチャットで、やりたいことを一文で伝えます。

> AMCで、購入後の商品が再読込しても使えることを確認して

スキルを選ぶ場合は `$amc` を指定します。新しいチャット、別のCLI、Webへの入力、DBの準備は利用条件ではありません。

AMC（avokado Mission Control）は、このチャットを司令部にしてGoalと範囲を保持し、実行担当へ任務を渡し、別の担当が成果を検収します。利用可能な委任機能へ役割を渡して動くため、カスタム役割名の自動検出がなくても作業できます。委任機能自体がない環境では単独作業と明示し、独立検収済みにはしません。

## 動かないとき

設定や保存失敗の原因を調べるには、プロジェクトの端末で次を実行します。

```sh
npm run amc -- doctor
```

診断はファイルを書き換えず、3役割とスキルの登録・内容一致、端末版Codexの有無、プロジェクトと一時領域の空き容量を表示します。端末版Codexの確認はバージョン照会だけで、認証や任務実行の成功を意味しません。CLIがなくても、このチャットからの利用は可能です。空き容量警告だけの場合はexit 0になりますが、空き確保や保存成功を示すものではありません。

- 未登録: `npm run amc -- install` で登録します。
- 既存定義に差分: 内容を確認して更新します。インストーラーは異なる既存ファイルやsymlinkを上書きしません。
- 空き容量不足: 入力と成果を保持して、OSのストレージ設定で空きを確認します。自動削除はしません。保存結果が不明な作用は再送せず、先に結果を照合します。
- スキルが候補に出ない: プロジェクトを開き直して認識を確認します。役割ファイルがあることと、自動検出され実行できたことは別です。

## 任意のCLI利用

別の対話端末から開始したい場合だけ、既存のCodex CLIを使います。

```sh
npm run amc -- help
npm run amc -- doctor
npm run amc -- install
npm run amc -- '購入後の商品が再読込しても使えることを確認する'
```

依頼文は一つの引用符で囲みます。起動内容だけを確認する場合は、送信もCodex起動もしないpreviewを使います。

```sh
npm run amc -- run --goal '購入後の商品が再読込しても使えることを確認する' --preview
```

`npm run amc -- describe` は役割の説明を表示します。従来の `npm run amc:agent -- …` も同じ入口です。対話端末でない場所からの実起動は拒否し、このチャットまたはpreviewへ案内します。

CLIは既存の認証・モデル・権限・承認設定を使い、このチャットで一時的に選んだ設定とは同期しません。チャットから委任した担当は親のモデルを継承し、既存の承認条件を守ります。検収担当の定義はread-onlyです。フォルダの信頼確認が出た場合は利用者が対象を確認し、保護を回避しません。閉じた後の常時稼働は行いません。

## 登録されるもの

役割の正本は `data/amc/agent-definitions.json`、スキルの配布元は `toolkits/amc-agent/SKILL.md` です。installは次のファイルを登録します。

- `.codex/agents/amc.toml`: 司令官
- `.codex/agents/amc-worker.toml`: 実行担当
- `.codex/agents/amc-reviewer.toml`: 独立検収担当
- `.agents/skills/amc/SKILL.md`: 自然文と `$amc` からの利用手順

別のワークスペースへ登録する場合は `npm run amc -- install --project /absolute/workspace` を使います。global config、モデル、認証情報、利用者の他のエージェントは変更しません。

## 実装と受入の境界

今回この作業branchへ導入した範囲はCLI・役割・スキルです。フルAMC runtimeはmain側の別実装であり、この導入だけでWeb/Core全体を統合した意味にはなりません。main側のGoal engine、有限自律ループ・永続化、隔離作業場所のrunnerの証拠を、現在のチャットでの実行や検収の証拠に流用しません。

Webからの起動・部隊表示への自動同期は未接続です。別の永続台帳は作らず、既存の保存Goalを扱うときは正式なreducer・認証・同意を維持します。成果提出と正式受入を分け、JSONへ直接done/acceptedを書き込みません。役割分離は認証・強制隔離・本番の受入の代用ではありません。

Goalの版が変わった場合は影響する任務を停止し、最新のGoalと成果を照合して再開します。実Codexへの委任成功とカスタム役割の自動検出、CLIのexit 0と任務成功、local fixtureと実機・決済・公開の受入は、それぞれ別に確認します。
