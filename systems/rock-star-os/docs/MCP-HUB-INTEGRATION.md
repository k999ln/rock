## 接続経路

ネイティブ画面 → OS所有者UID1000のUnixソケット → Platform UID1002 → 明示CAで検証するHTTPSゲートウェイ → 既存の購入資格・月額利用状態 → Broker → 所有MCP試験サービス。通常のHub一覧はMCP通信を待たず、MCPページだけが接続状況と結果を取得する。

端末設定は購入者サービスのauthority・consumer・deviceと結合する。ゲートウェイ、既存サービス設定、CAのハッシュを永続的に固定し、設定消失や別端末への付け替えで別サービスへ切り替えない。画面はURL、秘密情報、別の所有者IDを要求に追加できない。異なる所有者が同じ接続先アカウントを共有する設定も拒否する。

現ゲートウェイは無料の所有loopback試験サービスに限定。本番MCP提供者、OAuth失効、接続先の公開・審査、有料ツールの売上精算は未接続。既存の月額888 centsの利用状態は新規送信時と実行開始時にauthorityで再確認する。未払いでも、有効な端末所有資格があれば結果照合と接続解除を許可する。

## 送信と解除

1. 接続先を選び、端末で本文を入力する。
2. 確認時はハッシュと長さを管理サーバーへ送る。ハッシュは匿名化ではない。
3. 接続先・本文・料金を確認し、送信に同意する。この操作で初めて本文を送る。
4. サーバーは本文のハッシュ、長さ、接続世代、仕様、価格、確認期限を照合する。
5. 解除は未送信の準備と待機処理を止める。送信開始済みの処理は同じ記録を照合し、勝手に再実行しない。

接続開始時点を永続化するため、接続途中の解除とサーバー再起動が重なっても、古い要求で復活しない。Broker schema2は整合したschema1だけを移行し、既存の時刻上限・同意・受付記録を保持する。データベースや時刻管理行の欠損を新規状態として修復しない。

「入力へ戻る」は本文を送らず戻る操作であり、確認記録の削除ではない。接続先の認証情報の失効と、送信済みデータの取り消しも実装済みとは表示しない。
